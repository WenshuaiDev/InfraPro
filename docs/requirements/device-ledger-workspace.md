# 租户设备台账工作区重构

状态：待人工验收。实现与自验已完成，用户已选择原型 B 的主从交互，结合 C 的位置筛选；视觉使用项目既有 shadcn/ui 规范。

## 目标与范围

- 租户设备台账采用左侧设备列表、右侧详情的持续工作区。厂家、产品、来源、状态和当前安装位置共同筛选。
- 设备详情的档案、输出槽、来源关联、安装履历和变更记录保留既有业务能力，减少重复导航和摘要侧栏。
- 桌面切换设备保留列表分页、筛选和详情页签；具体输出选择随设备切换清除。手机采用列表与详情两个视图，返回保留列表上下文。
- 保留 `/t/:tenantId/devices/:deviceId` 深链接、浏览器前进后退和刷新恢复。
- 项目设备的独立授权、租户数据隔离、变更预览、请求回执和冲突处理沿用现有规则。

## 设计与技术

- React + TanStack Router：增加租户设备父路由，持有工作区和列表状态；列表和详情子路由共享该父组件。筛选及详情页签保存在 URL。
- TanStack Query：复用游标分页和现有作用域缓存。筛选在服务器执行，避免只过滤已加载的一页。筛选变化回到第一页并清除旧设备及输出选择。
- shadcn/ui：复用 Button、Tabs、Card、Badge、DropdownMenu、Input 和 ResponsivePanel，沿用主题变量、PageHeader、间距、边框和全局侧栏。参考 shadcn-admin 的列表/详情分栏交互，不引入原型配色、装饰性指标或新的设计系统。
- Go + PostgreSQL：扩展设备列表的当前安装类别和设施筛选；设施包含安装在其构件、测点的设备。列表批量读取当前安装摘要，经现有资源权限投影后返回，禁止泄露无权查看的目标。无数据库结构变更。
- API 契约与 TypeScript 客户端同步扩展筛选。厂家/产品从设备目录分页选择；设施从工程资源分页选择。无资源读取权限时不提供设施筛选，服务端同时拒绝越权筛选。
- 登记和编辑沿用现有响应式抽屉、字段校验、预览及回执；设备切换重置详情内部临时状态。

参考：[shadcn-admin](https://github.com/satnaing/shadcn-admin)、[shadcn/ui](https://ui.shadcn.com/docs/components)。
