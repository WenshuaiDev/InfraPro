## 1 目标与本轮边界

本轮完成后，租户及项目管理人员可以在资料页添加附件、查看上传及处理进度、受控下载、替换、移入回收站和恢复。开发其他模块时，接入既有业务对象、权限检查和附件组件即可使用这套能力，不再各自实现上传、文件状态、下载和清理。

本轮同时接入现有监测导入、空间图模、大屏包及导出结果的公共上传和文件展示能力。原文件仍归原模块所有；公共模块不接管监测原始数据、图模转换、大屏发布或成果有效性。

交付边界可以概括为：**一套普通文件服务、一套附件绑定规则、一组公共组件、租户与项目两个真实附件入口、现有专业文件入口适配，以及权限和生命周期自验。**

## 3 文件、附件与业务归属

### 3.1 必须区分的对象

| 对象 | 职责与约束 |
| --- | --- |
| 上传会话 UploadSession | 记录人员、目标业务对象、预期大小／摘要、已收分片、有效期和处理状态；会话 ID 不是下载或跨账号使用凭证。 |
| 普通文件 ManagedFile | 一份不可变正文及其元数据。隶属一个租户，明确是租户空间还是某个项目空间；不同空间不能互换。 |
| 业务附件 Attachment | 业务对象上的一个附件位置，有独立 ID、名称／说明、当前文件和修订记录；文件替换不覆盖旧正文。 |
| 附件修订 AttachmentRevision | 固定关联某一文件、操作者、时间和替换原因；历史读取仍要检查当前业务权限。 |
| 保护引用 Reference | 声明附件历史、任务输入／输出、读取租约或保留要求对文件的占用，提供清理判断依据；引用本身不授予读取权限。 |
| 专业文件引用 DomainFileRef | 保存白名单来源模块、来源对象／版本、文件标识和用途；通过原模块解析及授权。它不属于普通文件的回收和保留策略。 |

普通附件的权限来源是业务宿主，不建立另一个可以绕过宿主权限的文件 ACL。`file_id`、摘要相同、上传者身份、任务管理权或有一条引用，都不能单独构成读取授权。

保护引用通过文件模块的事务接口幂等建立、释放，和业务采用事实共用事务；后台执行先获得有限保留租约，再读取文件。异步检索索引及估算计数不能作为“没有引用”的权威依据。新增宿主必须声明其引用释放条件。

### 3.2 首批附件宿主

| 宿主 | 页面与用途 | 固定边界 |
| --- | --- | --- |
| `tenant.profile` | 租户工作空间资料页的“资料附件”：租户说明、常用资料等。 | 只属于该租户空间，不包含其所有项目附件；平台租户治理页不因此获得正文读取权。 |
| `project.profile` | 项目资料页的“资料附件”：项目说明、参考材料等。 | 只属于该项目，不随租户成员资格自动开放；归档后的读取遵循项目既有规则，新增、替换、回收和恢复均按项目写入门禁执行。 |

本轮只在已经创建的租户／项目上添加附件。创建对象表单中的未保存附件、设备检修附件、报告附件、反馈附件等不纳入本轮入口，但模块接入规范必须能够供它们后续使用。

同一宿主下的附件使用同一组附件权限，上传前明确可见范围。首版不提供每个文件单独选人员、密码分享或秘密附件。含不同保密范围的业务，后续须登记独立宿主及授权规则，不能靠文件名或前端隐藏实现。

### 3.3 绑定和替换规则

1. 上传开始即固定 `tenant_id`、可选 `project_id`、宿主类型及 ID、上传人员和添加／替换意图。客户端不能在完成时把文件改挂到另一空间或另一宿主。
2. 用户确认上传时同时提交附件意图。服务端校验成功后，复核当前账号、业务委托、宿主状态及附件修订，再以一个数据库事务建立附件，或切换现有附件的当前文件并保存历史。页面只在该事务成功后显示“附件已添加／已替换”。
3. 处理期间退出页面不影响已持久接受的后台工作；退出登录与业务委托撤销分别处理，沿用任务中心规则。账号停用、成员撤销、权限收回或项目归档后，不得继续发布新的附件。
4. 文件校验完成但宿主已经变化时，正文进入有期限的“待绑定”，任务显示需要处理；有权人员可以在原目标重新确认，或放弃。重新确认记录实际操作人和新的预期修订，不能冒用原上传人的委托。权限不足时只显示仍允许的最小状态，不能通过待绑定文件下载绕过授权。
5. 修改名称／说明与替换正文分别记录。替换使用附件自己的预期修订号，不能覆盖其他人刚提交的版本。恢复旧正文采用“以历史文件建立新修订”，保留完整顺序。
6. 首版不提供跨对象复用选择器、跨项目移动、复制到其他租户或专业文件转普通附件。需要同一文档出现在多个地方时，必须分别执行获准上传；服务端不能利用摘要命中跳过传输或授权。

## 4 上传、读取和保留规则

### 4.1 普通附件的首版默认策略

| 项目 | 本轮基线 |
| --- | --- |
| 文件格式 | PNG、JPEG、PDF、TXT、CSV、DOCX、XLSX、PPTX。前端展示允许格式，服务端独立校验；不接受普通 ZIP、HTML、SVG、脚本、可执行文件和宏格式。 |
| 大小 | 每份普通附件大于 0 且不超过 100 MiB；单个分片 8 MiB，最后一片按实际长度检查。属于本轮可配置保护值，不改写专业模块自己的限制。 |
| 名称 | 允许中文等正常文件名；上限 200 个 Unicode 字符；拒绝路径、控制字符及 CR/LF，页面转义显示，下载头安全编码。 |
| 并发 | 公共客户端最多同时传输 2 个文件、每文件最多 2 个片段；服务端另设有限的会话数、工作并发、暂存字节和请求速率上限，不能仅靠浏览器限制。部署文档必须列出实际默认值与耗尽错误。 |
| 上传有效期 | 连续 24 小时无成功分片则过期；单次会话总寿命最多 7 天。续传不复活已经过期或取消的会话。 |
| 待绑定文件 | 校验完成后保留 24 小时供原目标处理；到期且没有保护引用、写入或读取租约时进入清理。 |
| 正式附件及历史 | 没有默认自动删除期限。替换产生的旧修订继续保留；不把“不是当前版本”判定为垃圾。 |
| 回收站 | 用户移除整个附件后保留 30 天，期间可恢复；包含该附件的全部修订。到期只进入待清理，必须再次通过引用检查。首版不提供立即永久删除按钮。 |
| 在线预览 | 只提供经服务器解码、尺寸限制并重新编码的 PNG／JPEG 预览，去除原始元信息；超过 2500 万像素不生成预览，正文接收仍须通过独立格式与体积检查。其他格式提供类型标识和受控下载。 |
| 完整性 | 校验实际长度、分片摘要、整文件 SHA-256 及格式的一致性；不能只相信扩展名、浏览器 MIME 或客户端摘要。内容类型检查不等于文档业务有效性或无恶意软件认证。 |

格式允许范围只能从经过实现和验证的处理器中选择，不能通过配置任意开放文件执行能力。Office 文件只进行有界容器／类型检查，限制条目数、展开字节及耗时，不执行宏、公式、外部链接或预览转换；不能将其解释为监测数据导入。普通 CSV 也只作为附件保存，文本格式检查不能被宣传为对文件内容用途的识别。

上传 UI 支持续传及取消，明确区分“校验本地文件、上传中、服务端检查、待绑定、已绑定、失败、取消、过期”。浏览器刷新或重开后，用户须重新选择同一文件，大小及完整摘要匹配才能复用已收片段；不保存本机文件路径或宣称关闭浏览器后仍能传输剩余字节。

服务端检查失败必须给出有限、可理解的原因及处置入口。重试只重做可恢复步骤；缺失本地数据时提示继续上传，摘要不符时要求重新上传，目标冲突时要求重新确认，不能用同一个“重试”按钮掩盖不同语义。

### 4.2 下载与预览

普通文件通过带人员身份的业务下载网关输出，首版不发放浏览器直连对象存储的下载 URL。每次详情、下载、预览和 Range 请求都重新检查当前资格与具体附件修订；传输途中按有界数据块复核权限，撤权提交后不能再放行新的数据块。已经送达客户端的内容无法撤回，验收不得要求追回已发送字节。

预览与下载使用相同的正文读取权限。原文件默认 `attachment` 下载；普通文档、HTML 或上传包不得作为管理站点同源可执行内容。预览仅输出服务端生成的受控图片；响应不允许公共缓存，认证内容使用私有、不可持久复用的缓存策略。

业务引用必须解析成白名单内部动作，不接收任意 URL、对象键或 bucket。任务中心和通知只保存结构化定位信息，不能保存长期下载凭证。专业文件继续经原模块下载接口，不能由一个公共 `file_id` 路径绕过来源鉴权。

### 4.3 回收与物理删除

公共文件服务只清理自己拥有的普通文件命名空间。清理必须同时满足：保留期已过、没有有效附件或历史引用、没有保护引用、没有活跃上传／执行／读取租约，且对象状态允许回收。

流程为“生成候选及原因 → 重新核验并持久化删除意图 → 标记回收中并阻止新绑定／读取 → 删除私有对象 → 记录结果及墓碑”。判断与加引用共享事务锁；已有租约失效后才能删除。不能先按引用计数快照删文件再补记录，计数只是派生统计，不能代替权威引用检查。

正式附件和历史引用一直有效；附件进入回收站后改为保留引用，30 天到期后才允许在同一锁定事务中释放这一组引用，修订及操作元数据保留为墓碑。其他任务、备份或业务保护引用仍独立生效。回收站恢复先核验所有待恢复正文仍完整且未进入物理回收，再恢复引用；不能把正文缺失的附件标为可用。

数据库与 S3 不存在共同事务。每次对象写入必须有持久化写入意图与独立键；失败、响应丢失或进程退出后按意图核对，不能立即认定对象未写入。删除失败可重试，未知结果保留待核对；未登记的对象仅报告为未知，不通过全桶扫描直接删除。异常“正文丢失／摘要损坏”与按计划回收是不同状态。

租户停用、项目归档、人员离职、模块关闭或额度不足都不能触发附件清库。源模块不可用、引用无法确认或恢复对账尚未完成时，暂停相关物理删除。专业文件的过期、保留和清理由原模块执行，不套用普通附件的 24 小时／30 天规则。

## 5 权限与审计约束

新增租户和项目两组附件权限，名称以权限目录规范生成：`attachments.read`、`attachments.download`、`attachments.manage`，分别挂在 `tenant` 和 `project` 作用域下。

| 操作 | 必须检查的权限与范围 |
| --- | --- |
| 列表、名称、大小、状态和历史摘要 | 当前人员资格、宿主可见性及对应 `attachments.read`；数量、筛选和详情使用同一可见性条件。 |
| 原文下载、图片预览、下载历史版本 | 以上条件加 `attachments.download`；预览不能绕过下载资格。 |
| 上传、改名、替换、回收、恢复 | 宿主仍允许写入，具备 `attachments.read` 与 `attachments.manage`，并满足宿主所要求的资料修改权限。管理附件本身不授予正文读取权。 |
| 下载或引用专业文件 | 按专业模块分别检查原件、成果、数据范围和有效期；公共附件权限不参与替代授权。 |
| 运行诊断、清理重试 | 独立运行权限和有限命令；只展示允许的状态与汇总，不自动获得租户文件名、内容或对象存储凭证。 |

权限目录迁移为现有受保护租户／项目管理员角色补齐相应本地管理能力；普通成员和自定义角色不自动获得新附件内容权限。查看资料、平台管理员身份、租户项目治理权都不自动升级为附件下载权。角色目录、权限选择器、授权说明及版本同步必须一起修改。

公共文件接口拒绝大屏终端及 `ReadSubject` 使用人员附件能力。若未来需要向大屏供图，必须设计独立业务授权和发布规则，不能借普通附件地址实现公开托管。

审计记录上传接受／终态、绑定、替换、改名、回收／恢复、下载授权及结束状态、清理计划／结果、完整性异常；关联请求、人员、空间、业务对象、文件、附件修订和任务。每个下载只记录必要事件，不按分片刷审计；不写入正文、访问令牌、完整私有地址或本机路径。权限不足的错误不能泄漏其他空间的文件名和存在性。

## 8 任务、通知和实现边界

普通附件服务建立自己的持久文件处理记录及有限执行机制，至少覆盖最终拼装、服务端摘要／类型检查、图片预览和附件绑定。只登记真实接受的后台工作为 `files.prepare` 人员任务；上传片段不逐个成为任务，浏览器传输期不显示虚假的后台执行。

文件正文和预览状态分别保存。图片预览失败而正文校验通过时，附件可下载，页面明确“预览不可用”，不把正文误报为损坏；正文校验失败则不能绑定或下载。绑定冲突显示需要处理，不能显示任务已成功且附件已可用。

任务完成、失败或需要处理的事实由文件模块在相应状态事务中提交，按既有通知偏好向发起人投递；不广播每个附件给全部成员。普通后台自动重试不重复通知，人工新一代操作按任务中心规则记录。清理批次及内部巡检进入运行诊断，不逐个进入个人任务列表或个人通知箱。

任务中心原有来源使用白名单，新增 `files` 必须同时补登记、Adapter、结果定位、权限、控制、来源失效和恢复处理。文件结果仍由文件服务校验下载；任务取消只有在文件模块阻止后续绑定后才成为取消终态，已经绑定的附件不会因取消记录被删除。

技术沿用 Go、PostgreSQL／pgx、私有 S3 兼容对象存储和 React／TypeScript：PostgreSQL 保存权威状态、幂等收据、引用、租约及事务事实；S3 保存不可变正文与受控预览；Go 服务执行分片检查、授权和受限文件处理；前端负责上传交互和展示。文件服务不依赖 ClickHouse，不引入新的消息队列、全文检索或 Office 转换集群。

`files` Module 的公共 Interface 只提供上传会话、完成／取消、附件查询／变更、授权读取和保护引用等用例；宿主 Adapter 负责定位真实对象、当前读写授权和生命周期判断。业务模块不能自行拼接对象键或直接改文件表。将来新增宿主须注册、声明权限与保留规则并通过接入测试，不开放用户可配置的任意表名、脚本或回调地址。

## 9 升级、恢复与交付约束

1. 采用增量迁移，新增普通文件表、引用／写入意图表和权限定义，不搬迁、重命名或删除现有专业对象；迁移编号按任务中心等在途改动落地后的实际顺序分配。
2. 提供普通文件元数据及对象的备份清单：文件／修订／引用、摘要、大小、未完成意图和策略版本；对象存储支持版本标识时一并记录，否则以不可变对象键和摘要确定内容。以明确备份时间点和保留租约保护备份覆盖的对象，不能仅导出数据库后假定正文一致。
3. 在隔离环境完成一次小规模真实恢复和对账，核验正文摘要、附件历史及引用关系；报告缺失、额外对象和在途任务。恢复期间暂停删除，推进读取／执行代次，不复活旧下载资格或旧执行提交。
4. 程序回退、模块停用与数据回退分别说明。关闭新上传不能删除历史文件；破坏性数据库回退不能只切旧程序。首版不新增全平台备份调度系统。
5. 输出模块接入示例、普通与专业文件边界、状态／错误码、配置及默认值、权限升级说明、维护命令和人工验收步骤。已确认的稳定规则并入现有主需求、架构与技术选型文档，实施证据单独记录。
6. 合成样本由开发过程提供，包含中文名、多片、相同名不同内容、错误摘要、格式伪装、超限、异常图片、删除竞争及跨空间样本，不依赖厂家协议、真实设备或用户资料。
7. 功能、隔离、并发竞争、失败恢复和小规模恢复验证属于本轮必要自验。专项容量、压力、长时运行及生产环境验证分别列出实测或未测状态，不把默认限制写成已验证吞吐能力。

## 10 明确不包含的内容

这些排除项只界定本轮，不删除两份上位文档中仍待实现的长期需求。

## 11 实施顺序与验收条件

内部按五步推进：先固化宿主／文件契约与权限，再完成普通文件生命周期，然后接入租户／项目真实页面，再适配全部既有文件入口及任务／通知，最后完成清理竞争、升级恢复和完整自验。步骤之间可以分别检查，但不能把某一步完成作为整轮交付。

任务中心目前正在实施，本轮方案可先行定稿；代码对接以其最终契约为准。本轮最终验收必须完成真实任务与通知联调，模拟接口或临时页面不计为完成；不得反向要求任务中心等待整个文件模块才能交付。
