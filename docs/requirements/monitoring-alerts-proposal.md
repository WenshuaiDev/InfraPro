# 监测预警与异常事件处置交付范围建议

日期：2026-11-13。状态：**历史范围建议；本轮范围已收窄**。

用户随后明确本轮只做系统级站内通知，具体范围与重构见[系统级站内通知方案](in-app-notifications-proposal.md)。以下正文保留原先完整预警闭环的候选内容，不作为本轮实施清单；预警、研判处置、催办与升级等待后续范围确认。

本提案采用用户最新进展：**大屏 SDK 与运行机制已设计完整，正在实现；设备接入和数据解析放到后续迭代。** 本轮建议建设监测预警与异常事件处置，使用已有正式导入数据、派生通道和历史分析能力，并接入大屏预留的告警读取能力。

目标是让项目人员能够配置有依据的预警规则，验证规则效果，在符合条件的数据上产生可追溯事件，完成通知、确认、研判、处置、复核和关闭。自动结果提供异常证据，专业判断由有权限的人员记录。

## 1 为什么推荐这一轮

当前资源、数据、计算及空间基础已有实现。正在实施的大屏机制提供目录、曲线、统计、成果和空间读取，并为 `alerts.query`、`alerts.summary`、`alerts.subscribe` 保留契约和 Provider 接口；实际告警业务仍待建设。[大屏能力边界](/Users/hijacker/Documents/ChatGPT/InfraPro/docs/requirements/visualization-display-proposal.md:136)

预警可以直接使用已有正式观测，无需等待厂家协议或设备。导入批次采用、原始批次撤销和派生结果变化已有持久变更记录，可以作为后台评估的依据；历史数据也可以用于规则试算。该迭代同时补齐项目日常异常管理，并让大屏能够展示真实业务事件。

对照目标为[数字化解决方案](/Users/hijacker/Downloads/交通基础设施健康监测与数据资产平台数字化解决方案.md)第11章，以及[Progma 需求](/Users/hijacker/Developer/Company/progma/docs/refactor/progma-requirements.md)的 RQ-ANA-003。本轮只纳入预警所必需的数据资格和新鲜度判断，完整质量治理及正式报告作为后续业务模块建设。

## 2 建议的完整交付范围

| 编号 | 交付内容 | 用户可获得的能力 |

| AL-01 规则管理 | 项目内规则目录、名称与说明、适用对象、输入通道、等级、技术依据、责任人、通知对象、草稿、固定版本、启停和生效记录。 | 选择本项目获准通道，填写阈值及依据，核对后启用；修改形成新版本，历史事件保留原版本。 |
| AL-02 基础规则类型 | 上限、下限、区间外、枚举状态、持续时间、连续样本数、有限的多条件全部／任一满足；去抖、恢复阈值及重复归并。速率、累计变化、滑动统计使用已有派生通道作为输入。 | 对原始值及派生指标配置预警，避免同一异常每来一条数据就生成一个事件；规则条件和恢复条件均能解释。 |
| AL-03 试算与历史评估 | 选择固定规则版本、数据范围与快照，检查单位、质量、覆盖和输入权限；查看命中区间、预期等级、恢复点、证据曲线及受限说明；比较规则修改前后的结果。 | 用已有历史数据核对规则效果，试算结果与正式运行分开。 |
| AL-04 持续评估 | 消费正式原始／派生变更，保存独立进度；支持重启恢复、重试去重、持续条件的时间驱动及受影响区间重新评估。 | 新数据符合条件时形成事件；进程重启不漏掉未处理变更，重试不重复创建同一事件。 |
| AL-05 数据资格与计算状态 | 执行当前授权、质量、真实／模拟来源和派生有效性检查；区分可评估、数据不足、数据陈旧、等待计算、输入失效及执行故障。需要采样计划的判断必须有明确计划和监视时段。 | 没有足够数据时看到明确原因；不能因为未产生事件就显示设施正常，也不将没有新导入判定为设备离线。 |
| AL-06 异常事件与证据 | 事件身份、所属项目、对象、等级、发生与发现时间、规则版本、固定数据依据、触发与恢复过程、影响状态和关联记录。 | 从一条事件追溯到当时的规则、输入、曲线与分析结果；后来改规则或撤销数据仍能解释历史。 |
| AL-07 处置闭环 | 确认接收、核查、专业研判、处置说明、责任记录、附件、复核、关闭及理由；误报处理保留证据与人员记录。 | 完成一次异常处置，并清楚看到当前责任人、处理经过及关闭依据。信号恢复和人工关闭分别记录。 |
| AL-08 站内通知与事件提醒 | 项目内接收人配置、持久通知、未读／已读、事件确认、失败重试、未确认提醒和等级变化通知；保留投递记录。 | 用户能在系统内收到事件通知，查看关联事件；已投递、已读和已确认分别显示。 |
| AL-09 项目管理界面 | 规则配置与试算页面、事件列表、详情、证据曲线、处理记录、通知入口；按设施、测点、规则、等级、发生时段及处理状态筛选。 | 日常路径为“项目 → 预警与事件 → 查看证据 → 确认／处置”；不要求手填内部 ID 或 JSON。 |
| AL-10 大屏及空间联动 | 实现大屏告警 Provider，支持授权后的事件查询、汇总和订阅；事件变化进入既有连续供数机制；空间对象关联事件，支持受控跳转。 | 大屏获得真实事件及状态更新，模型／测点可定位相关事件；确认和处置在控制台进行。 |

| AL-12 自验与交付材料 | 隔离合成场景、功能与故障回归、SDK 联调、操作说明、权限说明、运行恢复说明和人工验收清单。 | 不需要厂家设备即可验收整个软件流程；能够区分软件逻辑正确与工程阈值专业有效。 |

事件处理附件与受控导出纳入本模块，复用现有私有文件存储。它们不扩展为完整项目文档管理或监测报告系统。

## 3 关键业务规则建议

### 3.1 规则和事件归属

建议规则及事件归属于项目。源设施、设备、原始和派生通道继续由租户持有；规则只能使用本项目已获准的对象、数据时段和相关依据。两个项目可以针对同一设施采用不同阈值、接收人和处置要求，不自动共享事件。

事件汇总默认以本项目事件为口径，不把多个项目对同一源数据产生的事件简单相加解释为独立工程事故数量。跨项目部门事件总览不纳入本轮。

后台评估采用明确、持久的项目执行委托，不依赖创建者浏览器在线；执行前和发布结果前复核当前资格。创建者、责任人、运行委托和当前操作者分别记录。人员失效或撤权需要明确提示与处理，不使用隐藏管理员身份继续运行。

### 3.2 输入与阈值

支持当前系统已有的数值、枚举和正式派生输出。规则固定指标、单位、方向、基准和时间含义；不允许直接比较单位或物理含义不兼容的值。

沿用已确认的数据质量规则：未标注记录按当前默认规则可参与，可疑／无效输入不直接触发工程预警；派生 pending、已失效结果及“上一有效值”不能冒充当前有效输入。数据不足时保留“无法评估”的状态和原因。

模拟来源默认不进入正式预警。软件验收在隔离环境中显式允许标记过的合成数据运行测试规则，使用同一评估、持久化和处置链路；生成的事件、通知及大屏样例持续标为测试内容，不进入正式项目通知和工程结论。

速率、累计变化等先由已有派生计算形成有明确语义的通道，再作为预警输入。本模块负责判断条件与管理事件；无需另外实现一套通用计算语言。阈值必须记录依据，产品不默认提供统一适用于所有设施的工程安全阈值。

### 3.3 时间与历史数据

至少区分观测发生时间、平台发现时间、规则生效时间和处置时间。规则启用时明确监视起点及新鲜度要求，不能把刚导入的多年历史记录自动当作当前事故。

历史试算、补算默认生成独立评估结果，不批量生成当前待处置事件或发送实时通知；确需把历史发现转为正式事件时，由有权限人员明确操作并保留历史发现性质。迟到数据按已声明的监视时段及迟到政策处理，不静默丢弃。

持续时间条件不能只靠服务器等待到时判断成立，还需满足输入新鲜度、覆盖及允许间隔；仅一条旧异常值不能无限延伸为持续异常。没有明确采样计划时，不推导缺测率或设备故障。

### 3.4 事件状态与人工处理

分别管理三个维度：

- **评估状态**：当前能否作出判断，以及输入或任务异常原因。
- **触发状态**：条件是否仍满足、是否已恢复、依据是否发生变化。
- **处理状态**：待确认、核查处置、待复核、已关闭等业务进展，具体转换在详细设计中固定。

同一规则及对象的一段持续异常归并为同一事件；等级变化、恢复和再次发生有各自记录。自动恢复不直接替人员关闭事件，人工判定误报也不能删除原触发证据。

原始批次撤销或派生结果变化后，已有事件保留，标明依据变化或失效并支持复核；不覆盖旧证据，不无记录地改写已关闭事件。规则新版本默认向后生效，历史重评估单独执行。

### 3.5 通知与生命周期

本轮通知交付范围为站内消息与事件提醒，形成配置、持久投递、读取、确认及失败重试闭环。站内已投递不等于用户已读，已读不等于已确认，更不等于完成处置。

通知接收人必须满足当前项目成员和事件查看资格；过期或撤权后停止后续详细投递。超时提醒和升级仅服务于事件业务，不建设通用待办、派单或审批引擎。

项目归档后暂停新增常规评估和通知任务，保留历史及未完成处理的真实状态，按现有只读规则访问。恢复启用需重新确认运行边界，不自动补发全部历史通知。规则停用、项目归档和数据撤权分别表达。

验收包含可运行的最小 SDK 告警联调样例，并验证读权限和撤权；不交付成品业务大屏。SDK 继续只读，不能借事件接口修改阈值或提交处置。

## 6 人工可核验的完成条件

1. **规则与试算**：在项目中选择已有通道，创建阈值及持续条件规则；用固定历史数据试算，结果与已知异常区间一致，未产生正式事件或通知。
2. **事件运行链路**：在隔离验收环境显式启用测试规则，导入标记过的合成数据并采用原始或派生结果，生成明确标为测试的事件；重复处理同一变更不重复产生事件，等级变化和恢复有记录。正式规则默认排除模拟来源。
3. **数据不可判断**：加入无效数据、缺口或派生等待状态，界面明确显示无法评估；不会将它们变成正常或使用陈旧值继续推断异常。
4. **处置流程**：站内通知可读，确认后核查、填写研判、附件和处置，经复核关闭；每步保留人员、时间和原因，恢复状态不自动关闭事件。
5. **历史与变更**：修改规则不改写旧事件；撤销事件输入后出现依据失效提示；历史补算不批量发送实时通知。
6. **空间与大屏**：对应对象可定位事件；SDK 查询、汇总和订阅返回一致版本，恢复连接后更新完整；事件关闭后保留获准的历史查询并更新处理状态，运行会话关闭或撤权后停止该会话供数。
7. **权限与隔离**：两个项目共用同一通道仍执行各自规则及权限；无权者不能读取事件证据、附件、汇总或通过大屏间接取得数据。
8. **故障与恢复**：评估和通知中断后恢复，不重复副作用；迁移、备份及恢复保留规则、事件、证据、任务和处理历史。

本轮需要功能、故障、隔离及集成自验；大型性能、压力和长时观察沿用既有暂缓决定，另行专项安排。合成数据只证明软件行为，真实工程阈值与处置规则仍需业务方确认。

## 7 本轮范围之外

- 设备接入、厂家协议、原始报文解析、网关和设备控制，按用户最新决定后置。
- 完整数据质量平台、人工修正／补值发布、科研算法沙箱、专业健康评分和高频波形处理。
- 正式日报／月报／专项监测报告，以及完整项目资料和巡检维护模块；本轮仅保存事件自身的附件与处置记录。
- 短信、电话、邮件及企业通信平台的实际外部投递；本轮交付站内通知并保留明确适配接口。
- 成品大屏、部门跨项目驾驶舱、通用审批、待办协作、维护派单及合同履约管理。
- 全平台配额、许可、统一身份服务及全范围用途权益重构。

规则作用范围、基础规则集合、站内通知和上述边界均是本次建议。范围确认后再固化详细开发设计；当前没有实施业务代码或将本提案标为已接受。
