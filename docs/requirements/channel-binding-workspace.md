# 测点与设备绑定：C 统一入口 + B 设施快捷入口

状态：Awaiting acceptance。C + B 已正式实施并完成自验；用户验收尚未进行。检查证据和人工验收步骤见 `docs/verification/channel-binding-workspace.md`。

## 目标与范围

租户管理员从「监测业务 → 测点与设备绑定」直接进入 C 双栏配对：左侧找到设施、测点及业务通道，右侧选取语义一致的设备通道，核对关系后提交。在设施详情增加醒目的「设备绑定」入口及页签，以 B 的测点分组、设计要求与实际设备对照卡片就地操作。测点详情也提供同一入口。

两个入口共用真实的绑定、切换、解除、预览和历史流程。绑定对象仍是直接业务通道与具体设备输出代次，保留监测设计和现场实施的独立性。派生通道继续使用派生计算。安装位置及安装历史保持独立；绑定不代表设备在线或已有监测数据。

## 实现

- 新增租户绑定目录只读接口，支持跨设施搜索、设施/测点/状态筛选、服务端游标分页和筛选范围内的状态数量。批量投影当前绑定，避免原型逐通道请求和首 50 项截断。
- C 使用正式路由 `/t/:tenantId/bindings`，可从侧栏发现、可刷新及分享定位链接。B 在设施/测点详情的「设备绑定」页签中，仍保持资源树和当前详情上下文。
- 共用候选设备通道选择器、关系摘要和确认弹窗。兼容性、占用、停用、退役和受限状态提供文字说明；失败不显示成功。真实提交沿用后端预览哈希、双端修订号、幂等请求及回执恢复；发生冲突重新读取后再核对。
- 读取与操作按现有工程资源、设备和来源维护权限控制。目录不暴露无权查看的设备；只读用户不显示维护操作。项目原有入口及授权规则继续保留。
- 完成后同步刷新绑定目录、当前关系、候选可用性与历史。展示服务端返回的完整分页历史及生效时间。
- 原型保存到本地评审产物目录，并记录 C + B 决策；从正式应用移除方案切换器、模拟状态、DEV 导航和原型启动脚本。遵守当前分支工作约定，不创建分支或工作树。

## 技术

React / TypeScript、TanStack Router 与 Query 实现路由、查询缓存及分页；使用仓库现有 shadcn/ui 组件、语义颜色及响应式布局。Go / Gin 在现有 sources 服务内提供目录读取，PostgreSQL 关联现有工程资源和来源关系，无新增业务表。OpenAPI 同步生成 TypeScript 类型。来源写入继续复用既有事务和约束，不另建关系模型。Playwright 完成真实浏览器操作、窄屏及截图；Go 集成测试验证权限、过滤、分页及原有来源写入规则。

## 验收

1. 租户侧栏可直接进入 C，搜索/筛选可找到分页之外的通道；刷新及深链接保留定位。
2. 设施及测点详情可从明显入口进入 B，看到按测点分组的设计要求、未绑定/已绑定/需处理状态；可回到统一入口。
3. C 与 B 均可真实绑定、切换和解除，需填写原因并核对关系与影响；返回另一入口/刷新后状态一致。
4. 已占用、不兼容、停用和无候选有明确反馈；受限和只读不能越权；并发变更保留输入并要求重新预览。
5. 历史保留时间边界，切换前后相邻，解除后仍可查；设备安装记录不被改变。
6. 类型、相关 lint、生产构建、权限/契约检查、来源集成测试和真实浏览器自验通过；无模拟成功或原型切换入口。
