# 账号开户邀请页面重构（A 方案）

状态：Awaiting acceptance。2026-11-11 用户选定 A「列表优先」并授权实现及补齐必要功能；正式功能已实现并完成自验，等待用户手动验收。验证结果见 [验证与验收记录](../verification/account-invitations-refactor.md)。

## 目标与交付

将 `/invitations` 改为记录列表为主、右上角创建入口。新增状态页签与数量、用途备注搜索、行操作菜单、详情抽屉、创建/重新生成弹窗、撤销确认和首次使用引导。保留既有权限、账号隔离、最近密码确认、单次邀请、链接仅生成后展示、重新生成保留旧记录等规则。

## 设计与技术

- React/TypeScript 与现有 shadcn/ui：PageHeader、Table/DataTable、Tabs、Input、Dialog、Sheet、DropdownMenu、AlertDialog；复用控制台导航、主题和布局，不加入原型切换条或示例数据。
- TanStack Query：按账号及筛选条件隔离分页缓存；操作后刷新列表、统计和详情；查询可取消，切换账号或丢失权限时丢弃弹窗及完整链接。记录按创建时间与 ID 倒序，每页 50 条，支持加载更多。
- Go/PostgreSQL：扩展 GET `/api/v1/invitations` 的 `q` / `status` 查询，服务端进行字面包含搜索和状态筛选；增加 `total`（当前条件的总条数）及 `counts`（当前账号全部邀请各状态数量，不受筛选和游标影响）。使用同一 SQL 快照返回列表和统计，过期状态实时计算。新增只读 GET `/api/v1/invitations/{id}`，详情也校验所属账号和读权限。不需要数据库迁移。
- OpenAPI 与类型生成：同步接口参数、响应和 TypeScript 客户端。
- 本地运行：新增详情路由会改变权限目录校验值，启动新 API 前使用同版本 CLI 执行 `access sync --dry-run`、`access sync`、`access check`；本次验收环境只同步路由校验值，没有改变权限项或角色授权。
- 表单通过 React Hook Form / Zod 校验备注的 200 个 Unicode 字符上限。密码确认后要求用户再次明确提交生成，沿用现有禁止自动重放写请求的规则。生成结果的有效期来自后端，不在界面硬编码 24 小时。
- Playwright 与 Go 集成测试：验证分页筛选统计、归属隔离、真实生成/重新生成/撤销、权限收回、跨账号清理、密码确认、复制失败回退、窄屏布局。

## 手动验收

1. 无邀请时显示首次创建入口；创建表单只在点击按钮后展示。备注最多 200 个字符。
2. 创建成功展示有效期及可手动复制的完整链接；关闭后列表增加记录，重新打开表单不重显旧链接。
3. 状态筛选和搜索覆盖全部记录，数量不受前 50 条分页限制；加载更多无重复、无漏项。搜索 `%` / `_` 按普通字符处理。
4. 详情以抽屉展示真实记录，已使用记录没有重新生成/撤销操作；只读权限账号只可查看。
5. 重新生成需明确提交；旧链接失效且记录保留。撤销需确认，成功后刷新状态和统计。
6. 密码验证过期时在弹窗中确认；确认密码本身不自动生成，用户再次提交后才执行。
7. 切换账号、丢失读权限、关闭弹窗后，不显示旧账号或上次生成的完整链接；失败可重试且不自动重复写入。
8. 桌面、窄屏和深色主题可使用，键盘可进入及关闭弹窗，焦点返回操作入口。
