# 工作空间导航重构方案与原型

日期：2026-11-11。状态：**Awaiting acceptance**。原型自验证通过，等待用户评审；尚未批准正式实现，也没有用户验收结论。

## 要回答的问题

租户与项目已能在左上角切换，账号层还保留「首页 / 我的租户 / 我的项目」侧栏和两个选择列表页，会重复同一任务。移除重复页面后，首页怎样独立存在，进入业务空间后又怎样组织功能导航？

本轮按 prototype 技能的 UI 分支，在既有路由上提供三种结构，用 `?variant=A/B/C` 和底部对比工具切换。首页直接复用原 HomePage，正文、卡片、文案、权限判断和数据读取都不改。

## 推荐方案 A

使用贯穿全站的顶栏。左侧保留品牌、工作空间选择器和首页入口，右侧保留页面搜索、主题和账号菜单。品牌也能返回首页。选择器始终位于左上方，业务侧栏出现或消失时不移动入口。

| 页面范围 | 导航形态 | 主要入口 |
| --- | --- | --- |
| 首页 `/` | 顶栏，无左侧菜单与折叠按钮 | 左上角选择工作空间；首页正文保持现状 |
| 个人资料、账号安全 | 同首页外壳；保留内容区内现有设置导航 | 右上角账号菜单 |
| 租户工作空间 | 顶栏 + 租户业务侧栏 | 租户资料、项目治理、成员及已有业务功能 |
| 项目工作空间 | 顶栏 + 项目业务侧栏 | 项目资料、成员、角色等当前可访问功能 |
| 平台工作空间 | 顶栏 + 平台业务侧栏 | 平台管理功能，仍按权限显示 |
| 手机与窄屏 | 顶栏 + 按钮打开业务抽屉 | 个人空间不显示业务导航按钮 |

账号层的「概览 / 工作空间」侧栏分组整体取消；「我的租户」「我的项目」独立列表页退出正常用户流程。进入租户、项目或平台后，仅显示该空间有实际业务含义的导航。不会为了保留首页人为凑出一个侧栏。

首页保留为普通登录的默认落点，后续工作台的内容建设另开迭代。正常登录不自动恢复上次租户或项目；未登录时主动打开的有效业务深链接仍按现有 `returnTo` 回到目标页面，不额外改变认证约定。

## 三种结构对比

| 原型 | 结构 | 适合情况 | 代价 |
| --- | --- | --- | --- |
| **A · 推荐** | 全站统一顶栏，业务空间显示左侧导航 | 管理功能较多，需要频繁切换；兼容当前页面与后续工作台 | 业务空间占用侧栏宽度；个人与业务空间内容宽度不同 |
| B | 双层顶栏，第二行按业务分类打开菜单 | 重视页面宽度、功能分类少而稳定 | 分类菜单多一次点击，功能增长后顶栏拥挤 |
| C | 紧凑顶栏，内容区按钮打开业务导航抽屉 | 低频管理、希望尽量扩大内容区域 | 功能发现性较弱，每次切换通常需打开抽屉 |

三版比较的是导航结构；业务内容一致。应先从首页切入同一个租户或项目，再使用底部箭头比较。底部工具仅用于原型，正式产品不会出现。

## 选择器接住被取消页面的能力

- 在选择器内搜索名称或编号，按全部、租户、项目筛选；保留分页加载入口。
- 项目显示所属租户。仅有项目资格而没有租户业务权限时，租户只是分组标签，不能因此获得租户入口。
- 当前空间有选中标识；同名项目通过所属租户与编号区分。
- 已归档项目保持状态标识，并按照原权限进入。停用租户可查看状态，但不能进入正常租户业务。
- 空结果、未加入空间、读取失败重试放在选择器中处理；权限仍由现有前后端资格检查裁决。
- 平台入口仅向已有平台权限的账号展示。它不是所有账号的默认空间。

正式版本需要核对服务器对项目名称、编号及所属租户名的搜索语义。原型使用现有查询参数；本轮不扩展 API 搜索契约。

## 路由和旧入口处理

| 入口 | 建议行为 |
| --- | --- |
| `/tenants` | 替换导航到首页并自动打开选择器，选中「租户」 |
| `/projects` | 替换导航到首页并自动打开选择器，选中「项目」 |
| 首页既有「我的租户」卡片 | 本轮正文和链接保持不变，通过上面的兼容路由进入选择器 |
| 页面内「切换项目」「返回我的租户 / 项目」 | 正式实现改成「切换工作空间」或「返回首页」等贴合场景的入口；原型先由兼容路由接住 |
| 个人资料、账号安全 | 保留原路由，右上角账号菜单可达 |
| 租户内 `/t/:tenantId/projects` | 保留，这是项目治理，承担管理职责，不属于账号的「我的项目」选择列表 |
| 平台 `/platform/tenants` | 保留，这是租户管理，不属于账号的「我的租户」选择列表 |

清理范围要同时覆盖侧栏配置、页面搜索、切换器底部的「查看全部」、错误页、租户和项目资格失效页、邀请流程取消入口及旧书签。不能只删菜单。兼容路由用 replace，避免返回键在废弃列表入口和首页之间反复跳转。

## 组件与数据流

正式实现建议把 `WorkspaceShell` 的空间与权限判断继续保留在应用层，向共享布局传入当前空间、业务菜单、用户入口和内容。共享布局负责统一顶栏、可选业务侧栏、窄屏抽屉和内容区，不读取业务 API。

1. URL 决定个人、租户、项目或平台空间；继续使用现有 `workspaceScope`。
2. 现有认证和租户 / 项目边界读取上下文、核验资格，并负责切换后的缓存清理。
3. `navigation` 产生当前空间的业务菜单；个人空间不产生占位侧栏。
4. 选择器按需读取 `myTenants` 与 `myProjects`，点击后跳到现有空间路由；标签页之间不引入共享的当前空间状态。
5. 页头、搜索和账号菜单复用同一份入口数据，避免重复定义或权限不一致。

原型文件刻意与真实布局相邻，并在文件名和顶部注释标出 prototype；不作为可直接合并的正式实现。

## 技术选型

| 技术 | 本轮及正式方案中的用途 |
| --- | --- |
| TypeScript + React | 延续现有前端，组合顶栏、侧栏和抽屉；原型交互状态保存在组件内 |
| TanStack Router | 保留既有文件路由和鉴权边界；URL 携带原型方案，兼容旧列表路径 |
| TanStack Query + 现有 API client | 复用账号、租户和项目读取及缓存隔离，不自建另一套权限模型 |
| shadcn / Radix、Tailwind CSS、Lucide | 复用现有菜单、抽屉、输入、主题 token 和图标，沿用应用视觉语言 |
| Vite + pnpm | 单命令启动独立预览；开发环境开关启用原型，生产构建不显示对比工具 |
| 现有 Go API / PostgreSQL / Redis | 仅通过现有 API 读取验收环境数据；不新增存储、不迁移数据库、不修改业务状态 |

没有新增依赖。预览服务器在转发前拦截业务写请求，活跃心跳只在本地返回；需先在原验收站点登录，再在同一浏览器访问原型。

## 结论与归档规则

当前建议：**A**，理由是可见的业务导航适合本项目较多的管理功能，并且首页与未来工作台不再受空侧栏限制。**这是建议，不是已确认决策。**

用户尚未选择获胜方案。全套原型保存在独立原型分支；选定后应按正式质量要求重写所选结构，并把选择理由和本文件 / 分支指针带入实际实施任务。没有创建或发布外部 issue、PR，也没有把原型合入开发分支。

自验证结果单独记录在 `docs/verification/workspace-navigation-prototype.md`；自验证通过不等于用户验收。
