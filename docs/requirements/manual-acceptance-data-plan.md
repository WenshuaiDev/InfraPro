# 全功能人工验收数据准备

日期：2026-11-10。状态：Awaiting acceptance。用户要求由 Codex 创建账号并补齐当前已完成功能的数据，再由用户手动验收。准备、接口检查、浏览器检查和重启保留验证已完成；人工验收待用户确认，见[自验记录](../verification/manual-acceptance-data.md)。

## 目标与范围

提供独立、持久化的本机验收环境，覆盖账号与个人安全、开户邀请、平台角色与审计、租户建档与交接、成员邀请和授权、租户启停、项目治理和归档、工程定义和监测模板、设施/构件/测点/业务通道，以及工作空间切换和响应式页面。

账号按实际权限分工；样例采用明确标为“验收”的虚构单位、项目和工程资料。准备正常数据、可供修改的练习对象，以及停用、暂停、移除、归档、退役、删除等历史数据。保留一条未领取成员邀请和开户邀请。一次性链接有有效期，过期后可用管理员重新生成。

## 实施方式与技术

- 复用现有 Go/Gin API、Go 运维 CLI 和 React/Vite console，构建当前工作区版本。
- 在现有本机 PostgreSQL 容器中创建专用数据库；Redis 使用独立键前缀。普通开发库和原有账号保持原状。
- 专用入口为 `http://localhost:25173/`，API 仅监听本机 `127.0.0.1:28080`。使用 localhost 隔开现有 127.0.0.1 环境的 Cookie。
- Node.js 脚本编排环境和通过真实 HTTP API 建立业务数据；首个账号通过现有交互 CLI 创建。所有版本、预览、权限、审计规则均走业务接口。
- 凭据和含邀请令牌的链接仅写入 Git 忽略的 `.artifacts/manual-acceptance/`，文件权限 0600。可提交文档不含密码或令牌。
- 启动命令只启动已有环境，不重置数据。数据准备按阶段保存进度，重复执行已完成阶段不会重置用户的验收操作。

## 交付与验收

交付入口、账号密码本地文件、数据清单、模块操作顺序、预期结果、重启方法和自验记录。验收数据通过 API 核对权限及跨租户隔离，并用 Chromium 检查主要账号的页面访问和示例数据显示；停止再启动服务后确认数据仍在。自验通过后状态改为 Awaiting acceptance，用户明确确认后才可记为 Accepted。

真实采集、观测数据存储、图表告警、地图/图纸/模型绑定等当前未实现功能不伪造演示数据。完整业务验收仍由用户执行；本轮准备和抽查不替代所有既有自动回归测试或生产部署验证。
