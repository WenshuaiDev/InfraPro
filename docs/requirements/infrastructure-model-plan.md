## 1. 目标和核心建议

采用 **通用监测底座 + 可配置的专业模型与监测模板 + 可组合的功能模块**。在现有单个 Go API 和 React console 中按业务模块组织，随系统版本统一构建发布。

达到以下行为：

- 新增设施类型、构件类型、属性字段，以及使用现有数据形态和处理能力的监测指标，通过管理界面配置和发布即可生效，不修改源码、不重新构建部署。
- 新增已有功能的组合，通过模板与实际启用配置完成，例如为另一座桥梁启用已经实现的视频监控。
- 首次出现平台没有的处理能力，例如视频播放、专门分析算法或新设备协议，开发一次相应模块或适配器；后续由不同设施复用。此时允许增加代码、迁移和发布，但核心设施业务不增加按设施类型分支的规则。
- 专业模型表达设施和监测含义；功能模块实现行为。模型配置只能引用系统已经支持的能力。

目前的目标不能表述为“未来任何新功能都不需要开发”。可承诺的是：在已支持的能力范围内，新增类型与配置组合不需要开发。

## 2. 五个概念及关系

以下术语记录早期方案讨论。当前规范用语见仓库词汇表；独立“项目监测方案”已由后续讨论取消，实例设计以本文开头链接的新方案为准。这些讨论不代表其余编制职责、生命周期或迭代范围已获确认。

| 概念 | 回答的问题 | 示例 |
| --- | --- | --- |
| 设施类型 | 这是什么类别的设施？ | 桥梁、边坡、大坝；类型具有稳定标识，不使用程序枚举限制可新增类型 |
| 设施模型 | 这类设施允许怎样的结构和属性？ | 梁桥模型、斜拉桥模型；允许的构件类型、父子关系、数量约束、字段与校验 |
| 监测模板 | 面向某种监测目的，建议监测什么、如何组织？ | 位移与应变监测项、适用构件、推荐展示方式和已有功能的默认组合 |
| 功能模块 | 系统能够完成什么操作？ | 设施档案、时序监测、告警、视频、巡检、专业分析 |
| 实际设施与项目监测方案 | 现场究竟有哪些对象，本项目怎样使用它们？ | 租户维护某桥及构件、测点、通道和数据来源；项目方案引用获准资源，确定监测项、功能、告警及展示 |

一个设施类型可以有多个模型；一个模型可以有多个适用的监测模板。模型和模板组合，不采用多层继承来隐式传播变化。设施保存采用的模型版本；项目监测方案保存实际配置及模板来源版本。租户资源配置与项目监测方案分别记录，二者不能合为一份可被任意项目覆盖的配置。

这里的设施模型是业务结构模型，不等于 BIM 或三维模型文件。以后可为同一设施关联三维展示资源。

已确认租户统一管理工程资源，项目按授权引用并分别维护监测方案。在此基础上，建议平台维护公共设施模型、指标及公共监测模板；租户可复制、维护私有监测模板，首轮不编制私有设施模型或独立指标定义。模板编制职责仍待用户确认，具体配置和职责见第 12–15 节；本轮范围及待确认规则见第 16–17 节。

## 3. 结构和属性怎样配置

模型定义构件类型、允许的父子关系、数量约束及属性表单；实例记录实际编号、数量、位置和属性值。某座桥有多少桥墩不写在桥梁程序中，也不因为一个工程的特殊数量而修改所有桥梁模型。

结构以树表达物理组成，支持可选构件和重复构件，验证父子合法性、无环及数量规则。监测断面、分区和监测对象分组与物理组成分别表达，通过引用关联构件，避免为展示分组复制真实构件。

属性配置包括稳定字段标识、名称、数据类型、必填、枚举、范围和单位；展示配置另行表达分组、顺序和控件。名称可变，稳定标识不变。

首期支持哪些字段和关系约束应在实施方案中列为有限、明确的能力集。超出支持范围的任意脚本、流程和计算不通过字段配置偷偷实现。

## 4. 监测内容和指标怎样配置

监测项表达业务关注点，例如桥梁挠度监测、边坡深部位移监测、大坝渗流监测；每项引用一个或多个指标定义，并说明适用设施或构件、分组及所需能力。它们可以复用已有数值监测、曲线和告警模块。

指标具有稳定标识、明确含义、数据形态、单位量纲及适用范围。相同显示名称不代表相同指标；方向、参考基准、测量含义不同的位移，应明确区分或以受校验的参数表达。工程属性与随时间变化的观测值分开存放。

建议分别表达公共资源与项目使用关系：

```text
租户设施 / 构件
    └─ 测点及其指标通道
         └─ 数据来源绑定（设备采集、人工录入或已有计算能力）

项目监测方案
    └─ 实际监测项
         └─ 引用获准的测点与指标通道
```

设施模型不定义设备通信协议；数据来源绑定负责把实际数据映射到测点指标，设备替换不改变物理构件或监测指标身份。

新增一个已有形态的位移指标可以配置；新增平台不支持的波形处理、分析算法或协议需要扩展对应能力。工程参数必须明确归属：测量基准、标定、实际设备采样等改变公共数据的配置由资源维护方管理，项目告警阈值及业务展示由项目监测方案管理，不能从“设施类型”自动推断工程安全限值。模板中的值只能作为有来源的初始建议；项目提出的采样需求不直接改写设备配置。

## 5. 功能模块及视频示例

每个模块拥有自身业务实现和必要的数据，通过稳定的设施、构件或监测对象标识进行关联。模块登记自身标识、支持的使用上下文、配置格式、依赖、兼容要求、页面入口和真实权限；启用时统一校验。

模块先采用编译期装配：后端 Go 业务模块、HTTP 接入和前端 React feature 随现有应用发布。配置可以选择已有模块，不能把任意代码、页面地址或数据库脚本变成已实现功能。

视频模块的职责可以包括摄像机与设施关联、视频访问授权、实时播放，以及后续明确需要的回放和云台能力。模块通过视频接入适配器连接实际平台；不同协议的适配成本属于接入层。流媒体所需部署组件在视频实际立项时确定。

大坝模板可默认推荐视频，具体大坝在绑定摄像机后使用；桥梁模板也可以引用同一个视频模块。系统不使用“设施类型等于大坝”作为视频可用条件。

首次建设视频仍需要开发和发布；完成后，为另一种设施启用现有视频能力不再开发一次。

## 6. 页面、菜单及项目如何工作

菜单由现有页面入口、当前上下文启用的模块和用户有效权限共同生成。类型配置可以影响业务分组、名称、默认视图；实际操作页面由通用模块或扩展模块提供。

可使用某功能需要同时满足：模块已部署且兼容、当前业务上下文已启用、用户拥有操作权限、目标资源位于获准范围、相关账号/租户/项目状态允许操作。前端展示和后端请求使用一致的判断依据；隐藏菜单不替代后端鉴权。

模块权限接入现有唯一权限目录，不按桥梁、大坝复制整套权限。启用功能本身不授予访问权限；角色配置也不代表模块已经启用。

项目可组织多类设施。例如同一项目同时监测桥梁、边坡、大坝，共用设施列表、监测、告警和视频入口，再按获准设施筛选。建议实际业务功能组合记录在项目监测方案中，可按方案中的设施选择适用功能；租户资源配置记录摄像机等公共绑定，不作为所有项目共同的业务开关。启用管理入口允许有权人员完成初始配置，不要求先有观测数据。

已确认设施、构件、测点等资源由租户统一管理，多个项目按授权引用，各自维护监测方案；不因为进入另一个项目而复制物理设施。资源主责、授权粒度、撤权联动及维护委托的具体操作需要后续资源方案确定，本文不宣称相关授权已经实现。

关闭模块与删除数据是两种操作。建议关闭停止该上下文的常规使用并保留资料；重新启用时按当前状态及权限恢复。采集、回放、后台任务是否继续，应由各真实模块的生命周期规则明确说明。

## 7. 三种设施的组合示例

下表只为说明配置关系，不是完整的工程监测规范。

| 场景 | 结构示例 | 监测内容示例 | 使用功能 |
| --- | --- | --- | --- |
| 桥梁 | 桥墩、梁、支座 | 位移、应变、振动 | 档案、监测、告警；可按工程需要加视频 |
| 边坡 | 坡面、锚杆、挡墙 | 表面或深部位移、降雨 | 档案、监测、告警；可按工程需要加视频 |
| 大坝 | 坝段、廊道、坝基 | 位移、渗压、渗流量 | 档案、监测、告警、视频 |

使用者体验是：选用发布模型建立租户设施 → 根据现场建立构件及测点、配置数据来源和摄像机关联 → 向项目授予所需资源使用范围 → 项目应用监测模板并绑定获准资源、调整实际方案 → 在公共或专业页面开展监测。具备相应资源维护权限的项目人员可完成现场建档，写入的仍是租户统一资源。平台配置人员通过可视化界面完成模型和模板编制，不要求业务人员编辑 JSON。

## 8. 发布、版本和历史解释

模型与模板采用草稿、校验、预览和发布流程。已发布版本不可原地修改，实例固定引用采用的版本；新版本不自动重写已有设施。发布快照同时固定引用的指标定义及其他会改变解释的依赖版本，避免外层版本未变、内部含义已经变化。

后续新增必填字段、删除构件类型、改变指标含义或单位，必须评估已有实例影响，通过明确升级过程处理；历史数据保留当时含义。相同含义的单位转换应保留来源单位并按受支持规则换算，不能通过更改字典标签重新解释历史值。

模板更新不自动覆盖实例已经调整的配置。停用或退役模板默认阻止新选用，既有引用和历史读取继续按原版本处理。

模块兼容契约与业务模型版本分别管理：设施引用的配置格式必须由当前部署模块支持。不能把固定模型版本误解为必须同时运行任意旧代码版本。发布和启用时发现缺失或不兼容能力，应明确阻止并提示原因。

## 9. 技术选择与实现位置

| 技术 | 在本方案中承担的工作 | 选择原因 |
| --- | --- | --- |
| Go + Gin | 在共享业务模块中实现模型校验、发布、版本与能力规则；Gin 负责 HTTP 接入 | 延续现有架构，核心规则同时约束界面和直接请求 |
| PostgreSQL | 用关系表保存类型、身份、版本、引用、结构关系和权限相关信息；用 JSONB 保存受约束的模型定义及扩展属性 | 支持可变业务字段，同时保留引用完整性和事务约束；不按设施类型建表 |
| JSON Schema 的明确受支持子集 | 表达字段类型、必填、枚举、范围等数据约束，由前后端使用一致定义校验 | 标准化字段规则；构件关系和跨对象规则仍由 Go 业务逻辑执行 |
| React + TypeScript、现有表单和 UI 包 | 编制模型、预览结构、按元数据渲染表单、装配功能页面及菜单 | 延续单 console 与共享布局，通过有限控件集支持动态字段 |
| OpenAPI | 定义固定的业务操作和元数据传输契约 | 新设施类型只新增配置数据，不为每种类型生成一套接口 |
| 现有 access、审计及迁移机制 | 模型编制/发布授权、模块权限目录、审计、增量数据库迁移 | 保持现有账号、租户、项目规则和运维方式 |

JSON Schema 是数据规则的来源；既有表单工具负责交互，不再另写一套随类型变化的字段规则。具体前后端校验库在实施前选定并核验支持的规范版本与子集。

实时观测数据不塞进设施属性 JSONB。时序数据存储、告警执行和流媒体接入按实际监测规模及需求分别设计。本稿不提前选定时序数据库、微服务拆分或运行时插件市场。

## 10. 建议的实施顺序和可观察验收

整体方案与本轮交付范围分别确认。下列为整体建设顺序；本轮建议对应第一步，具体交付与限制见第 16 节，不将整个路线图计入本轮：

1. **模型与模板编制闭环：** 类型、构件、属性、指标和单位、监测模板、发布版本、预览及权限审计；明确已有能力引用与校验规则。先支持实际存在的页面和能力，未实现模块不能显示为可用功能。
2. **实际设施使用闭环：** 设施建档、构件实例、测点和指标通道、实际配置、版本引用及资源使用范围，接入相应的通用监测页面。验证模板确实能够驱动实际业务。
3. **第二种功能形态验证：** 在视频成为真实需求时，实现可复用视频模块，并分别用于大坝和桥梁，验证菜单、资源关联、启用与权限链路。只预留一个名称不能算已验证扩展能力。

第一步完成能验收“模型可配置”，第二步完成才能验收“配置驱动实际监测”，第三步完成才能验收“新功能模块可复用”。不得把其中任何一步的结果表述为整体目标已全部完成。

整体验收场景：

- 通过页面配置并发布桥梁、边坡、大坝模型；在相同通用页面上呈现不同结构、字段和指标。
- 再新增一种未写入程序的设施类型，使用已支持的结构规则、字段和监测能力，完成发布及实际使用；期间不修改源码、增加类型专用表或重新部署。
- 在视频模块已实现的前提下，为大坝启用视频，再为桥梁启用同一模块；两次启用都只需配置，没有设施类型专用判断。
- 混合设施项目正确汇总可用能力并过滤资源；直接请求也不能越权或绕过停用状态。
- 发布模型 V2 后，采用 V1 的设施结构与历史数据含义保持不变；升级可展示影响并明确执行。
- 未实现能力、单位不相容、非法构件关系、未获准的配置变化均给出明确校验反馈。

本次仅编写讨论稿并核对其与当前代码架构的衔接，未执行功能测试，未进入 Awaiting acceptance。

## 12. 设施模型的具体编制步骤（建议）

模型回答“允许怎样的设施结构和档案”，不规定每座设施必须采用同一套监测业务。以梁桥为例，以下内容均为配置示意，不代表工程规范。

| 步骤 | 编制内容 | 示例与结果 |
| --- | --- | --- |
| 1. 基本资料 | 选择设施类型，填写模型名称、稳定标识、说明 | 在桥梁类型下创建“梁桥模型”；以后可另建斜拉桥模型 |
| 2. 构件类型 | 定义可用构件类别及其属性集合 | 主梁、桥墩、支座；模型定义类别，不填现场的实际构件清单 |
| 3. 结构规则 | 定义允许的父子关系、可选或必需关系、重复数量约束 | 允许多根桥墩、可选构件；不要求所有类型拥有相同层数，实际数量由现场建档确定 |
| 4. 属性字段 | 在设施及各构件类型上定义字段、类型、单位、必填和取值约束 | 桥梁长度为带长度单位的数值、结构形式为枚举、桥墩高度为数值；具体填写值属于设施档案 |
| 5. 表单呈现 | 定义分组、顺序、提示和支持的输入控件 | 基本资料、尺寸信息；同一套通用表单根据定义呈现 |
| 6. 校验与预览 | 检查标识、关系无环、字段及单位规则，并以样例预览结构和表单 | 无法把不允许的构件挂入结构；模型可选、重复规则可操作 |
| 7. 发布 | 发布不可变版本，用于新设施建档 | 梁桥模型 V1；修改后形成 V2，旧设施不自动升级 |

模型中的“构件类型”与现场的“构件实例”分别管理。例如模型有“桥墩”类型，某座桥实际建立 P1、P2、P3 三个桥墩；另一座桥可以建立不同数量。监测断面或展示分组引用这些对象，不为分组重复建档。

结构规则约束正式有效的档案，分步录入时允许草稿暂不完整，并明确展示缺项。发布或完成建档时才检查完整性，避免用户必须在一次请求中录完全部构件。

模型及属性的配置基于平台已经支持的能力集；新增设施类型不增加类型专用代码或表，新增字段类型及执行能力则仍属于平台功能扩展。

## 13. 监测模板的具体编制步骤（建议）

监测模板回答“针对某种任务，如何组织监测”，输出项目监测方案的初始配置。模板不保存某个客户现场的实际摄像机、设备口令或测点标识。

| 步骤 | 编制内容 | 示例与结果 |
| --- | --- | --- |
| 1. 适用范围 | 选择支持的设施模型版本和监测目的 | “梁桥日常监测”适用于选定的梁桥模型版本 |
| 2. 监测项 | 按业务目的分组，指定目标构件类型及可选项目 | 主梁竖向位移、支座温度；同一模型另有其他任务模板 |
| 3. 指标定义 | 从公共指标目录引用指标，指定所需值形态和单位 | 竖向位移、温度；模板不通过改名改变指标含义 |
| 4. 资源绑定要求 | 定义需要绑定的对象类别和数量要求，留待工程使用时选择 | 某项需选一个或多个主梁测点的竖向位移通道，不在模板中绑定具体编号 |
| 5. 功能建议 | 选择已实现且兼容的监测、告警、视频等模块及默认组合 | 视频为可选，选用视频后需绑定获准摄像机；依赖未满足时方案不能正式启用 |
| 6. 展示与规则初值 | 选择已有图表、分组和展示单位；声明需现场确认的工程参数 | 默认趋势图；告警阈值待工程填写或明确确认有来源的推荐值 |
| 7. 校验、预览与发布 | 校验目标构件、指标单位、模块依赖与版本，发布不可变模板版本 | 生成可预览的示例方案，发布模板 V1 |

模板可以覆盖多个明确兼容的模型版本，但不能仅凭“都属于桥梁”就自动套用；采用时重新验证目标构件和通道要求。新增支持的模型版本或改变解释含义后形成模板新版本。

模板给出的监测项可按工程需要选择；保留下来的监测项必须满足自身指标和资源绑定要求。模板中的告警示例不是自动生效的工程安全限值。采样需求仅作需求说明，不直接作为共享设备的控制指令。

建议租户可以复制公共模板的某个发布版本为私有草稿，调整监测项、默认功能组合及展示，校验后发布为本租户模板；也可以使用现有模型和指标新建私有模板。私有模板不可更改公共模型结构或公共指标含义，不需要平台逐份审批，编制、发布权限由租户内有效授权控制。

复制后保持独立，只保存来源以便追溯；平台模板升级不会覆盖租户版本，租户模板升级也不会自动覆盖现有项目方案。私有模板转为公共模板属于另一项明确的发布行为，不因为被多个项目使用就自动公开。

## 14. 平台、租户、项目职责（建议）

| 对象或操作 | 平台 | 租户 | 项目 |
| --- | --- | --- | --- |
| 设施类型和模型 | 编制、校验、发布公共版本 | 选用已发布版本建立真实设施；提出所需新定义 | 引用获准设施及其模型，不另建一份结构真相 |
| 指标与单位 | 统一定义含义、形态、适用性和单位规则 | 按定义建测点/通道；所需新定义由平台配置补充 | 选择获准通道、展示单位及受支持分析 |
| 监测模板 | 提供公共模板和版本 | 使用公共模板，编制/发布本租户私有模板 | 选用模板并形成实际项目监测方案 |
| 实际设施和构件 | 平台身份本身不产生业务维护权 | 统一建档、维护结构和属性 | 引用；被明确授予资源维护能力的人员可现场维护统一档案 |
| 测点、数据源和摄像机 | 提供已实现能力及接入支持 | 管理资源身份、关联、接入和影响公共数据的设置 | 选择获准资源；普通监测配置不改写公共设备参数 |
| 资源使用范围 | 提供授权机制，平台身份不代替业务授权 | 明确授予项目可使用哪些资源及读/维护范围 | 在获准范围内分配成员操作职责 |
| 实际功能组合 | 由开发实现模块，平台提供可用能力目录 | 准备相应资源并管理可授予的使用范围 | 按工程需要选择兼容功能，并受资源范围和人员权限约束 |
| 工程监测方案、告警与展示 | 提供通用规则执行和页面能力 | 可维护可复用的私有模板 | 绑定具体通道、选择监测项、配置项目规则、展示及接收人员 |

“平台、租户、项目”表示业务操作范围，同一账号可以在不同范围承担不同职责。平台管理员、租户管理员、项目管理员称谓本身都不构成跨范围业务访问权。租户资源维护权限允许维护该资源，不自动允许读取项目私有分析结果和全部项目业务内容。

租户人员可以直接维护公共资源，也可以明确授权合格人员承担某些资源的现场维护。项目人员从项目页面维护时，操作仍需满足资源维护授权和相应角色权限，写入统一档案并记录审计，不建立项目私有的第二份设施。

采样频率、设备接入、标定和测量基准属于公共资源配置；项目告警阈值、趋势显示时间窗、看板及项目分析参数属于项目方案。修改公共配置应展示使用该资源的项目影响，记录生效时间；需要更高采样率的项目提出需求，由资源维护方统一调整。项目中的展示重采样不等同于改变设备采样频率。

项目规则产生的告警归属相应项目，不能把一个项目的告警状态当成同一设施在所有项目中的统一结论。若未来需要租户范围的统一告警，应单独确定其规则归属和共享语义。

## 15. 从配置到实际使用的贯穿例子（建议）

1. 平台发布“梁桥模型 V1”、竖向位移和温度指标，以及“梁桥日常监测模板 V1”。模型允许相应构件和属性；模板提出监测项与功能建议。
2. 租户为“东河桥”建档，录入实际主梁、桥墩和支座，建立测点及通道，绑定数据源；另将摄像机 C1 与该桥关联。这些资源只维护一份。
3. 租户把该桥及所需通道授权给“日常监测项目 A”，把部分通道和摄像机 C1 授权给“专项观测项目 B”；授权具体可用范围，不因为项目关联了一座桥就自动开放其全部资源。
4. A 应用公共模板，选择需要的监测项，绑定实际测点，配置自己的告警和看板；A 可以不启用视频。
5. B 应用租户私有模板，引用相同的获准通道并启用视频，使用自己的告警和展示。模板复用不复制通道及原始数据，项目告警和业务输出分别保存。
6. B 的视频启用或告警阈值调整不改变 A 的方案；任何项目需要修改公共采样或标定，都由获准的资源维护操作统一处理并说明影响。
7. 发布模型或模板 V2 不自动重写东河桥的档案或 A、B 的方案。项目归档不删除租户设施或停止其他项目的监测；归档项目自身任务如何停止在对应真实模块中另行明确。

在模型、模板及实例功能实现后，人工验收应验证：同模型建立不同数量构件；同模型应用不同监测模板；租户私有模板与公共模板分别版本化；同一实际资源被两个项目引用时方案、权限和告警互不覆盖；未经资源维护授权无法改写公共参数。以上是未来验收建议，当前没有实现或测试结论。

## 16. 本轮建议交付范围：设施模型、指标库与监测模板管理

第 1–15 节包含整体目标与后续场景。本轮交付以本节为准，尤其不将视频、告警执行、具体资源绑定或项目菜单装配计入已交付能力。

### 16.1 本轮配置能力的明确范围

- 工程属性支持文本、整数、小数、布尔、日期、日期时间、单选和多选枚举；支持静态默认值和与类型对应的校验。数值字段可关联单位。文件附件、任意嵌套对象、脚本字段及计算字段不在本轮。
- 指标定义支持单值数值与枚举状态。多方向位移可用含义明确的不同方向指标表达；波形、频谱、视频流、矩阵等不声明为已支持的数据形态。
- 单位目录提供含义、类别和适用性校验；真实采集数据的单位自动换算与存储不在本轮。展示样例不能作为转换算法验证。
- 构件类型先在模型内维护，复制模型时形成独立定义；不引入全局构件继承与自动传播。模板的适用对象明确到模型版本和其中的构件类型。
- 监测模板本轮保存监测内容、指标、目标对象和绑定要求；样例阈值不作为生效工程参数。实际功能选择、图表运行、告警规则执行和菜单生成，随对应真实模块接入。
- 公共模型、指标、单位及模板只能引用公共的已发布定义；租户模板可以引用允许使用的公共定义，不能引用其他租户私有内容。发布校验需要整个依赖链均已发布且允许新使用。
- 提供桥梁、边坡、大坝的示例配置与验收步骤，说明它们是验证配置能力的样例；不自动发布为用户正式工程规范，也不预置自动生效的工程告警限值。

### 16.2 功能扩展在本轮的交付形式

记录功能模块的装配约定：稳定标识、支持的上下文、配置格式、依赖和兼容关系、权限及页面入口。沿用现有 Go 模块和 React feature 的统一构建发布方式，不建设运行时插件系统。

这部分交付是设计约定，后续有真实监测、告警或视频模块时再实现对应注册、启用及菜单链路。本轮不在产品中列出可启用的虚构视频或告警模块，也不靠添加空菜单来宣称完成扩展。监测模板可以先发布其监测定义；该发布只表示定义有效，不表示已经具备数据接入和运行条件。第 5–6 节关于模块存在性、兼容性和启用的检查，在模板实际引用功能模块后执行。

### 16.3 后续交付

1. 租户真实设施、构件、测点和指标通道建档及公共参数维护。
2. 项目资源使用授权、撤权与维护委托；项目实际监测方案及真实资源绑定。
3. 设备接入、原始监测数据、时序存储、实时与历史曲线、告警执行。
4. 视频、巡检、专业分析等真实功能模块，以及功能组合和菜单运行链路。
5. 已有设施/方案跨模型或模板版本升级的数据迁移工具。

系统继续暂不建设额度与用量控制；本轮也不新增计费、许可或商业功能开通机制。

| D-05 | 首期支持的数据形态 | 属性支持第 16.1 节列出的常用字段；指标先支持单值数值和枚举状态。超出范围的波形、矩阵、文件等另行扩展，避免名称可填而数据无法正确处理。 |
| D-06 | 模板复用与调整 | 模型/模板复制形成独立对象，保留来源但不自动同步；模板是实际方案的初始建议，监测项可按工程选择，保留项目需满足其指标和绑定要求；正式工程参数后续由工程方案确定。 |
| D-07 | 版本、停用与删除 | 发布版本及解释所需依赖固定；修改形成新版本。停用可恢复，停用后禁止新采用，既有引用仍可读取预览；仅未被引用的草稿可删除，已发布版本不硬删除。新采用时检查全部依赖，避免通过旧模板绕过依赖停用。 |
| D-08 | 发布是否需要审批 | 查看、编辑、发布分别授权，一个人可兼有多种权限；首轮不强制双人审批，具备发布权限者通过校验即可发布，全程留审计。 |
| D-09 | 公共和私有内容的可见范围 | 已发布且可用的公共定义供有权的有效租户成员选用，不增加逐租户开通；公共草稿由平台有权人员查看。私有模板仅本租户有权成员可见，平台身份不自动获得读取私有模板的权限；历史依赖停用后仅保留必要的引用解析与预览。 |

D-01、D-02 不在本轮重新征求确认。后续资源授权的读/维护粒度、跨租户共享、撤权时任务处理、项目功能启停对采集的影响等不阻塞本轮编制能力，待对应迭代形成具体方案再确认。

## 18. 本轮人工验收建议

| 场景 | 操作和预期结果 |
| --- | --- |
| 不改代码新增类型 | 通过平台页面新增一个未预置的设施类型，配置模型和字段、发布并预览；期间不改源码、不新增类型专用表、不重新构建部署。 |
| 同模型不同实际结构样例 | 在预览中用同一模型建立不同数量的合法构件并填写不同属性；非法父子关系、数量或字段值被明确阻止。预览标明是样例。 |
| 同模型不同监测内容 | 为同一个模型发布两份监测模板，选择不同监测项和指标；预览正确显示差异及各自待绑定对象。 |
| 公共与租户私有模板 | 租户 A 复制公共模板并调整发布，公共原件保持不变；租户 B 不能读取或修改 A 的模板。 |
| 发布版本保持不变 | 发布模型/模板 V1，再编辑草稿发布 V2；V1 的定义、依赖和预览保持不变，租户副本不被自动同步。 |
| 停用和引用 | 停用某个发布版本后无法新选用，也不能借引用它的旧模板建立新采用；已有引用可解释和预览。恢复后按当前授权恢复可选状态。 |
| 权限与状态 | 只有编辑权限者不能发布；被撤权、账号或租户不可用后，界面和直接请求都不能继续相应操作。平台管理身份不越权进入租户私有内容。 |
| 未实现能力 | 无法把不支持的数据形态或不存在的模块作为已实现功能发布/启用；产品不出现可用的视频或实时监测占位入口。 |

这些是待实施后的人工验收步骤。本轮尚未开始功能实现或自验，当前不填写通过结果，不进入 Awaiting acceptance。

## 19. 实施安排与自验计划

沿用第 9 节技术选择，不新增常驻服务。Go 业务模块集中处理定义、引用、校验、发布和范围授权，Gin 负责传输接入；PostgreSQL 保存关系与受校验的 JSONB 定义；React/TypeScript 使用现有 UI 和表单工具实现编制、预览；OpenAPI 作为接口契约源，迁移由现有统一 CLI 执行。

实施按以下顺序拆为小步，每步完成相应检查，但整体状态在全部交付通过前保持 In progress：

1. 定义与校验：类型、模型、构件、属性、指标和单位，验证非法结构、属性和单位关联能被服务端拒绝。
2. 公共模型与模板：页面编制、预览、发布、版本引用、状态和并发草稿冲突。
3. 租户私有模板：复制、新建、隔离、发布、来源与不可自动同步的规则。
4. 全链路收尾：权限与状态回归、审计、增量迁移、契约和前端检查、HTTP 与浏览器关键路径测试，交付操作手册及独立自验记录。

测试重点覆盖定义变化驱动通用页面、服务端与前端规则一致、版本及依赖不可变、跨租户隔离和发布授权；不以模拟预览通过代替真实资源、数据接入或视频扩展验证。全部相关自验通过后才进入 Awaiting acceptance，用户明确完成手工验收后才进入 Accepted。
