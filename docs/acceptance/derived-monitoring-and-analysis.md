## MA-01–MA-06：规则、归属、数值和匹配

**MA-01，从模板建立真实持续通道。** 进入“派生指标”新建草稿，输入 `MANUAL_DIFF` 和名称。设置一个numeric输入，固定单位选择已发布的毫米单位，量值尺度为比率尺度，允许直接来源。套用时间差分模板，保留相邻方式、无效样本中断和最大间隔1800秒。填写原因，创建／保存草稿，校验并发布固定版本。在“派生通道”新建，归属选择位移验收测点，选中刚发布版本并绑定位移A。创建后在“试算固定配置”填00:00至00:31，对完整范围试算；应得到无前驱、4、6。预览启用区间00:00至次日00:00并确认，等待正式代次出现。返回运行记录再打开原任务，状态和固定目标应保留。

## MA-18–MA-20：故障、并发及独立恢复

这三项在隔离环境由维护者配合执行，保留命令、源码hash、故障点、原预期和实际结果。不要停止既有业务容器或修改生产库来模拟故障。

**MA-18，worker及存储故障。** 对一个真实后台任务，在块封存后、PG正式发布前中断worker，重新启动同一版本；观察接管、检查点复用和原子发布。重复投递同一变化事件，不得出现重复当前结果。分别模拟CH副本不可用、S3不可用及PG发布失败；查询不能看到半份正式成果。恢复存储后技术重试仍使用原固定目标。执行入口 `pnpm test:derived:contract --keep` 的隔离物理故障组，实际用例和证据以实施记录为准。

**MA-19，重算中的追加及再次更正。** 开始历史回算，同时正式发布晚于目标范围的新输入，原历史任务应继续推进。再次撤销或改变目标相关配置时，旧任务不得覆盖新结果，新的dirty必须保留。检查消费者位置、任务fence、当前根和来源，最终当前值与最后合法目标一致。本轮核对这些功能行为；混合负载、资源上界和26小时观察按用户决定暂缓，短测不作为其通过证据。

**MA-20，独立备份实际恢复。** 在独立测试目标运行 `pnpm test:monitoring:restore`。确认备份目录、hash和构建版本，与源不同的PG／CH／S3目标，以及实际恢复而非只读备份文件检查。恢复后验证原始采用、固定配置、当前和历史根、分析成果、权限与旧规则回放，原数值满足同版本契约。恢复检查通过后才开放目标写入；保留恢复报告。旧v12升级和旧二进制就绪拒绝另有隔离升级记录，不能用空库迁移代替。
