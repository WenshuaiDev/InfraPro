## 逐项验证

每个配对 HTTP 沙箱从同一冻结快照建库。`snapshot.json` 记录 PG 归档摘要、列存初始行数、对象数和当次安装的角色授权文件摘要。关闭回放后，`storage-archive.json` 保存 ClickHouse 表清单和逐表重新挂载语句，便于复核原始行。人工走查样本使用各自持续保留的数据库。

配对 HTTP 工作流保存每次请求的操作、响应码、两侧响应原始字节摘要和字段差异。新记录用 `mappingReasons` 写明生成值的逐字段配对原因。双向登记的对象 ID 可用于后续请求，分页游标须指向同一快照与边界行，并在各侧实际翻页。CSV 下载先核对各自清单里的长度和 SHA-256，再逐字节比较替换已登记标识后的内容。[工作流比较实现](../../scripts/architecture-workflow-http.mjs)

解析结果中的 service_build_digest 标识实际执行该请求的解析服务。自动和人工解析回放分别校验原始响应中的该字段与该侧封存的 parser 二进制 SHA-256。两侧继续逐项比较方法版本、输入摘要、原文字节、结果和数值精度。[解析回放及构建摘要核对](../../scripts/architecture-ingestion-http.mjs)
