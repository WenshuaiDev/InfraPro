# 角色与权限实现验证

日期：2026-11-09。状态：**Awaiting acceptance（实现与自验完成，待用户人工验收）**。用户已确认[完整方案](../requirements/role-permission-plan.md)；实现覆盖 RP-1–RP-4。以下是开发自验证据，**不代表用户人工验收已通过**。

## 实现交付

- `packages/go/platform/access`：22 项集中权限、精确操作策略、两种内置角色、目录同步与一致性校验、权限并集/来源、事务内授权、角色管理、账号角色管理、最后管理账号与授权范围保护、审计。
- `00002_access.sql`：目录投影、角色/权限/账号绑定关系、授权状态锁及修订号、账号管理版本和结构化审计；无账号直接权限表、管理员账号标志或存量回填。
- identity：首次开户原子绑定管理员角色、邀请原子绑定基础成员；本人功能按操作检查权限，仍保留归属隔离、密码复验、凭据撤销和 Redis 故障处理。密码哈希/验证在授权锁外完成，事务内复查凭据版本。
- HTTP：所有注册路由都有中央精确策略；新增角色、账号授权、权限目录和审计接口。管理写请求严格拒绝未知字段，使用字符串版本、变更原因及最近密码复验。
- CLI：`access sync`、`access check`、`access recover-admin`；Compose 增加迁移后的目录同步任务，API 启动只验证，不修改授权数据。
- console：账号、角色、权限目录、审计页面；分组权限选择、筛选全选/部分选中、变更预览、影响人数、原因、冲突提示和只读内置角色；菜单、路由、按钮按生成的权限常量展示。
- 身份状态：内存权限上下文、30 秒可见页刷新、焦点/可见性/响应修订刷新、401/不同 403 分流；权限减少时销毁敏感状态，丢弃旧身份/授权代次响应，保留无关修订下的草稿。密码复验不自动重放写入。
- `permissions:generate/check`、OpenAPI、运行手册及测试；权限常量和枚举从 Go 目录生成，并纳入 `pnpm check`。
