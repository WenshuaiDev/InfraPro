## 固定环境和目标

本机 arm64、14 CPU、36 GiB 内存；Docker VM 14 CPU、8,318,910,464 字节内存。API/worker 为宿主 Go 1.27 程序；单个负载进程 `GOMAXPROCS=2`、`GOMEMLIMIT=1GiB`，同一时刻一个历史计算任务。真实隔离 PostgreSQL 17、双副本 ClickHouse 26.8.36.3、SeaweedFS 4.53 沿用 `deploy/monitoring-contract/versions.json` 镜像 digest。每 CH 容器 2 GiB、server 1.5 GiB、查询 512 MiB、2 threads；共享 Docker VM 的其他既有服务保留，实际并行资源占用附运行清单。

对象存储和数据库均在本机 Docker 网络／loopback；持久工作目录在本机 APFS，未限制网络带宽，不能称为远程生产硬件或冷存储。每项创建新 schema、CH database 与租户对象前缀；底层文件系统缓存不清空，记录为新业务数据、共享底层热缓存。每个算子独立建档并通过正式 CSV 上传、校验、发布进入原始存储。

- 接续至少24小时持续观察，每分钟新增并正式发布1个实际时间点，读取循环保持运行；每小时提交相同的历史任务组合。采用稀疏时间点验证速率按实际时间差和滚动窗口空缺边界。

- 查询中返回的每一行核对独立有理数期望和唯一性；结束时完整导出所有当前输出，核对每一时间点、十通道数量、值／null／状态且无重复身份。分钟记录阶段、真实时间、输入点数、请求数、积压和内存／磁盘。
