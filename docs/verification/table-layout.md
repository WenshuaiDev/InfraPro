# 控制台表格列宽优化

日期：2026-11-10。状态：**Awaiting acceptance**。自验已完成，等待用户对视觉效果人工验收。

## 需求与交付

用户指出角色列过宽，并要求同时优化其他存在相同问题的表格。本次收窄角色主列，按内容长度分配其他列，统一单元格间距、数值与操作列对齐，处理长名称及备注。保留原有查询、授权、分页和操作流程。

| 范围 | 调整 |
| --- | --- |
| 平台角色、预置租户／项目角色、租户工作台角色 | 桌面按比例分配列宽，操作菜单保留 56px；角色主列约占 37%～42%。隐藏列后重新计算比例；名称和说明省略，完整内容可在详情查看 |
| 账号列表 | 账号、状态、绑定角色使用独立比例；长名称和角色标签可以换行 |
| 平台租户列表 | 租户状态、租户、当前管理员、管理员可用性分别设置宽度 |
| 租户成员、成员邀请 | 成员／受邀账号、角色、状态、时间和操作分开分配宽度；按钮靠右，空间不足时换行 |
| 账号开户邀请 | 备注、状态、时间和操作列按内容分配，长备注换行 |
| 平台审计 | 操作、操作者／目标、原因和差异使用稳定比例，长标识和展开内容不撑宽其他列 |
| 登录会话、近期安全记录 | 浏览器信息和时间使用合理比例，避免长 user agent 决定整表宽度 |

采用现有 React／TypeScript、TanStack Table、shadcn/ui 与 Tailwind CSS。共享 `DataTable` 将显式 `ColumnDef.size` 用作列宽比例，并保留最小可读宽度；没有声明列宽的调用保持自动布局。密集表格在自身容器内横向滚动，既有手机卡片保留。角色表在小于 1024px 时使用紧凑行，将来源、权限数和绑定人数合并显示在角色说明下方。

不涉及 API、Go 授权、数据库结构或迁移。项目工作台使用的卡片列表没有同类表格列宽问题，本次未调整。

## 人工验收

本机服务运行时刷新[角色管理](http://127.0.0.1:5173/access/roles)。若服务已停止，在仓库根目录运行 `make dev`，不需要重新初始化或迁移数据库。

1. 切换平台角色、预置租户角色、预置项目角色，再进入租户角色：主列明显收窄，来源、状态、数量分布均衡；数字与列标题右对齐，行末菜单位置一致。
2. 打开“显示列”隐藏或恢复来源／权限数；搜索无匹配名称：剩余列重新分配，空结果保持表头和布局稳定。打开、关闭角色详情，列表条件和页码保留。
3. 查看账号、租户、成员、邀请、审计及账号安全列表：长文字在所属列内换行或省略，不挤压其他列；原有链接、菜单及操作可用。
4. 缩窄窗口到手机宽度：角色表显示紧凑信息，既有租户卡片仍正常；密集表格只在自身容器内滚动，页面本身不横向滚动。
