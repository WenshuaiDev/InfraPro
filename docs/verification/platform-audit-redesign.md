# 平台审计重设计验证

日期：2026-11-10。状态：**Awaiting acceptance**。实现与自验完成，尚未获得用户人工验收。范围见[方案](../requirements/platform-audit-redesign.md)。

## 交付内容

- 列表重新组织为发生时间、操作与变化摘要、操作者、影响对象、真实结果；原因是可选列。中文名称及业务摘要替代主表中的 UUID、校验和、英文事件码和 JSON。
- 全部记录／管理变更／登录与安全／系统维护分类；名称、用户名、原因搜索；操作、结果、时间与高级精确 ID 筛选。分页支持 10／20／50 条，改变查询回到第一页。
- 复用角色页的 shadcn/ui 控件、TanStack Table／Query、Base UI Drawer。将筛选和分页提取为 `ListFilter`／`ListPagination`，游标状态复用 `useCursorList`。详情采用右侧／底部响应式抽屉，含操作详情、技术信息两个标签。
- 权限及角色变化展示新增／移除的名称，可切换完整前后内容；资料变化逐字段对照。安全事件说明结果；系统同步解释用途及记录中的数量。ID、来源、请求编号和原始内容按需查看。
- Go 审计查询增加只读展示投影：真实 outcome、操作者和对象名称、历史／当前名称来源、租户名称，以及事件所引用的权限／角色名称。不修改事件原文，不要求审计者额外拥有账号／角色目录读取权限。
- 保留租户可见性及项目隔离。失败登录不把目标账号当作已认证操作者。排序与游标统一使用时间及数值 ID，支持时间相同、编号跨位数的跨页读取；兼容旧数字游标。
- 修复共享角色表格在重渲染时替换按钮导致焦点丢失的问题：角色与审计表格均使用稳定的单元格组件，保留 Drawer 关闭后的触发元素。

过程中的问题与修正：

1. 首次新增 Go 排序测试的夹具对同一 SQL 参数混用了隐式 UUID／text 类型，修正为明确转换后通过。
2. 首轮 23 项浏览器回归中，平台角色抽屉关闭的焦点断言偶发失败（22 项通过）。原表格的内联列渲染函数会在后台刷新时重新挂载按钮；改为稳定单元格后，完整 23 项回归通过。
3. Go 扩展回归发现搜索整段原始 JSON 会把后续事件快照中的旧原因误匹配为本次原因。搜索收窄为显示名称、用户名、事件编码和本次原因，保留完整原文仅供技术信息查看。`TestTenantLifecycleIsolationPreservationAndPrivacy` 及全部生命周期相关用例修正后通过；未将首次失败记为首次全通过，也未重复运行其余已通过的长耗时租户用例。
4. 对照分页 SQL 时发现输出中的文本 ID 可能影响同时间事件的排序；改为显式引用数值 ID，并增加跨位数完整遍历断言，全部通过。

## 启动与人工验收

现有本机服务已更新，直接访问 [平台审计](http://127.0.0.1:5173/access/audit)。服务停止时执行 `make dev`，使用原账号登录；不重复 bootstrap，不需要迁移或权限目录同步。

1. 选择“管理变更”，查看 `ceshi` 角色的“配置角色权限”：主表显示操作者 hijacker、影响对象 ceshi、成功及新增 22 项权限；点击后能看到中文权限名称、原因及发生时间。
2. 切到“登录与安全”与“系统维护”：登录、密码确认、权限目录发布使用不同的业务说明；结果以实际记录为准。
3. 搜索名称／用户名／原因，改变操作、结果、时间条件或每页数量：筛选正确并回到第一页。输入开始时间晚于结束时间，出现明确错误且不提交查询。
4. 翻页后打开／关闭详情：原页码和筛选保留，键盘焦点回到原按钮。“技术信息”可以核对 ID 和原始内容，主表没有这些内部字段。
5. 在手机宽度与明暗主题下查看列表和详情：没有整页横向溢出，抽屉内可滚动，关闭和操作按钮可达。

## 边界与未验证项

- 等待用户对信息含义、实际数据与视觉效果的人工验收；未测试真实手机软键盘、Safari 或读屏软件。
- 历史记录缺少名称／字段快照时只能使用明确标注的当前名称或说明无法还原；权限名称无历史目录快照时由当前目录解释。
- 本轮只重设计平台审计；租户与项目审计页面、审计记录写入范围、导出及总数统计不在本轮范围。
- 未提交、推送或部署生产；没有新增数据库迁移，也没有重写旧审计记录。现有工作区包含此前多轮未提交改动。
