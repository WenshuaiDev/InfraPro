# 平台与租户权限说明整合

日期：2026-11-10。状态：**Awaiting acceptance（实现与自验完成，待用户人工验收）**。用户已要求按本次方案实施，人工验收尚未进行。

## 范围与实现

- 平台、租户侧栏和页面搜索移除独立权限目录入口，保留既有侧栏分组与间距。
- 旧 `/access/permissions` 跳转到 `/access/roles`；旧 `/t/<tenant_id>/permissions` 跳转到同一租户的角色页。目标页继续执行原有访问控制。
- 角色详情及权限配置就地显示中文用途、作用范围和风险；配置表单提供“权限说明”。权限编码默认隐藏，可按需显示，仍可用编码搜索。
- 租户管理员保留能力可展开查看说明，不提供选择框；租户角色编辑器补齐已有项目治理权限分组，平台角色编辑器仅展示本人及平台范围的选项。
- React／TypeScript 复用权限说明组件，TanStack Router 处理旧链接，现有 shadcn 与 Tailwind 组件负责显示和交互。沿用 TanStack Query、API client 和现有目录接口读取权限信息。
- 没有修改 Go 权限定义、查询接口、授权策略、角色绑定、数据库或迁移。本轮限定于平台和租户，项目工作空间的独立目录入口继续保留。

## 启动和人工验收

仓库根目录运行 `make dev`，访问 <http://127.0.0.1:5173/access/roles>。已有服务运行时直接刷新；已有环境无需重新初始化。

1. 打开平台及租户工作空间：侧栏和“搜索页面”均不再出现对应权限目录；其他分组及入口正常。
2. 在平台角色管理选择一个自定义角色：可直接查看每项权限的用途、范围及风险，展开“权限说明”可查看配置规则；编码默认隐藏，勾选“显示权限编码”后出现。
3. 在租户角色页创建或配置角色：资料、项目、成员、邀请、审计权限按组展示；按名称、说明或编码搜索不清空已选项。管理员保留能力可展开阅读，不能勾选。
4. 按既有流程保存平台角色权限；租户角色变更先预览影响再保存。变更原因、影响提示和授权生效行为保持。
5. 打开平台、租户的旧权限目录链接：跳到对应角色页，租户不串换；无权用户仍无法读取角色或权限数据。
6. 用桌面及 375px 窄屏查看角色详情和配置表单：说明、编码及保留能力可阅读，无整页横向溢出，可用键盘操作。
