# 全局页面返回工作台修复

状态：**Awaiting acceptance（等待用户验收）**。2026-11-15 完成实现与自检；用户尚未确认验收。

## 问题与修复范围

任务中心、通知中心及其设置／邀请页面、账号首页、个人资料和账号安全使用全局布局。原布局没有返回工作台入口，也没有记录进入这些页面前的完整地址，用户只能重新选择工作空间。

现在这些页面的内容区顶部提供“返回工作台”，旁边显示来源工作空间和页面名称。平台管理、租户和项目工作台均支持；连续在全局页面之间跳转不会覆盖来源。返回保留原地址的路径、查询参数和锚点，包括地址中记录的监测点／通道选择。

没有可用历史来源时，提供“选择工作空间”，复用现有工作空间选择流程；没有工作空间授权时不显示这个入口。

## 实现

- `apps/console/src/app/workspace-return.tsx`：React / TypeScript 记录最近的工作台地址；状态由公共 shell 持有，避免侧栏布局和全局布局切换导致丢失。`sessionStorage` 按账号保存，刷新后恢复，各标签页后续访问独立。
- `apps/console/src/app/workspace-shell.tsx`：统一记录来源、显示返回导航，覆盖工具栏、通知浮层、账号菜单、页面搜索和直接访问的入口。
- TanStack Router 按原路径、查询参数和锚点执行站内跳转，保留正常浏览器前进／后退行为。只接收已知工作台路由，拒绝外部地址、登录页、全局页及未知路径；返回仍执行现有权限校验。
- 复用现有 Button、Lucide 图标和主题颜色。按钮点击区域至少 44px，支持键盘；窄屏缩略来源名称，完整名称保留在可访问名称中。
- `tests/helpers/workspaces.ts` 增加可选参数，使本次测试可以创建不带额外平台邀请角色的工作空间账号，默认行为不变。

## 手工验收

沿用当前验收服务和账号，无需重启 API 或迁移数据库。刷新 <http://localhost:25173> 后：

1. 在平台管理工作台进入“账号管理”，点击顶部“任务”。应看到“返回工作台”和“平台管理工作台 · 账号管理”；点击后回到账号管理。
2. 在租户或项目工作台进入“监测浏览”，选定一个监测通道，再打开任务中心或通知中心。点击“返回工作台”，应回到原租户／项目的监测浏览，地址中的监测点和通道选择保留。
3. 从工作台进入个人资料，继续切换账号安全、账号首页、通知接收设置或任务中心。返回入口应始终指向离开前的工作台页面。
4. 在上述全局页面刷新，再点击返回。应仍能直接返回原页面。
5. 在手机宽度或 200% 缩放下操作返回入口；用 Tab 聚焦后按 Enter。按钮应可见、可操作，页面没有新增横向溢出。
6. 在没有历史来源的新标签页直接访问个人资料／任务中心。应提供工作空间选择入口，不跳到其他账号的历史位置。

## 边界

- 修复生效前未记录的历史来源无法恢复；首次进入工作台后会自动记录。
- 浏览器禁用会话存储时，当前页面访问期间仍能返回，但整页刷新后无法恢复历史来源。
- 本次保留完整页面地址；不新增未保存表单、未写入地址的临时筛选或弹窗状态的持久化机制。
- 本次是前端导航修复，已在现有本地服务验证；没有执行生产部署或全库业务回归，用户手工验收仍待完成。
