## 2. 实现与技术边界

- Go/Gin：`platform/resources` 及 HTTP handler 承担实际对象事务和严格输入校验；从 `engineering` 读取固定公共版本与依赖。定义影响只收到引用是否存在，不得到租户资源详情。
- PostgreSQL/pgx/Goose：迁移 9 分别建立四类对象、变更历史和收据。组合外键、保留编号、状态/形态约束及触发器保护结构、固定语义和历史；所有资源写入在设施行锁下完成。
- React/TypeScript/TanStack Query、React Hook Form、Zod、shadcn：租户设施列表、分页构件树、对象面板、位置表单及历史；按账号/租户/成员关系隔离，复用 `engineering-fields` 控件，不扩展工程样例为真实实例。
- OpenAPI 与 TS client：30 个资源操作、90 项权限目录；生成文件与源一致。读已有资源不要求通用目录权限，新采用类型/指标要求目录权。

没有新增监测方案、实例发布流程、完成度、项目地图、路线目录、模板应用、图纸/模型绑定、设备采集或运行演示。

## 5. 本机升级、备份及运行

实际升级前停止旧 API 和 console，备份数据库、配置及旧应用，先将 v8 备份恢复到新隔离数据库并执行 v9。比较 32 张原有业务表（不含迁移日志）保持不变；核对后才迁移当前本机数据库。`after-migrate.json` 记录资源六表均空、版本 9、权限仍 88。

随后执行 `access sync --dry-run` → `access sync` → `access check`。权限目录变为 90 项，27 张不应受权限同步影响的原表逐表保持不变；允许变化仅为权限目录/内置角色投影、授权版本、同步审计及迁移日志。再次预检 `changed=false`。没有重复 bootstrap、重置密码、删除账号或重新生成既有业务关系。

当前常规开发入口为 `http://127.0.0.1:5173/`，API `/healthz` 与 `/readyz` 返回正常；资源深链接由 SPA 正常接收。人工验收另使用 `http://127.0.0.1:15173/` 隔离运行环境，账号及资源入口见操作手册。
