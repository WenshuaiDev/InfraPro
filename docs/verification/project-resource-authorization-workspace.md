## 完成范围

- 项目列表显示真实已授权设施数量、新建设施权限和项目状态，支持搜索、状态筛选及分页。
- 项目详情统一为“已授权设施 / 新建设施权限 / 授权记录”。设施清单显示实际构件、测点、通道数量及维护权限摘要；统计不受当前分页影响。
- 添加设施采用选择面板，再进入资源树。设施、构件、测点和通道独立勾选，点资源名称设置操作权限；下级按需读取，搜索覆盖设施内对应类型的资源。
- 新选择默认仅查看；批量选择保留已有维护权限，只选择当时存在的资源。待保存摘要、还原修改、离页提示、重新载入及窄屏权限抽屉均可用。
- 授权写入继续使用真实预览、必填原因、修订校验、预览哈希、幂等请求和回执；冲突保留输入。预览与历史记录以业务语言展示前后权限，移出设施明确保留租户资源和其他项目授权。
- 新建设施权限明确说明与“在已有设施内新增测点/通道”的区别。归档项目只能缩减权限，来源维护仍受独立权限限制。
- 原型 A/B/C 已归档在本地 `.artifacts/resource-access-prototype/archive/design-abc-20261112.tar.gz`；正式路由不再包含原型切换和演示数据。

## 本地运行与人工验收

现有服务已更新并启动，刷新即可访问：

[青澜项目资源授权](http://localhost:25173/t/a78cdb12-b224-4869-9cb7-c7c1f76d0c8b/resource-access/2381620c-bd82-43aa-9ba3-09891aedb746)

服务沿用本机 `~/.local/share/infrapro/manual-acceptance/scripts/start.mjs` 和原有配置/数据。本轮更新了本地 API 与 CLI；启动检查发现当前 checkout 的权限目录校验和已变化，先执行 `access sync --dry-run`，确认权限、角色、租户及项目差异均为空后同步目录并通过 `access check`。没有数据库迁移，也未修改原验收项目的授权、账号或登录凭证。后续重启可使用该启动脚本；普通开发环境仍遵循仓库 README 的启动方式。

1. 查看已授权设施：每座设施显示开放的资源数量；“管理资源与权限”直接进入其资源树。
2. 打开资源树、展开构件与测点：子项独立勾选；点资源名称后可设置编辑或新增下级权限。窄屏在抽屉中完成。
3. 在可修改的测试项目中调整一项权限：底部出现待保存变化；预览抽屉要求原因并展示前后差异，保存后数量和授权记录更新。
4. 查看“新建设施权限”：能清楚区分新建设施与已有设施内新增测点；关闭新建权限不收回已有资源授权。
5. 检查归档项目：不允许添加设施、扩大资源或开启新建设施权限；仍可查看和缩减已有授权。
