# 通知界面 A + C 改造与验收

日期：2026-11-15。状态：**Awaiting acceptance（实施与自验完成，待用户验收）**。用户已选定 A 轻量浮层 + C 完整收件箱，并授权实施和自验；人工验收尚未进行。

## 已确认方案

- A：顶部铃铛打开靠右、无背景遮罩的浮层。支持全部／未读、全部／当前工作空间、当前筛选全部已读、原位详情和进入通知中心。
- C：桌面分类导航、通知列表、详情三栏；窄屏改为列表／详情切换。选择、返回、刷新、直接打开详情链接均保留来源、分类、阅读状态与分页条件。
- 列表／详情路由切换保留列表滚动位置和本页查找；这些临时状态只存于当前账号与权限版本的内存，限制最多 20 个筛选视图，账号或权限变化即清空。
- 信息层次：优先显示接口允许披露的业务对象；分类、正文、来源、发生／收到时间、事件结果、当前业务状态仍可查看。对象缺失或受限时使用服务端安全标题，不拼造项目名、文件大小、下载能力或任务结果。
- 沿用 React、TypeScript、TanStack Router/Query、项目主题和组件；浮层使用已安装的 Base UI Popover 管理定位、键盘与焦点，没有新增依赖。前端继续调用原通知 API，不修改数据库、worker、投递、权限或业务操作。
- “查找本页通知”仅匹配当前已加载的可见通知，明确显示本页范围；查找时禁用全部已读，避免用局部查找影响未展示的通知。历史继续通过服务端分类、来源和游标分页浏览。

原型位于本次聊天独立目录，未将演示数据、原型切换条或模拟业务入口引入系统。用户选定的 A + C 是本次实现依据，B 不进入正式界面。

## 保留的业务规则

1. 一个账号一个通知箱，跨工作空间共用未读数；列表与详情仍采用服务端当前资格披露。
2. 打开浮层、加载列表和切换筛选不会标记已读；详情加载成功才对该条执行原状态更新。
3. 恢复未读会取消归档；归档同时已读；取消归档保持已读。阅读、归档不接受邀请、不重试任务、不确认工程事件。
4. 全部已读继续发送当前服务端筛选和已接收序号水位，不把游标当作批量操作边界；新入箱通知保持未读。
5. 业务入口继续由原目标解析接口重新鉴权，保留执行代次和安全路由白名单。切换详情后取消旧目标请求，防止迟到解析结果带走当前页面。
6. 过期、已失效、撤权与脱敏通知继续使用原提示和能力判断；安全／资格／邀请必收规则与接收设置保持不变。
7. 仍使用原轮询间隔、焦点／网络恢复刷新、隐藏暂停、账号与权限缓存隔离。迟到状态响应仅更新原查询且不重建已清理的权限缓存。
8. 任务操作记录保留在详情的可展开区域，按用户展开再加载。

## 人工验收步骤

继续使用现有本地环境：<http://localhost:25173/notifications>。前端是当前工作区 Vite 服务，刷新页面即可使用更新；账号沿用已有验收账号。

| 步骤 | 预期 |
| --- | --- |
| 在原业务页点击铃铛，再关闭／重新打开 | 右上浮层显示，不出现遮住工作区的灰色遮罩，未读数不因打开列表减少。 |
| 切换未读、当前工作空间，点击一条通知 | 仅列表范围变化；该条详情加载成功后才变为已读。 |
| 在浮层点击“在通知中心查看” | 进入三栏通知中心，保留当前来源和阅读筛选；当前详情清楚显示。 |
| 在分类与来源中筛选，选择另一条、刷新、返回列表 | 详情与高亮一致，URL 保留筛选条件，不串用上一条正文或状态。 |
| 滚动到列表下方，进入详情后再返回 | 列表位置保持；本页查找条件也在详情／列表切换时保留。 |
| 在“查找本页通知”输入关键词 | 只匹配本页并显示匹配数，全部已读按钮暂时不可用；清空后恢复。 |
| 归档、查看已归档、取消归档，再恢复未读 | 归档项从默认列表收起；取消归档保持已读；恢复未读取消归档。 |
| 按分类或来源执行全部已读 | 只改变该服务端筛选范围内已收到的通知，其他范围和之后到达的消息不受影响。 |
| 查看过期、撤权回执、邀请或任务通知 | 显示当前状态与可用入口；读取通知不会自动接受邀请或执行任务操作。 |
| 用键盘打开浮层、按 Escape；缩小到手机宽度 | Escape 关闭并返回铃铛焦点；手机可从列表进入详情并返回，无横向溢出。 |
