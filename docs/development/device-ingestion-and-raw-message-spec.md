### 0.2 统一协议管理的落地方式

平台界面统一称“协议与解析方法”。保留 method_id／method_version 作为测量解析的唯一身份，新增平台管理的“接入协议及版本”描述接收和身份识别能力。两者均通过代码、清单和发布包提供；平台配置选择与启用，租户没有协议定义、脚本、字段偏移或代码上传能力。

接入协议版本是有限清单，引用确定的传输适配器、识别方法、输入视图和兼容声明；不提供任意步骤编排和服务 URL。厂家用于分类及适用性说明，同一方法可被多个厂家／产品使用，不建立厂家与协议一对一约束。

| --- | --- | --- |

### 0.3 兼容原则

增量迁移保留厂家、产品、设备、方法 ID、配置修订、采用和样本运行。旧设备不自动登记终端、不自动开启接入、不按序列号猜来源。现有 contract_version=1 的 Manifest 严格校验且摘要不可变，通过独立接入能力目录承载新增元数据，不能给旧 Manifest 补字段后沿用版本。具体对接、迁移及验收见第 7、12、14 节。

## 1. 已确认场景与交付范围

### 1.1 网络与业务事实

1. InfraPro 位于内网，没有固定公网入口；厂家平台和现场网关统一向云端报送。
2. 内网管理员已批准访问特定云 IP／端口；内网主动发起拉取、确认和配置下发，云端不依赖内网固定地址。
3. 当前没有云转发程序，本轮新建并交付其持久缓冲、确认、重投、连接管理和部署材料。
4. 一个项目通常有多个厂家，厂家产品可共用协议；平台为“租户＋项目＋厂家＋兼容接入协议组”建立入口，首期以独立监听端口实现。
5. 云端持有有限入口配置：租户、项目、厂家、入口协议版本。云端不持有完整设备／产品台账、不连接内网业务数据库、不解释测量值。
6. 原始设备报文可以没有租户、项目、产品和方法字段；接收端口决定入口，终端／子设备登记关系决定设备与产品，设备采用决定测量方法。
7. 设备仍属于租户，项目沿用 project_device_grants 使用设备；一台设备可服务多个项目。每条上报的来源项目不改写设备所有权、不自动建立通道绑定，也不扩大其他项目权限。

入口启用必须验证上游确实按项目／厂家／约定格式分流。首批不接受一个业务入口混合多个租户／项目；不能分流的厂家来源列为尚未支持，后续另设计来源类型，不自动回退。端口用于路由，来源凭证还须限制到获准入口。

实际 IP、内网访问端口、外部监听端口、证书和路径由部署配置提供，不预设已放行 443。新增公网业务入口不意味着新增内网防火墙端口。

### 1.2 本轮闭环

平台发布协议及入口 → 租户确认并登记终端／设备 → 上游按端口报送 → 云端保存和包装 → 内网保存、确认 → 入口协议识别 → 项目／厂家／设备核验 → 固定设备采用 → 解析、映射及证据 → 查询、异常补处理。

| 本轮交付 | 后续范围 |
| --- | --- |
| 现有协议目录和绑定兼容改造、云转发及内网接入进程 | 多机容灾、跨地域与大规模分片 |
| 端口、入口发布／确认、终端与子设备登记 | 不能按项目分流的混合业务入口、未取得资料的真实厂家 API |
| 原始报文、自动识别、固定版本解析、证据和隔离 | 标准监测观测正式采用、完整质量治理和业务告警 |
| DDP TCP、同项目厂家 HTTP 批次、两类模拟端、跨项目误投负例 | 真实硬件／固件认证、DDP UDP、新适配器 |
| 权限、审计、任务、诊断、断网恢复及版本回归 | 远程控制、固件升级、租户自定义协议 |

必须经过真实网络、PG／S3 和解析服务。模拟来源标记 synthetic；模拟贯通不等于实机兼容。

云端处理通信所需的注册、空闲检测及确认；解析服务解释完整输入。DDP 纯结构代码和夹具复用，抽取代码不能改变已发布执行产物。

### 2.1 网络和认证通道

内网经获准地址主动长轮询、确认、发布配置和查询状态；公网多业务监听端口与统一消费者／控制端口分开。机器接口按报送、消费、配置用途分权，浏览器不直接连接云服务。

消费者和首批厂家／DDP 模拟端使用双向 TLS；报送凭证绑定一个或明确列举的入口，相同厂家跨项目不得仅凭厂家身份访问全部入口。TLS 包裹保持 DDP 原字节。证书轮换不改变逻辑入口和终端，始终验证服务身份及证书链。

未来不支持 TLS 的设备需经获准安全网关／网络接入；隔离明文实验单列，不能宣称已完成公网认证。DDP 编号、源 IP 和端口不单独充当密码。

## 3. 入口识别、设备匹配与最终解析版本

### 3.1 无需预先知道产品的处理顺序

| 顺序 | 确定依据 | 产出 |
| --- | --- | --- |
| 1. 入口路由 | 云节点＋传输方式＋监听地址／端口 → 平台有效入口修订 | 租户、来源项目、厂家、入口协议版本 |
| 2. 身份识别 | 原文＋入口固定识别方法 | 终端编号、消息类别、子单元及定位，不返回获准业务 ID |
| 3. 登记查找 | source_namespace_id＋terminal_key，再按 terminal_id＋child_key 查关联 | 平台设备 ID；单路可无 child_key |
| 4. 业务核验 | 入口与登记、设备产品、project_device_grants 比对 | 明确设备可经该项目／厂家入口上报 |
| 5. 冻结采用 | 设备实际采用＋精确兼容声明＋输入视图 | 测量方法版本、产物、配置、映射和授权快照 |
| 6. 字段解析 | 固定输入调用 /v1/parse | 解析结果和过程，不自动正式采用 |

例：E1 属于租户甲／项目甲／厂家 A，DDP 识别得到 00000000001。在 E1 命名空间找到 T1 和 D1，D1 已有产品与采用版本，无需从报文猜产品。DTU 本体、下挂设备和测量通道分别登记，不能将 DTU 产品当作所有传感器产品。

### 3.2 入口身份、命名空间与项目范围

每个入口有永久 ingress_id；source_namespace_id 为外部编号命名空间，首期与入口一对一、同生命周期。端口与入口身份解耦；旧入口停用、连接排空后，端口可分给新入口，历史仍指向原入口修订。

一个入口只属于一个租户、项目、厂家；归属和编号规范启用后不可修改，变化需新建入口／命名空间。终端键为 (source_namespace_id, terminal_key)，子设备键为 (terminal_id, child_key)。保留原始表示及前导零，不用名称、源 IP、到达顺序或全局编号猜归属。

一个入口可接多个终端，终端可挂同租户多台设备；设备可通过多条获准入口报送，每份单元只匹配一台设备。目标设备必须属于入口租户，并具有来源项目有效的 device 类 project_device_grants；入口厂家须与设备产品引用的厂家 ID／作用范围一致。名称相同的公共／私有厂家不自动等同。

来源项目、租户所有权和项目成员可见范围分别校验。来源项目不自动创建授权或规定未来观测只能服务该项目。项目停用或设备授权撤销后，相关生产领取／结果提交受阻，原文安全保管。

### 3.3 包装协议与设备特化

包装的 ingress_protocol_id／ingress_protocol_version 决定身份识别，不能覆盖所有设备的最终测量方法。计划另存 effective_method_id／effective_method_version 及 adoption_id。

同入口 D1 固定 V1、D2 显式采用 V2：识别方式兼容时分别执行。产品默认变化、入口识别升级、服务更新均不升级 D1。

兼容性由平台发布的精确声明确定：入口协议版本＋可选解复用版本＋输入视图／解释传输类型＋测量方法版本及摘要。不能仅校验“都叫 DDP”或比较版本号；缺失声明返回 ingress_method_incompatible。设备采用／升级必须在预览和提交时检查所有有效入口，不兼容返回 409 和有权查看的关联摘要。可明确停用冲突关联后再采用；重启关联重新校验。

载荷字段、换算和版本特化可在识别后生效；若外层分帧／身份位置改变，需对应新入口和登记。识别与字段解析是平台代码能力，不向租户提供规则编辑器。

### 3.4 未知身份与错误分流

支持 extracted_terminal；fixed_terminal 仅用于独占且认证的来源。无标识共享入口不能启用固定终端。缺失／歧义、未知终端和子地址分别进入本入口待处理队列，不自动创建设备或改产品。

跨项目／租户／厂家混报不是成功用例。校验失败的单元隔离为 routing_scope_mismatch，不搜索其他租户台账、不自动改路由。外层不可信则整包隔离；外层可信、单元独立可验证时，合法单元继续，未知／冲突单元不公开原文。

### 4.1 配置对象

| 对象 | 核心内容 | 管理者 |

| 入口及修订 | ingress_id、命名空间、租户／项目／厂家、监听端点、凭证引用、协议版本及发布代次 | 平台编制，指定租户确认后激活 |
| 终端及修订 | 入口内编号、可选本体设备、单／多设备模式、解复用版本 | 所属租户 |

| 产品／设备采用 | 复用既有配置、默认及 adoption | 既有公共／私有产品及设备权限 |
| 接入执行授权 | 入口／终端范围、识别／字段解析开关、预算及历史 | 获准租户成员，以持久机器授权执行 |

云端取得有限路由 ID，不取得产品／设备／输出映射、业务库凭证或私有业务名称。凭证为安全引用。平台分配并发布入口，租户确认后登记本入口的终端；不再逐台跨租户分配未知 DTU。

登记须有报送约定及理由，不自动开放过去积压；补处理固定范围。平台入口维护权不能替租户设设备解析采用或读取其原文。

### 4.2 端口分配、发布和生效

示例：甲／P1／厂家 A 使用 TCP 21001，甲／P1／厂家 B 使用 21002，乙／P2／厂家 A 使用 21003；实际端口由部署范围分配。

入口状态为 draft → awaiting_tenant_confirmation → publishing → active；另有 failed、paused、retired。租户确认精确修订；重发相同修订不重复确认，协议、身份凭证允许范围及身份约定变化重新确认。启用前校验业务对象可用、端点唯一、所需产物和兼容声明可用、上游分流能力及租户确认。

监听唯一键为 (relay_id, transport, listen_address, listen_port)，覆盖通配地址冲突；数据库预约与云端 bind 双重检查。首期一个监听端点对应一个业务入口，HTTP 推送也按入口独立监听，不从请求 body 或厂家名称动态选项目。消费者／控制接口使用统一独立端口。

发布带 command_id、修订摘要和 expected_generation，云端拒绝旧代覆盖、摘要不符和端口冲突。准确配置加载并监听成功后才显示 active；超时待核对，按原命令对账。

DDP 建连、HTTP 请求开始时固定修订。同归属普通升级允许旧连接保持旧修订，新连接用新修订；业务范围／身份切换必须停旧入口、关闭／排空连接后启新入口。端口复用不复用 ingress_id；积压按原包装处理，不重新贴标签。

“暂停接收”下发云端停接纳并关闭连接；“暂停解析”保留接收但停相应规划。断网时远程停接收显示未生效，内网阻断解析／提交立即生效。

### 4.3 关联生效与积压

云端按来源持久序号分配，计数行锁与接收同事务，已提交水位前无未提交空洞。首次登记、换绑及解复用变化时：暂停该来源规划，保存变更意图，以 command_id 取水位 N，再短事务结束旧区间并建立 N+1 起的新关联。可保存 start_after_sequence=N；网络调用不占长事务。

同来源变更串行化。云端不可达时待处理，可明确撤销；已生成计划保持快照，普通关联区间结束不重写旧计划。撤销机器授权、项目设备授权、设备资格或紧急阻断则立即拒绝新执行及成功提交，不等水位。

新登记不自动适用于 N 以前数据。补处理固定接收清单、原入口范围、目标关联及配置；禁止以普通操作将历史从一个租户／项目改到另一个。误配归属作为数据事件隔离。当前资格和历史快照同时检查，历史授权不代替当前读取／执行权限。

### 4.4 固定版本的时点

入口识别版本按云端接收修订固定；终端／关联按 epoch／序号区间固定；测量方法按内网首次成功建立计划时设备实际采用固定。计划还保存兼容声明修订，不能用设备观测时间猜配置版本。

产品默认变化只影响后续明确继承的采用。设备升级预览展示未规划积压量／未知量和兼容结果；已有计划用旧版本，未规划数据按新计划时点选取。需要旧方法处理积压时，暂停规划并明确选择范围和旧配置新建决定。重试不换版本，重新识别／解析均保留旧决定。

## 5. 云端接收、持久缓冲与投递契约

### 5.1 两次确认分别表示什么

| 确认 | 发送时点 | 保证范围 |
| --- | --- | --- |
| 云端对外报送确认 | 完整内容、可信接收元数据和待投递项已在云端持久事务提交后 | 云端已经收妥；不代表租户归属已确定、内网已收到或解析已成功 |
| 内网对云端确认 | 内网原文对象已校验，接收记录、原对象引用与待处理事实已在 PG 提交后 | 内网已经接管这份原文；解析失败或未知设备不妨碍该确认 |

TCP 的网络层 ACK 不能替代上述应用确认。TCP 提供字节流，传输适配器必须自行组装完整报文；一次读到的字节不保证恰好一帧。[依据：TCP 规范](https://www.rfc-editor.org/rfc/rfc9293.html)

云端采用独立 PostgreSQL 保存缓冲，原文 `bytea`、元数据和投递状态同事务落库，使用持久表、`fsync=on`、`synchronous_commit=on`。提交失败不返回应用层成功。该基线提供进程／正常重启恢复，不等同于单机磁盘永久损坏后的零数据丢失保证。[依据：PostgreSQL WAL 与提交设置](https://www.postgresql.org/docs/17/runtime-config-wal.html)

### 5.2 接收记录包络

内网投递契约命名为 `relay_contract_version=1`，严格 JSON；二进制内容使用 base64。所有序号、修订和字节偏移通过 HTTP 使用十进制字符串，摘要为 64 位小写 SHA-256。

| 字段 | 规则 |
| --- | --- |
| `relay_id`、`spool_epoch`、`receipt_id` | 云节点稳定身份、缓冲时间线、接收 UUID；三者构成内网接收唯一键，重投不变 |
| `ingress_id`、`source_namespace_id`、`source_revision`、`source_revision_digest` | 接收时的入口、命名空间和不可变修订；由监听配置生成，不能由报文覆盖 |
| `tenant_id`、`source_project_id`、`manufacturer_id`、`manufacturer_scope` | 平台发布的有限业务路由上下文；内网与该入口修订逐项比较，不直接当成人员权限 |
| `ingress_protocol_id`、`ingress_protocol_version`、`ingress_protocol_digest` | 固定入口协议及清单摘要，用于识别身份；不是最终设备测量方法 |
| `listener_transport`、`listener_address`、`listener_port` | 实际接收端点证据；历史不通过当前端口表反查归属 |
| `source_sequence` | 在该 epoch／来源内已提交的有序序号；分配及提交按第 4.3 节串行化 |
| `producer_principal_id`、`transport`、`authentication_level` | 已验证的报送方身份和接收事实；不含私钥、令牌或证书正文 |
| `connection_id`、`connection_sequence` | DDP 连接关联与帧序号；HTTP 无连接业务意义时为空 |
| `received_at`、`committed_at` | 云端服务器时间；与设备观测时间、内网入库时间分别保存 |
| `content_kind`、`payload_base64`、`byte_length`、`sha256` | 原始内容、实际完整性和摘要；类型来自入口约定，不能据此信任业务含义 |
| `producer_delivery_id` | HTTP 报送方提交的幂等键；DDP 可为空，不拿内容哈希代替消息身份 |
| `transport_adapter` | 固定适配器标识、版本及产物摘要，供帧边界和应答追溯 |
| `evidence_kind`、`truncated` | `complete_message` 或 `invalid_fragment`；若有界诊断截断必须显式标记，不能宣称完整保存 |
| `delivery_id`、`delivery_attempt`、`lease_token`、`lease_until` | 本次投递租约；每次重投可变化，不能参与业务报文唯一身份 |

内网核验机器身份、节点、入口修订、租户／项目／厂家／协议字段、长度及摘要。外部 HTTP body 即使包含同名字段也只是原文，不能参与包装赋值；原文与包装分别计算摘要，保存确定的不可变包装摘要（排除投递租约字段）。

可信云节点发送未知修订时，可保存在不对人员开放的隔离区后确认接管，状态 source_revision_unknown，补齐准确历史后才路由。已知修订的业务字段不一致、包装摘要冲突、同一接收身份对应不同原文或路由时，不确认、不覆盖，记录 envelope_config_mismatch／receipt_conflict；云端将该投递隔离等待对账，不进行无限热重投，其他条目继续。恢复不得把本地最新配置覆盖到原包装。

### 5.3 云端 API

所有路由为新接口，部署入口按机器证书用途分权。第三方只能报送；消费者只能读取其平台流并确认；控制身份才能应用来源配置。浏览器不直连云服务。

| 路由／端口用途 | 请求与行为 |
| --- | --- |
| DDP 受保护 TCP 监听 | 按入口固定适配器处理注册、数据和注销；持久化后作相应协议应答 |
| 各业务监听上的 `POST /v1/push/:source_code` | 先由目的监听确定 ingress_id，再验证 source_code 与凭证都属于该入口；路径不能切换项目，原 body 原样保存 |
| `POST /v1/consumers/:consumer_id/pull` | `request_id`、条数／字节上限、等待时长；领取一批未确认项及租约，空批表示当前没有可投递项 |
| `POST /v1/consumers/:consumer_id/acks` | 明确逐条接收身份、租约、原文摘要和本地接收收据；部分确认，不以最大序号替代 |
| `POST /v1/consumers/:consumer_id/releases` | 放弃／延后指定租约并给有限原因码；不删除原文 |
| `POST /v1/control/source-revisions` | 通过统一机器端口应用入口修订：路由 ID、端点、协议／适配器版本及摘要、凭证引用、expected_generation；返回实际监听及应用代次，不含设备台账或解析代码 |
| `POST /v1/control/source-watermarks` | 以 command_id 固定指定 epoch／来源的已提交水位，重复请求返回同一结果 |
| `GET /v1/status`、`GET /healthz`、`GET /readyz` | 有限容量、队列、连接及健康；受保护状态不得包含业务正文 |

单次拉取最多 100 条且解码原文合计最多 8 MiB，响应 JSON 最多 12 MiB；长轮询最多 25 秒，消费者 HTTP 超时 35 秒。投递租约 120 秒；来不及保存时释放租约，重投同一接收身份。消费者按容量领取，恢复网络使用有上限的指数退避和抖动。

云端确认是幂等操作；重复确认返回已确认状态。过期租约不能确认尚未确认的条目，需重新领取；已经确认的相同条目／摘要可以返回原收据。批次中部分失败不导致已确认项重新创建。平台使用一个稳定消费者组，多个内网实例通过租约分工，不能以两个组重复消费同一生产流。

### 5.4 重投、重复报送与顺序

HTTP 推送要求 `Idempotency-Key`，在已认证来源范围内唯一：同键同原文返回原接收收据，同键异文返回 409。Cloud HTTP 只有持久提交后返回 202；请求响应丢失时生产者重放同一键。该幂等身份贯穿确认后的索引保留期，旧键冲突不能重新当作新报送。

DDP 上行数据在本选定布局中没有可供本系统可靠使用的通用全局消息编号。每次实际收到一帧形成一个接收事实；同内容再次报送保留为新接收记录并可标重复候选。云端向内网的同一条记录重投则必须命中接收唯一键，不能新建原文或新的默认解析结果。两种重复分别统计，不能按“设备＋时间＋数值相同”直接丢弃原始上报。

拉取和处理可能乱序，每条接收序号、连接序号和租约完整保留。一个来源的坏消息不阻塞其他来源；单元解析独立，后续基于观测时间的排序和冲突处理属于正式采用模块。

### 5.5 容量与删除

云端未确认原文不按时间自动删除。默认已确认原文至少保留 7 天，再按可审计策略清理；轻量接收身份／摘要／HTTP 幂等索引保留，生命周期另有明确归档策略后才能收缩。内网自动重解析使用自己的原文，不能依赖这 7 天缓冲。

容量按来源和全局限制，实施配置显式给出磁盘预算；达到 80% 告警、90% 停止接纳新完整报送并保留已有队列。HTTP 返回 503／Retry-After，DDP 不返回“收妥”并按协议可行方式断开或限制读取。上游不会重试时可能丢失未被接纳的数据，状态页必须说明拒收量和时间段；禁止删除最老未确认记录来伪造正常接收。

云端缓冲不可用、数据库只读、磁盘满或持久性检查失败时 readiness 失败。公网无效连接和异常碎片有独立预算，只保存有界诊断片段；没有被完整接纳的字节不记为“完整原文已保存”。

## 6. 内网原始报文、处理单元与保留

### 6.1 两种记录分别保存

接收记录保存云端实际收到的完整 DDP 帧或完整 HTTP body，原文不可变。报文处理单元保存来源识别后可独立处理的字节视图、来源位置和归属决定。一份记录可以有多个单元；单元可对应整帧、原文范围或明确的 base64 解码结果。

每个单元至少保存 `unit_id`、接收 ID、识别决定 ID、稳定单元键、原文定位、转换规则、单元字节数／摘要、终端线索、子地址线索及当前处理状态。派生字节另存不可变对象时标记其派生性质，不能把它冒充网络收到的整份原文。

定位须能从监测结果回到：产品解析步骤 → 输入单元 → 来源识别／解复用步骤 → 原接收记录。解码、去外层和切分都记录固定方法版本、产物和范围。无变化转换可直接引用原对象及范围，避免无意义复制。

### 6.2 持久化和内网确认顺序

1. 校验云端包络，在本地创建有界接收意图；以唯一对象键写原字节并核验 SHA-256。
2. 短事务写接收记录、对象引用、来源修订、待识别事实和确认 outbox；接收唯一键冲突时比较全部不可变事实。
3. 只有上述提交完成，确认发送器才向云端确认。原文不可用、摘要错误或事务失败时不确认。
4. 确认响应丢失或进程崩溃后，重投命中原接收收据，再幂等确认；确认 outbox 可以恢复。
5. 对象写成功但事务未提交的孤立对象可在宽限期后按引用及活动意图复核清理；不能按文件年龄删除正在处理的数据。

内网 PG 保存控制真相和检索索引，S3 保存原文、大结果与步骤。生产接收使用独立对象前缀、容量和队列，不能沿用试解析样本的临时清理规则或 10 GiB 范围预算。所有已接纳生产原文和处理历史本期不自动过期；存储水位不足时暂停拉取，保持云端未确认记录。

### 6.3 按入口保管、按核验单元开放

入口的租户和来源项目在接收时已知，不再把所有未识别报文放进全平台“可认领”池。未知配置、身份未明、项目／厂家冲突的原文保存在系统隔离区；租户仅凭自己的已确认入口查看有限待处理元数据。平台普通管理员或入口维护者没有正文读取权。

只有终端和设备关系、来源项目授权及厂家校验通过的单元，才能按租户消息／原文权限开放。登记新终端不自动开放历史范围，须明确补处理。原文即使被误投到本入口，也不能因此被认为已证明属于该租户。

厂家批次根原文完整保存在系统层。本期对人员统一提供核验后的单元视图及必要公共上下文，批次根对象不作为直接下载接口；单路完整帧经核验可作为该单元原文读取。每项视图保留根接收 ID、摘要、切分位置及转换证据，不公开其他未授权单元目录。

服务器按授权返回精确范围或派生单元，不能整包交前端裁切，不暴露 S3 地址。错误混报、无法安全拆分的坏批次和未知修订不提供普通正文下载，不能因“解析失败”退回平台全局可读。原文完整保存和人员可见范围分别管理。

### 6.4 查询与状态

支持按云端／内网接收时间、来源、终端、设备、接收身份、解析方法版本、处理阶段及错误码筛选。原始值全文检索、任意正则扫描和全平台正文搜索不在本轮；查询有界分页，不要求一次加载全部报文。

至少显示四组独立状态：连接状态、接收／确认状态、身份关联状态、解析执行状态。最近连接、最近收到完整报文、最近测量报文和最近解析成功分别记录；云端连接存活不能显示为监测设备测量正常。状态新鲜度基于真实观测时间，内网断联时显示云端状态未知／过期，不伪造所有设备已离线。

## 7. 解析服务扩展与生产链路接入

### 7.1 新旧契约及平台目录如何衔接

保留 GET /v1/catalog、POST /v1/parse 及 contract_version=1 的原结构和行为。新增 GET /v1/ingestion-capabilities 和 POST /v1/identify，使用独立 ingestion_contract_version=1；首期不修改已有 Manifest 原文或摘要。所有新接口继续使用已有机器认证、限额、固定产物与受限执行机制，浏览器不能直连。

| 新增能力目录内容 | 固定信息 |
| --- | --- |
| identification_methods | source_identify／terminal_demultiplex 用途、ID、版本、输入／输出契约、产物和清单摘要、样本集摘要、执行限制 |
| ingress_protocols | 入口协议 ID／版本、适用传输、准确适配器及识别引用、编号规范、允许输入视图；不含业务归属 |
| compatibilities | 准确入口协议＋可选解复用版本＋输入视图／parse_transport＋既有测量方法四元组及摘要、验证夹具摘要 |
| release_coverage | 服务发布和适配器发布中保留的所有被引用产物，供平台部署检查 |

平台将新能力同步到解析域的增量目录表，沿用 pending → 启用、停止新采用、紧急阻断和审计规则；界面归于同一“协议与解析方法”，不产生租户协议定义页。制造商适用范围是目录说明／筛选，具体入口及产品绑定仍以实际 ID 和兼容证据为准。

停止新采用不等于阻断执行：已固定入口仍可使用原识别版本，已有设备采用仍可生成同版本的生产计划；新入口／新设备采用不得新选已停止新采用的对应能力。紧急阻断则同时拒绝新的执行和终态提交；历史结果保留并按当前读取权限查看。测量方法的停止新采用不能让现有设备自动换到新版。

已有测量方法的兼容声明作为独立、不可变的附加记录发布，可引用原始 method_id、method_version、manifest_digest、artifact_digest，不改旧方法。声明更新产生新修订；撤销兼容声明是有审计的阻断动作，不静默切换方法。配置入口不下载／执行请求指定代码；云端仅选择发行包已包含的适配器，缺失时发布失败。

接入能力目录不可用时显示 unavailable 并停止新接入配置，不影响既有人工试解析。目录同步不得把未获取到的新目录当空清单删除历史。重放、积压和生产计划引用的旧产物纳入既有发布覆盖／恢复检查。

### 7.2 identify 请求、响应及证据

请求指定 execution_id、精确识别方法引用（ID／版本／清单及产物摘要）、原字节 base64／长度／摘要、固定接收时间和输入类型／解释传输类型、trace_id。身份识别只接受入口清单指定的方法；终端解复用只接受该终端在接收区间内固定的方法，不接受用户指定 URL、代码或任意存储键。

| 响应字段 | 必须满足 |
| --- | --- |
| status | identified／rejected／unsupported，损坏结构不能返回成功 |
| method、execution_id、input_sha256 | 与请求精确一致；保存服务发布／构建摘要 |
| units | 有界数组；稳定 unit_key、message_kind、terminal_key／child_key、input_view |
| input_view | whole／range／decoded；输入长度、摘要、原范围、转换链及输出解释类型完整 |
| external identities | 原始表示、规范值、类型和位置，不能返回已授权的 tenant_id／project_id／device_id |
| steps、diagnostics | 每次拆分／解码有规则、输入输出摘要和位置，拒绝越界、缺失依据及非法重叠 |

识别服务不消费整份业务包装来决定权限。内网验证包装后选出方法和必要上下文，再把原始字节交给它。多子单元需要重复的外层头部应显式引用公共证据，不把其他子设备载荷带入目标设备输入。所有字节范围采用 [start,end)，明确相对于哪个原文／父单元；base64 解码须保存原 JSON 字符串范围、解码规则及解码前后摘要，再连接子帧／reading 的范围。位移值定位不能把解码后的偏移直接当作 HTTP 根原文偏移。

### 7.3 单路、多路及传输上下文

单路 DDP 身份识别输出完整帧，可直接交给现有 example.hongdian.ddp.tcp.monitoring-json 的固定版本。多设备终端把完整 DDP 帧交给固定解复用能力，在其内部定位 channels 载荷并输出各 child_key 的 reading 原文范围，交给明确接受独立 reading 的新增方法；不能把 JSON 子对象伪装成完整 DDP 帧。

HTTP 批次识别解码出 DDP 帧后，保存实际 relay_transport=https_push，同时在输入视图中声明 parse_transport=tcp。POST /v1/parse 的 context.transport 使用该视图的解释类型，以满足现有完整 TCP 帧契约；这不声称网络实际为 DDP TCP。该转换固定在协议清单和计划里，不能由 worker 临时猜测。

如果目标方法输出了外部身份，还须与冻结的终端／子地址核对；不一致返回 parsed_identity_mismatch。方法未返回身份时，依赖已经验证的输入切分和登记依据，不能凭解析成功替代身份核验。原有精确数值、时间、单位、步骤和映射校验全部继续执行。

### 7.4 生产计划、执行授权和结果

阶段为 stored → identifying → awaiting_identity／identified → awaiting_association／planned → parsing → parsed／rejected／retry_wait／blocked；配置未知、路由冲突和协议不兼容使用明确错误码。control 单元只保存控制事实及识别证据，不创建测量计划或补零；envelope 根只产生子单元，不自己生成监测值。接收保存、身份匹配、执行状态、输出映射状态、业务质量、正式采用分别显示。parsed 不代表映射通过、质量正常或观测已采用。

计划固定：接收／单元／识别决定、入口业务范围和修订、终端及关联区间、来源项目设备授权依据、兼容声明、租户机器执行授权及代次、设备／产品版本、adoption_id、配置和输出代次、测量方法四元组、输入视图与摘要、接收时间和上下文。创建计划与入队同事务，一个单元的一次处理决定只有一个默认计划。

入口获准且租户确认后，基础接管可以继续。自动识别由已启用入口的机器处理授权控制，自动测量解析还要求终端／设备范围授权；个人启用者仅作审计来源。账号离职不借其身份运行，也不把离职等同于已撤销机器授权。人工补处理仍复验当前操作者权限和固定清单。

领取、调用前和终态提交分别复验入口阻断、租户／项目／设备状态、项目设备授权、机器授权、方法及兼容声明阻断。关联正常切换不篡改旧快照；安全撤权阻止旧计划成功提交。云端接纳或内网保存成功不代表租户已允许测量解析。

context.received_at 固定为云端接收时间，内网接管时间另存；观测时间按协议提供。旧计划重试不改时间、设备和版本。原文、解析结果和标准观测维持三层边界：生产结果保存到接入域，本轮不得生成正式观测 publication／chunk、导入或派生任务。

接口命名在实施中落到实际函数，必须维持以上职责。采用命令、关联变更和规划遵循既有 access／devicecoord 锁顺序，入口及关联锁置于相应设备协调锁之后，所有路径一致；远程 IO 不占业务锁。既有功能关闭接入时仍可执行；接入已启用而兼容检查失败不能以“检查器不可用”放行。

生产响应使用与人工解析相同的严格验证器，保存不可变结果对象和完成引用；接入域负责自己的权限、租约、fence、结果提交和历史。字段读数不直接散落写入设备台账。查询生产结果需接入消息权及既有 tenant.parsing.run.read，原字段／字节另需原文权限。

### 7.6 重试、重新处理和恢复

网络、暂不可用及限流每阶段最多 5 次总尝试，退避 1 秒、5 秒、30 秒、2 分钟；客户端不叠加隐藏重试。未知身份、范围冲突、不兼容、坏结构和契约错误不热重试。身份识别与测量阶段分别计数，预算与人工试解析独立。

每次尝试有新 execution_id、租约和 fence，结果对象先写再核验，提交时检查当前授权和代次。服务可能重复计算，系统只接受该计划一份终态结果。过期、取消及旧 worker 响应保留诊断但不得覆盖有效结果。

重新识别、换版本重解析和配置补齐后的补处理均新建决定，固定最多 1,000 个单元的清单及配置；只重投云消息不能产生新解释。历史计划／结果及对比保留，原报文身份与源项目不变，不能自动替换未来已正式采用的观测。

## 8. 异常、处置与恢复规则

| 情况 | 保存与状态 | 处置 |
| --- | --- | --- |
| 内网断网／出口改变 | 云端继续缓冲，内网显示状态过期与积压 | 恢复原消费者连接，按原接收身份续传 |
| 云端存储故障／容量不足 | 不确认新报送，保留已持久记录 | 修复重启，单机永久损失按备份能力报告缺口 |
| 本地 S3／PG 失败 | 不向云端确认，接收意图未完成 | 原身份重投核验，孤立对象不冒充接管成功 |
| 未知入口修订／新 epoch | 原文受限保存，配置待核对 | 补准确历史、重新确认时间线及关联起点 |
| 包装与已知入口不符／同收据变路由 | envelope_config_mismatch／receipt_conflict | 不确认冲突，隔离并对账，不用最新配置覆盖 |
| 未确认入口 | awaiting_source_confirmation | 不开放原文或启动业务解析，租户确认后按范围补处理 |
| 身份缺失／歧义 | identity_missing／identity_ambiguous | 补报送约定，不尝试所有产品方法 |
| 未登记终端／子地址 | terminal_unregistered／association_missing | 本入口待处理；租户登记关联，再明确范围补处理 |
| 租户／项目／厂家不符 | routing_scope_mismatch | 隔离错误单元，修复上游／关联；不自动跨范围转送 |
| 设备无解析采用 | parser_unconfigured | 配置后新建计划，不回退到产品最新默认 |
| 入口与测量方法不兼容 | ingress_method_incompatible | 停用冲突关联后选择兼容配置，或启用新入口 |
| 解析返回身份与计划不符 | parsed_identity_mismatch | 保留失败证据，禁止输出被当成该设备的有效结果 |
| 租户／项目／设备停用或授权撤销 | blocked，领取和终态提交均受阻 | 有权者恢复资格后显式恢复范围，原文不删除 |
| 方法缺失／被阻断／服务暂时不可用 | 分别显示 unavailable／blocked／retry_wait | 按固定方法与重试预算处理，不替换方法 |
| 坏结构／非法字段／映射冲突 | 原文、步骤、位置及映射状态独立保存 | 修复来源或发布新方法，新建重解析决定 |
| 并发配置／关联／采用变化 | 修订冲突，已提交计划保持快照 | 重读预览，使用统一协调锁和提交复验 |
| 原文／结果损坏 | integrity_failed | 校验恢复，不能生成替代原文冒充历史 |

人工操作包括入口确认、登记／关联、限定补处理、重新识别／解析、暂停／恢复及关闭异常。关闭异常只记处置结论，不删除原文或把失败改成功。每次最多 1,000 个单元，固定清单并保存逐项结果；恢复状态不能以部分成功冒充全部成功。

首批误投验收使用不获准入口的凭证、未登记编号或不满足项目／厂家关系的关联。若上游拥有两入口的有效凭证，且报送完全相同、在各自入口均合法的编号与载荷，系统不能仅凭字节证明真实现场来源；开通验收必须验证上游分流及凭证分配，界面展示“按入口约定归属”，不宣称端口能验证物理来源。

指标按真实阶段聚合，无权限、依赖故障与零值分开。云端、接入、解析均记录接收／决定 trace 引用；日志只含安全 ID、状态、耗时及字节数。

## 9. DDP、厂家模拟端及固定验收样本

### 9.1 DDP 传输适配器

沿用[解析规格中限定的 H7710S-DDP TCP 帧布局](parsing-service-and-method-binding-spec.md#ddp)，不扩大为所有宏电型号。云端适配器新增流分帧和必要应答：注册 `0x01 → 0x81`、上行用户数据 `0x09 → 0x85`、收到注销 `0x02 → 0x82` 后结束会话；应答只在对应记录持久提交后发送。选定的 `0x85` 是本接入配置要求的接收确认，不代表产品解析成功。[协议原文依据](https://www.ziliaoku.com/res/info_da3c4d67c0164a33a5721f0ad92ef27c.html)

每条连接先完成注册，固定其来源身份和 DTU 标识；后续帧的标识必须一致。注册之前发送测量包、同连接切换 DTU 标识、同来源／DTU 同时建立冲突活动会话均拒绝并留受限诊断；不采用后到连接无条件踢掉原连接的规则。断线后可正常注册重连。

分帧按长度处理粘包、拆包和载荷中的 `0x7B`。正常帧最大 1040 字节；错误长度、非法帧首、超时未完成或断线残留形成有界异常片段并关闭连接，不扫描后续标志后悄悄丢掉异常前缀。片段最多保留 8 KiB，截断必须标记。连接空闲超时默认 180 秒，可按来源明确设置；没有注册新“心跳包类型”，TCP 活动和有效报文活动分别记录。

云端不主动下发重启、参数修改或升级命令。厂家 HTTP 转发的 DDP 帧为已包装的消息，内网校验完整帧，不要求它在 HTTP 连接上重做 DDP 注册；HTTP 来源身份由该报送方认证确定。

### 9.2 首批识别方法和设备解析方法

| 方法标识（拟定） | 用途和固定输入 |
| --- | --- |
| `ingest.hongdian.ddp.tcp.identity@1.0.0` | 完整 DDP 帧 → 终端标识、控制／数据类别、完整帧输入视图；复用已核对 DDP 结构代码 |
| `example.vendor.ddp-batch.identity@1.0.0` | 本节模拟厂家 JSON 批次 → 解码各 DDP 帧、提取各终端；仅示例报送约定 |
| `example.hongdian.ddp.channels@1.0.0` | 完整 DDP 帧（载荷为本节 channels JSON）→ 子地址及 reading 原文范围；仅示例解复用方法 |

### 9.3 模拟厂家批次

厂家模拟端使用绑定 E2 入口的凭证，向该项目／厂家专属 HTTPS 监听推送以下精确 JSON。两个 DDP 标识都登记到租户甲、项目 P1、厂家 A，可关联不同产品或采用不同测量版本；原 body 不需要 tenant_id、project_id、product_id 或解析方法 ID。云端另外添加 E2 的可信包装，不能将此包装写回原 body。

```json
{"messages":[{"id":"m-1","ddp_base64":"ewkAUTAwMDAwMDAwMDAxeyJvYnNlcnZlZF9hdCI6IjIwMjYtMTEtMTZUMDA6MDA6MDBaIiwiZGlzcGxhY2VtZW50X21tIjoiMTIuMzQwIn17"},{"id":"m-2","ddp_base64":"ewkAUTAwMDAwMDAwMDAyeyJvYnNlcnZlZF9hdCI6IjIwMjYtMTEtMTZUMDA6MDA6MDBaIiwiZGlzcGxhY2VtZW50X21tIjoiMTIuMzQwIn17"}]}
```

该行无 BOM、无尾随换行时为 288 字节，SHA-256 为 `7e9632a8c63659897b9e85d1a1d13a5653917439e7e00ee90f9fbafe8ba8df16`。每个解码帧 81 字节；终端 `00000000001` 的帧摘要为 `87b7f3f0e959ee6881bba0d4d0ddb045cddc2786f947b2f64f5976a2a501c63e`，终端 `00000000002` 的帧摘要为 `8ce5f2e79b6e63da2fe71ae6464413a0a0f7434813ce7bca478da46c7dd852f4`。

模拟厂家约定 messages 为 1—100 项，id 在批次内唯一，ddp_base64 解码为一个完整帧；重复键、未知字段、非法编码和结构错误整体拒绝识别，保留根原文。结构成功后各单元独立关联。id 作为外部线索保存，云端报送幂等仍使用 HTTP Idempotency-Key。

### 9.4 多设备网关样本

模拟网关 `00000000003` 上报一个 `0x09` DDP 帧，用户载荷为下方精确 JSON，A／B 对应同租户两个不同产品的设备。租户配置明确选择示例解复用方法，两个设备采用读取独立 reading 的方法。

```json
{"channels":[{"key":"A","reading":{"observed_at":"2026-11-16T00:00:00Z","displacement_mm":"12.340"}},{"key":"B","reading":{"observed_at":"2026-11-16T00:00:01Z","displacement_mm":"8.500"}}]}
```

该载荷无额外空白时为 189 字节；完整帧 205 字节，头部为 `7B 09 00 CD`，随后是终端的 11 个 ASCII 字节、上述载荷和末尾 `7B`。完整帧摘要为 `94f95b17b4a91fad143ccea7939a03d3018fb0a0e057581cbc2d24c10a34e469`。两个结果应分别为 12.34 mm 和 8.5 mm，位置指向各自 reading，不包括另一个子设备的字节。

该示例限制 channels 为 1—16 项且 key 唯一；reading 结构及数值规则沿用原解析规格，未知子地址进入待关联。复制 reading 时不得重新格式化 JSON 再把新格式当作原始字节，使用原文范围或记录明确转换。

### 10.1 InfraPro 新增／扩展 API

### 10.2 控制台与已有页面如何连接

1. 平台既有解析页扩展“协议与解析方法”：分辨测量方法／接入能力、准确版本、兼容关系、示例标记和产物可用状态；旧样本／运行入口保留。
2. 产品“解析配置”继续选平台方法、版本和输出映射，显示适用入口；身份识别专用方法不能作为测量方法选入。
3. 设备“解析”保留当前采用、产品默认差异、特化／恢复继承；增加有效入口兼容列表和升级影响。设备“接入”展示终端／子地址、来源项目、最近接收／成功及反向链接。
4. 平台新增“数据接入”：云节点、入口端口与路由、租户确认、发布／实际生效状态、隔离元数据和运行诊断。平台无权限查看的私有项目／厂家名称不展开，有限 ID 引用不产生业务详情读取权。
5. 租户新增“数据接入”：入口确认、终端与设备关联、机器授权、原始报文、待处理及恢复。优先按项目／厂家／入口筛选，不把每端口变成独立侧边菜单。
6. 报文 Drawer／详情展示云端收妥、内网接管、识别、匹配、计划、解析时间线；并列显示入口协议和设备实际方法，支持字段定位与所有历史决定。
7. 项目设备页面只显示已有授权允许的安全摘要；不能因来源项目已确定而开放原文或接入管理。

复用现有 Query 授权缓存、表格、遮罩 Drawer 和字段证据组件。状态区分入口待确认／发布失败、云端不可达、无报文、待登记、待关联、不兼容、无采用、积压、控制包、拒绝、暂停及对象损坏，不能把未知画成在线正常。

### 10.3 任务、审计与诊断

自动接收／识别／解析使用模块流水和指标，不逐帧建立人员任务。人工恢复来源 ingestion:recovery、类型 ingestion.reprocess，固定清单、输入和代次，注册真实 Source Adapter、控制和结果入口，遵循[任务接入指南](task-center-integration.md)。项目不得发起；平台任务仅做传输／配置恢复，不能读取租户测量结果。

按[审计接入指南](audit-integration.md)记录协议启用／阻断、入口发布／确认、终端关联、机器授权、补处理、异常关闭、原文读取和结果下载。配置／操作和审计同事务；自动处理留实际授权和机器证据，不冒充启用者亲自操作。

普通审计／日志只存安全 ID、修订、摘要、状态、字节数和 trace，不写原文、测量值、密钥、底层路径及未授权名称。诊断登记云转发、ingest-worker 的真实 lane／依赖；查询状态通过既有安全连接，不另开云端管理端口。

### 11.2 必须同时成立的边界

- 云端按可信端口配置包装路由；外部自报 tenant_id／project_id／protocol_id 不能覆盖配置。凭证限制入口，拒绝拿甲入口凭证发乙入口。
- 入口确认和机器授权分别记录，平台发布不自动替租户允许测量解析；租户不能更改监听端口、云地址或协议代码。
- 终端、设备、项目和厂家采用组合外键／服务器事务校验，不能仅过滤前端选择器。已启用入口的业务归属不可修改。
- 生产状态与计划检查当前资格；设备或项目授权撤销后，领取和终态提交均受阻。数据保存不因解析失败回滚。
- 平台维护权不包含租户原文；未匹配、误投和未知配置仍在系统受限保管，不能以“管理员”或“排障”绕过。
- 项目路由不改变现有资源授权／通道绑定。项目页面、任务、计数、游标、下载和缓存都复验当前资格。
- 新接入 API 不提供任意对象键、任意 SQL、服务 URL 或代码执行参数；原文和结果由所属域鉴权后按范围读取。

| 云 relay_command_receipts、relay_connection_events | 发布／水位命令幂等、精确应用状态和有限连接事件，无业务台账 |
| ingestion_sources、ingestion_source_revisions、ingestion_source_confirmations | 永久入口及命名空间、不可变业务范围、修订、租户确认、云端应用状态 |
| ingestion_terminals、ingestion_terminal_revisions | 本入口编号唯一、不可变租户归属、单路／多路及解复用修订 |
| ingestion_device_associations、ingestion_change_intents | 子地址、设备、来源项目授权依据、epoch／序号区间与可恢复变更；同键区间不得重叠 |
| ingestion_execution_grants | 明确入口／终端范围、授权代次、预算、启停和历史 |
| ingestion_receipts、ingestion_receive_intents、ingestion_ack_outbox | 接收唯一键、原对象／摘要、包装快照、接收意图、待确认事实 |
| ingestion_identity_decisions、ingestion_units、ingestion_unit_assignments | 不可变识别／匹配决定、单元视图、当前状态及历史；不覆盖旧决定 |
| ingestion_parse_plans、ingestion_attempts、ingestion_results | 固定采用／兼容／机器授权／输入和输出快照、执行租约／fence、结果对象；唯一默认计划与唯一接受终态 |
| ingestion_recovery_jobs、ingestion_changes、ingestion_operation_receipts | 人工固定清单、任务事实、审计关联及幂等收据 |

入口、终端、设备、项目引用使用 tenant 组合约束；厂家引用校验 public／tenant 作用范围及产品实际厂家。原文对象由 ingestion 拥有，以已校验的输入引用交给内部执行代码；任何 API 均不能只凭对象键下载。业务配置、任务事实、审计和命令收据按当前事务规则提交，外部 IO 放在短事务之外。

接收唯一键为 (relay_id, spool_epoch, receipt_id)；同键同时比较原文、不可变包装及归属。来源计数／关联区间带 epoch。解析默认计划至少唯一于 (unit_id, decision_id)，尝试新建不等于新计划。无设备关联的记录可安全保存但不生成测量结果。

### 12.3 增量迁移与启用顺序

1. 保存既有目录、产品配置、设备采用、人工运行／对象和已发布执行产物的校验基线；记录数据库版本及未提交源码状态，维护既有业务数据。
2. 按实施时最新序号新增 Goose 迁移，不修改已执行的 00044_parsing.sql。建立增量目录、ingestion 表、约束、权限和索引；已有数据迁移后逻辑内容、方法摘要及 ID 相同。
3. 发布兼容旧 /v1/catalog、/v1/parse 的解析服务，保留旧清单及产物；随后同步并验证新接入能力。旧客户端和旧试解析仍可用。
4. 发布新业务 API／控制台及内部兼容检查接口；接入功能默认关闭，不启动公网监听或自动登记既有设备。
5. 显式迁移云缓冲库、安装服务和适配器；内网配置获准 IP／端口及证书，完成机器通道验证。
6. 平台编制入口，租户确认，云端应用成功；租户登记终端、确认项目授权、选用相容的设备采用并开启机器执行。
7. 先隔离模拟入口贯通和故障注入，再按实际部署验收批准的入口逐一启用。步骤是完整交付内部顺序，不缩减第 14 节范围。

服务启动检查迁移／契约版本，不自动执行数据库迁移。平台目录、云端配置、入口发布和设备采用是不同操作，任何一步成功都不能自动替代后一步。

### 12.4 部署、容量与诊断

部署清单包含云环境、独立持久 PG、外部端口范围、内网获准地址、证书、内网 PG／S3、parser、ingest-worker、平台 API 及控制台。云与内网分别使用受限数据库角色，云端无业务库地址和凭证。密钥仅通过受控文件／安全引用提供。

初始预算：HTTP 原文 4 MiB，单次识别 256 单元，具体方法可更小；执行 5 秒、响应 16 MiB。云端每入口逻辑预算 10 GiB、节点合计 100 GiB，部署须扣除索引／WAL／磁盘余量。生产原文使用独立 S3 前缀和预算，不继承人工样本的临时清理及 10 GiB 限制。

接收／识别／测量各有持久队列和有界并发；初始识别／测量每租户各 2、全局各 4。共同 parser 服务保留人工试解析可用容量，按入口／租户公平调度，后端限流进入有界退避。隔离记录也计入容量，不因不参与解析而无限积累。

新进程接入[独立进程报告](diagnostic-process-reports.md)，显示接收、拉取、确认、识别、规划、解析、队列和最后成功时间。就绪条件按 lane 分别核验真实存储、清单、认证和处理依赖；只有心跳线程活着不算就绪。parser 暂时不可用只使解析 lane 等待，接管／确认 lane 在本地存储健康时继续工作；不能把测量服务故障变成“原文尚未接管”。隔离预算和停止接纳规则按第 5、6 节执行。

### 12.5 恢复、暂停与回滚

普通重启保持 relay_id、spool_epoch、来源序号及收据。恢复旧备份或丢库后可能回退序号时，新接收建立新 epoch；恢复旧记录仍保留旧身份。新时间线先隔离确认，再重建关联区间，不能套用旧序号。

备份包含云 PG／原文、内网 PG／S3、入口／确认／关联历史、计划结果、机器授权、所有清单／产物及部署配置引用。按接收身份、原文和包装摘要对账；已接管未确认可再确认，缺失记录明确报告缺口。云端保留期不代替内网长期原文和备份。

暂停接入功能保留全部历史读取和原有人工解析／监测能力；停止新接纳与停止处理分别操作。回滚必须检查目标包支持已发布入口、新表读取及所有历史产物；缺少在用能力的旧包拒绝正常回滚。紧急情况下先停相应接收／规划并保管原文，使用支持当前 schema 的兼容版本恢复，不删除新表、重建方法或覆写已保存结果。

### 14.13 用户人工验收主路径

1. 打开平台“协议与解析方法”，查看原 DDP／模拟测量版本和新增入口／识别能力，确认方法不隶属于某产品，识别专用方法不能误作测量方法。
2. 给公共／私有样例产品选择平台测量方法，新设备明确继承；保留一台 V1，另一台显式特化为 V2。原配置、采用和样本历史仍可查看。
3. 按第 9.5 节建立 E1—E5：两租户、三个项目、两个样例厂家。查看监听端口、业务路由、入口协议、配置修订及实际应用状态。制造一次端口冲突，确认不会假显示 active。
4. 租户确认自己的准确入口修订，登记单路终端和多路网关，建立设备项目授权及终端关联，再开启机器执行；另一租户无法确认这些入口。
5. 启动 DDP 和 HTTP 模拟端，原 body 不带产品或项目也能自动保存、识别、查设备及按采用解析。查看 HTTP 接收与 TCP 帧解释类型的区别。
6. 检查同一入口的 V1／V2 各自结果，再修改产品默认，确认已有设备版本不变。选择不兼容特化应看到具体关联冲突且提交不成功。
7. 打开一条结果点击字段，逐层定位测量步骤、输入单元、识别／解复用、完整原接收身份及入口修订；原文、解析结果、业务质量和正式采用分开展示。
