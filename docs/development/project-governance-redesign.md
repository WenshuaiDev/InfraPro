# 租户项目治理：方案 B

状态：**Awaiting acceptance（待人工验收）**。用户于 2026-11-16 选择项目卡片原型；本轮实施正式页面，人工验收单独记录。

## 目标与交付

将租户项目治理改为“项目全景 + 项目卡片”。保留项目创建、名称/编号搜索、状态与负责人筛选、管理员异常筛选、分页、治理详情、恢复管理员以及工程资源/设备/空间资料/监测数据授权入口。

卡片展示真实名称、编号、运行/归档状态、已授权设施/测点/设备数、当前项目成员数、负责人、管理员可用性和计划周期。项目类型没有现成业务字段，不用名称猜测分类；卡片线稿只作装饰。

顶部提供全部、运行中、需关注数量，全部数量包含归档项目。统计覆盖租户全部项目，不受列表搜索或分页截断影响。没有管理员空缺时不显示异常提示。

详情使用系统 ResponsivePanel 遮罩抽屉，展示治理摘要与原有四类授权入口。独立详情 URL 继续可用；操作历史复用权限受控的审计入口，不制造示例事件。

## 技术与数据流

- React / TypeScript：正式组件、状态、无障碍语义与响应式布局。
- TanStack Router：保存筛选和详情选择；TanStack Query：服务端筛选、游标分页、作用域缓存和重新验证。
- Tailwind / 现有 UI 组件：沿用产品主题、按钮、状态标签和 ResponsivePanel，支持深浅色和窄屏。
- Go / PostgreSQL：在现有项目治理读取事务中计算总量和当前页项目规模，不增加表或数据库迁移。
- OpenAPI / 类型生成器：补充向后兼容的治理统计字段；“我的项目”继续返回最小投影。

现有项目列表返回分页项目，以及完整租户的概览/负责人选项/筛选结果数。规模按当前页项目 ID 批量聚合，详情查询复用同一统计函数。

## 权限与统计口径

- 基础摘要、概览和负责人选项继续要求 tenant.project.read。
- 设施/测点数量要求租户工程资源读取及资源授权读取权限；只统计活动关联下未结束、未删除资源的显式授权，不把上下文节点当作获授权资源。
- 设备数量要求租户设备读取及设备授权读取权限；只统计未结束的设备授权和未删除设备，不把设备输出混入台数。
- 项目成员数遵循现有项目成员读取权限，不因租户管理员身份获得额外项目权限。统计未结束的成员关系（含暂停成员），与成员列表默认口径一致。
- 无权统计返回 null，界面显示无查看权限；真实零数量显示 0；读取失败不显示伪造零值。
- 不把多个项目的授权数量相加作为租户去重资源总量。
- 需关注指管理员不可用或空缺，与监测告警无关；计划周期不表示实施进度。临近计划结束只提供日期提示，不自动归档。
- 创建和恢复管理员沿用真实接口、影响预览与现有权限约束；归档状态继续遵循原业务规则。

## 自检与人工验收

1. 项目卡片真实数量与对应授权/成员列表一致，两个项目及更多项目布局整齐。
2. 顶部总量不因分页、搜索或负责人筛选而变小；结果数随筛选变化。
3. 搜索名称/编号、状态、负责人、仅管理员不可用或空缺均有效；清除筛选、空列表、加载更多和失败重试可用。
4. 点卡片打开系统遮罩抽屉；关闭/返回焦点、刷新深链接、授权导航和独立治理详情可用。
5. 无权限不暴露数量或对应操作；撤权/切换租户后不残留旧摘要；平台身份不替代租户/项目资格。
6. 恢复管理员完成后卡片与总览刷新；创建项目入口仍进入现有创建流程。
7. 桌面和窄屏无页面横向溢出，按钮与标签不挤压，深色主题可读。
