# 工程空间：设施树工作台

状态：**Awaiting acceptance**。方案 A 的正式重构、仿真工程资料制作与入库、自验收已完成；等待用户人工验收。用户尚未确认 Accepted。

## 目标与范围

租户工程空间以「设施 → 任意层构件 → 测点」为唯一业务导航，复用资源目录的权限、搜索、分页和键盘操作。右侧只展示所选设施的资料；切换布设图、BIM / 三维、GIS 时保留业务对象。资料管理、源模型实体和对象详情按需使用系统遮罩 Drawer。项目工作空间既有固定版本授权不改变。

资料属于设施，设施下的对象可以查看资料，但只有显式创建的图纸区域、模型实体关联或测点坐标才算定位。一个对象可以关联多份资料或同一模型的多个实体。跨设施 GIS 作为共享参考图层独立提供。已发布版本不可修改，标注沿用「创建草稿 → 保存 → 预览影响 → 发布」流程；导入、任务、原件、版本、历史、退役与撤回保留现有能力。

## 实现

React + TypeScript / TanStack Query 接现有真实资源和空间 API；复用 ResourceTree、VersionCanvas、AssetManager、DraftEditor、ResponsivePanel。将地图/图纸/模型变成同一选择上下文中的视图，避免并列导航和重复目录。空间选择由 URL 承载，浏览器返回和复制链接可恢复。三维继续使用 Three.js，静止时按需渲染，模型实体保留可选、隔离、隐藏、剖切能力。

自制工程资料使用 Python、NumPy、IfcOpenShell 和 ReportLab：四类交通设施各有细化 GLB、IFC4 BIM、含尺寸与监测点位的多页 PDF、WGS84 GeoJSON。共同几何源导出 GLB / IFC，保证坐标和实体对应。重点桥梁采用 3 × 40 m、18 m 宽双幅箱梁工程假设，体现空心箱梁、墩台、盖梁、支座、基础和桥面附属设施；隧道体现衬砌、洞门和道路净空；边坡体现分级平台、框架锚固与排水；道路体现路基、铺装、护栏和排水。资料明确为自行设计的仿真工程，不是实测或可施工设计。

通过现有账号和正常上传、处理、关联、发布 API 加入当前本地验收系统，不清理已有资料和业务记录。可重入导入器记录 ID，避免重复生成。记录模型实体数、三角形数、尺寸、文件哈希、图纸页数、绑定关系和处理结果。

## 自验收

- 树可逐层展开、搜索保留祖先、键盘选择；换设施不泄漏上个设施的资料。
- 图纸、GLB、IFC 和 GIS 使用实际上传并发布的数据；刷新后关联保留。
- 测点有显式定位状态；未定位对象可看设施资料但不显示已绑定。模型选中实体与业务对象双向定位。
- 在树选定对象后进入标注，正确带入对象和设施；保存、版本复核和发布通过真实 API 完成。
- 导入、版本切换、下载、历史和权限失败提示正常；项目固定版本路径不受租户布局变更影响。
- 类型、lint、针对性单元测试和接口核验通过；浏览器检查桌面、窄屏以及三维总览/墩梁连接/横断面等近景，修正穿插、悬空、错位和遮挡。
- 完成后更新为 Awaiting acceptance，列出用户可直接打开的入口和人工验收步骤。只有用户确认后才记 Accepted。

## 人工验收步骤与边界

1. 打开青澜二桥，沿树选择「上部结构 → 第1跨箱梁 → 箱梁应变」。预期对象路径清楚，模型和图纸均显示该对象自己的关联；切换设施不会混入上一设施资料。
2. 切换「布设图」的第1/2/3页，放大检查平面、立面与典型断面；切换 IFC 和 GLB，使用聚焦、隔离、透明度、剖切检查梁墩支座与基础。必要时点「全景」恢复模型视野。
3. 搜索 `QL-WD-01`。预期 GLB V3 为已定位；换到 PDF 显示尚未定位，而不是因继承设施资料就显示已绑定。
4. 在任一设施中打开「导入设施资料」；预期所属设施正确。选择测点点击「调整定位」可创建下一草稿，保存并核对发布后刷新检查关系。
5. 浏览隧道、边坡和道路，核对模型细部；GIS 在同一选择器中切换工程图层与资源位置，查看共享 GIS。
