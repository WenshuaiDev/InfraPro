## 实施与兼容约定

- 在当前 checkout / 分支增量实现，保留已有工作区改动；不创建分支或 worktree。
- Go 领域服务、PostgreSQL / pgx / Goose 管理实体、固定版本、事务、权限与历史；监测继续使用既有 ClickHouse 引擎。React / TypeScript 扩展现有工作区，SDK / Bridge / devtools 同步增量契约，不升级依赖。
- 元模型 1 保持内容及摘要不变；元模型 2 显式声明断面和孔位支持性。模板逐固定类型版本声明适用性、锚点、后代测点范围和数量基准。
- 统一主结构边为唯一组织事实；旧构件父链成为最近构件投影。新增独立断面与孔位实体，保留旧对象、通道、来源和观测 ID。同设施锁、修订及预览摘要约束移动与类型采用。
- 分类独立于产品输出定义；固定字典发布版本，产品默认与设备覆盖分别保留修订和历史。批量操作固定预览对象集合。
- 正式位置不接受断面文本写入；原文逐条进入迁移核对证据，只有显式映射才形成实体引用。
- 项目新增种类必须明确授权；上下文祖先不计实体。新 SDK 结构范围显式使用 `structure_model=2`，旧读取采用标注的 legacy 投影；无法表示的新通道所有者返回升级要求。
- 统计明确 authorized / monitoring_bound、nearest / subtree、来源 / 安装、直接 / 包含计数；快照固定结构与分类依据，交付前仍重新授权。

## 实际实现及读取口径

数据库版本 54，新增迁移 47—54。元模型 1 的固定内容及摘要不改写；版本 2 的能力声明、模板映射和建议分类依据分别保存。设施采用始终固定到类型版本，同定义兼容采用需预览、复核资源／权限／引用，并记录采用历史。

平台设备分类保留稳定 ID、字典发布版本、产品版本默认和租户设备覆盖。字典新版本影响新查询的名称／路径解释；固定统计与下钻保留原字典和原成员依据。`authorized` 与 `monitoring_bound` 分别去重完整授权设备和当前独立获准来源设备，来源关系与安装关系分开处理。

设施主结构使用带种类的唯一父引用。构件、断面、孔位可穿插，构件数量约束继续按最近构件祖先判断。设备安装、派生所有者、空间定位及文件关联使用同一实体身份；直接通道仍归测点。孔内定位明确最近孔位、沿孔距离和垂直埋深，未知值保持空值；孔位无完整权限时不投影其定位依据。

断面可关联图纸／模型中的显式区域，模型断面也可记录明确平面；孔位可关联已有路径。几何来自输入坐标，不由孔深推算孔底。原测点挂载、构件模型关联及发布版本复制继续保留。附件固定到文件版本，交付每一块内容时重新检查宿主及文件权限。

大屏的新命名视图明确声明 `structure_model: 2`；完整树、统计、设备类别、观测分组和固定下钻使用同一授权依据。旧视图使用四种资源投影，缺省不扩充断面／孔位；遇无法表达的新派生所有者返回 `structure_model_upgrade_required`。资源详情允许传入 `kind`，同 UUID 对应多个完整可读种类时必须明确指定。父级选择不隐式扩大成员范围。

旧位置中的 `sections` 每次出现按来源表、来源 ID、修订、JSON 路径和序号保存。当前位置移除此字段，历史原文不改写。设备安装和工程详情均有核对入口，逐条保留待核对／历史依据／显式实体映射；同名不自动合并。

## 技术预算与验证边界

- 单设施结构资源及通道合计最多 100,000 个保留身份；主结构最多 512 层，测点附属通道可再深一层。超过预算明确拒绝，不截断成功结果。
- 分类字典最多 10,000 节点、128 层；分类批量操作最多 5,000 个明确目标。平台建模样例最多 500 个节点，与真实设施的运行预算分开。
- 大屏每个固定成员范围最多 50,000；目录、候选和固定查询分别分页。超过旧 500 目标的验证使用 623 个真实授权资源，620 个断面均进入统计与候选分页。
- 区域 3—64 顶点，孔位路径 2—512 顶点；模型平面需显式法向与尺寸。图纸坐标归一化，模型坐标遵循已发布模型变换依据。
- 本机合成规模和恢复验证不等于生产容量认证。所有浏览器计数与权限证据来自真实服务；模拟 SDK 仅用于外部开发模板。
