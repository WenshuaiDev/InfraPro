# 上传部署适配

状态：Awaiting acceptance。生产准备 B3 与整文件限额配置已经实现并通过自检，见[验证记录](../verification/upload-deployment.md)。默认值沿用当前行为，分片继续使用附件/空间 8 MiB、监测 32 MiB、大屏 4 MiB。

## 设计与范围

- Nginx 按上传、JSON 命令、合并、下载和事件流的实际路由设置请求体、超时及缓冲；三种部署模板从同一份规则生成，保留 HTTPS origin 和凭据隔离。
- Go 配置增加空间、监测 CSV/XLSX、大屏 ZIP 的整文件限额；普通附件沿用 `files.max_file_bytes`。YAML 与环境变量均支持，非法配置启动失败。默认值保持 256 MiB、32 GiB、512 MiB、128 MiB、100 MiB。
- 服务端向已登录客户端提供当前限额；TypeScript 上传器和大屏开发工具使用服务端策略。已有上传按建立时的文件大小继续分片，调整限额不使历史文件失效。
- PostgreSQL 增量迁移解除文件总大小及总分片数量的旧固定上界，保留正数、分片大小、关系及摘要约束。迁移不搬动历史对象。
- 后台处理和恢复按已接收的大小校验完整性。解析器的展开大小、像素、时间、内存等资源预算独立保留，上传大小配置不等于处理容量承诺。

## 技术与验证

沿用 Nginx 作为 HTTP/HTTPS 代理，Go 实现配置和上传校验，PostgreSQL 保存上传依据，现有私有 S3 保存分片与源文件；TypeScript/Node.js 实现客户端校验及真实代理自检。Python 空间转换器使用接收的源文件长度，不再重复套用固定 256 MiB 上限。

验证：真实 Nginx 四类分片边界、超限 JSON、上传/续传/下载摘要、流式转发、HTTPS 凭据边界；配置覆盖与非法值、超过旧限制的上传及分片编号、首装与升级迁移、历史读取/恢复、前端类型与契约、相关模块回归。生产安装及人工验收单独记录。

人工验收：经代理上传跨分片的四类合成文件，暂停/重选后续传并下载核对；修改整文件限额并重启相关 API/worker，新上传使用新限额，超限有明确提示，既有文件仍可读取。
