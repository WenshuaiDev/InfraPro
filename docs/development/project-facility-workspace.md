# 项目设施树形工作区

状态：**Awaiting acceptance**（2026-11-16 自检通过）。人工确认后才转为 **Accepted**。

## 目标与交互

项目设施列表与独立详情页合并为与租户设施管理共用的工作区：左侧设施、构件、测点、业务通道资源树，右侧当前对象的资料和操作。桌面两栏独立滚动；窄屏先显示目录，选中后显示详情，通过“返回资源目录”恢复选中项。

搜索覆盖项目可见的四种资源并保留祖先路径，按设施类型和资源状态筛选，目录及下级资源按需分页。数量来自服务端完整查询统计。资源、筛选和详情页签保存在 URL，已有 `component`、`point`、`channel`、`tab` 链接兼容。项目身份与切换入口保留在全局工作空间导航，移除本页重复的项目标题；归档提示保留。

资源操作沿用服务端能力判定，包括编辑、新增下级、生命周期、变更记录、设备来源、空间定位和监测入口。项目中不显示租户的项目使用授权、设备绑定总入口及删除记录筛选。已归档项目只读；撤权或项目切换清理相应缓存。

## 技术与数据流

- React、TypeScript 复用 `FacilityWorkspace`、`ResourceTree` 和 `WorkspaceDetail`；TanStack Router 管理导航状态，TanStack Query 管理分页、缓存和授权修订失效。
- 项目树接口 `GET /api/v1/tenants/{tenant_id}/projects/{project_id}/engineering/resources/tree` 使用 Go 现有权限事务和 PostgreSQL `project_resource_visibility`，复用租户树查询的分页、搜索、路径和统计实现。每次查询重新校验权限，游标绑定项目、成员与授权修订。
- `node_id` 与 `facility_id` 提供精确导航路径查询。完整详情接口保持原权限规则；项目成员只能定位祖先时，详情区显示“仅路径”和已授权下级，不读取或展示该祖先的完整业务资料。
- 沿用 PostgreSQL 现有资源和授权表，本次功能不新增数据库迁移。OpenAPI 与 TypeScript 客户端同步新增项目树路径。删除旧版项目列表、详情以及临时列表拼接树适配器。

## 人工验收

打开本机 [青澜大桥项目设施](http://localhost:25173/t/64a4ebf9-c549-4706-94a9-117333b62d4b/p/727da42a-b48d-4ddd-87f5-9805d49d9e9b/resources/facilities)。本机服务使用构建产物，启动方式见 [本机环境](../operations/local-environment.md)。

1. 依次展开设施、构件、测点并选择通道：目录高亮、面包屑和右侧资料一致，页面不再进入旧式分离详情页。
2. 搜索通道名称或编号：保留对应祖先路径；刷新、前进后退仍定位相同对象。清除筛选后可收起全部再定位当前资源。
3. 查看下级资源、设施变更记录及通道数据来源，打开编辑抽屉：权限允许的功能保留，关闭返回当前对象。
4. 切换项目或使用仅有项目权限的成员：不出现其他项目、未授权设施和通道；仅路径祖先不显示完整资料及写操作。
5. 缩窄至手机宽度：目录和详情切换正常，返回目录保留选择，页面无整体横向溢出。检查浅色和深色主题。
