# 派生监测工作台重构

状态：Awaiting acceptance（待人工验收）。原型 A 已正式实现并完成自检；人工验收尚未进行。

## 目标与范围

统一侧栏入口为“派生监测”，内部保留“监测通道”和“指标定义”。目录负责查找和识别，系统遮罩 Drawer 承载详情，完整编辑使用分步工作区。沿用当前 API、真实数据、租户／项目授权以及已归档项目的只读边界。

## 设计与技术

使用现有 React、TypeScript、TanStack Router／Query、Tailwind 和共享 UI 组件；使用 ResponsivePanel 保持系统 Drawer 的遮罩、键盘与焦点行为。继续使用现有 Go API、监测查询和计算服务，不调整存储、计算语义或发布协议。

- 统一路由工作区；旧指标定义链接和通道详情链接继续工作。无通道读取权限但有指标读取权限时进入指标标签。
- 通道目录以名称、归属、规则、最新输出、控制状态和更新状态呈现；详细时间范围、原始依据和配置身份移入详情。
- 通道 Drawer 分为监测概览、规则与输入、历史与依据、运行管理。新通道先选择对象和固定规则，再绑定输入、调整参数，保存后进入真实试算与启用预览。
- 指标目录与编辑分离。编辑分为基本信息、输入要求、计算规则、时间与质量、输出与发布；高级输入要求放入 Drawer，计算节点按需展开。保存、校验和发布保持可达，校验问题能打开对应步骤并定位。
- 发布固定版本后可以直接创建通道。创建通道时缺少规则，可以暂存当前表单上下文，完成定义后返回；不使用浏览器持久存储保存业务输入。
