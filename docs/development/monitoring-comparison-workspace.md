# 多通道比较：方案 A 正式重构

日期：2026-11-16。状态：**Awaiting acceptance**。用户已选择原型 A 并授权正式重构；实现和自检已完成，等待用户人工验收。

## 目标与实现方案

- 左侧为紧凑的设施与所属对象通道目录，保留跨设施、设施／构件／测点归属、直接／派生通道、全局搜索、分页加载和已选管理。目录只使用当前租户／项目的获准监测目录。
- 右侧首先展示时间控制和同一张趋势图，最新观测改为图下读数表；通道位置、精确值、方向、基准、派生结果状态与计算进度在详情中继续提供。
- 每个已选通道对应一条系列，最多保留原有 50 通道选择上限。取消兼容组切换与每页六条限制；不同单位以独立纵轴在同一绘图区显示，同单位共轴，枚举保留状态点语义。
- 稳定通道颜色与标记，同图图例可显隐和移除；选择增减不重置时间、质量、时区、显示方式和自动更新状态。相对幅度使用当前视窗已加载样本，提示与明细保留精确原值。
- 保留单通道主页面、前后时间窗／缩放、自定义纳秒时间、全部历史、自动刷新、数据概况、明细与统计分页、后台导出、撤销历史、错误重试、只读项目和撤权清空缓存。

## 技术与数据流

使用现有 React、TypeScript、TanStack Query、系统 Drawer 和 ECharts Canvas。目录通过 monitoringDirectory 按范围和服务端过滤游标加载；所选 ID 继续建立正式监测 selection 与 snapshot，趋势沿用时间块缓存、并发限制、摘要与 20,000 点总预算。图下极值来自当前窗口正式统计，不能用图表抽样值代替精确统计。

绘图模型独立描述单位轴、每通道系列、空值和精确十进制坐标；ECharts 负责同一绘图区的渲染和时间交互。空值、断点、摘要和派生无结果不补零、不伪造连接。全量 UI 与模型回归和真实本机数据浏览器检查分别提供证据。

不改变存储、计算规则或后端接口，不进行生产部署和迁移。当前分支与检出目录内完成，保留其他工作区改动。

本机服务已运行，刷新原来的 `http://localhost:25173` 页面，进入「监测浏览 → 多通道比较」即可。若服务已停止，按 `docs/operations/local-environment.md` 启动已有本机运行环境。

1. 在第 1 跨跨中勾选竖向位移、第一跨位移 30 分钟均值、第一跨与第二跨位移差，预期同一张图显示三个通道，图下是紧凑读数表。
2. 继续勾选温度、应变、变化速率和其他测点通道，预期第七个通道仍加入原图，不出现分组切换或曲线分页；不同单位有独立标尺。
3. 点图例隐藏／恢复，再移除或取消勾选，预期只影响对应通道；可切换相对幅度观察变化形态。
4. 设置历史时间、质量、时区和暂停自动更新后增删通道，预期条件保留；核对读数信息、明细、数据概况和后台导出，最后关闭比较，主页面原通道不变。
