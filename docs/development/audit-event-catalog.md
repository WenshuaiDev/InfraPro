# 审计事件目录与生产路径账本

由 `node scripts/audit-event-catalog.mjs` 根据 `audit:contracts` 的有限注册表和 AST 生产路径生成。注册表是允许写入的词汇，不表示每个词条都已在本次测试触发。本机操作及人工接受以 [环境说明](../operations/local-environment.md) 为准。

当前登记 422 个事件词条，扫描 146 个生产／域内记录位置。目录描述当前源码的披露契约，不保存某次执行结果。

## 公共字段、可见性与事务规则

所有事实保留服务端事件 ID、来源幂等键／效果、真实空间、动作／结果、发生与入库时间、operation_id、原发起人／本代请求人／执行身份、对象与修订、有限变化和显式关联。只有白名单字段可以进入快照；缺失、null、空集合、脱敏、截断分别表达。凭据、带凭据 URL、会话、文件正文、监测值与任意日志不进入事实。超过旧业务原因上限的审计摘要明确标记截断与摘要哈希，原业务收据协议不变。

`platform` 仅平台事实；`platform_tenant` 要求平台租户治理读取；`notice` 在租户空间只投影公开说明；`tenant`／`project` 精确成员资格；`governance` 为独立租户项目治理摘要；`entry`／`business` 使用实际来源归属，不能由前端指定。业务字段另外经过所属 Module 的当前元数据权限核对。technical 权限不增加业务可见性。`business_or_platform` 的平台任务仅允许 audit.export 和 parsing.test。

生产函数拥有业务事务；auditrecord 只加入该事务。任务、通知持久化失败与业务成功一起回滚。失败事实在已确认业务回滚后使用独立有界事务；提交未知先查原收据，不伪造失败。大屏受限处理以同事务 handoff 为来源事实，公共桥接不重做包处理。传输每个 GET/Range/HEAD/304 各有独立 receipt，开始和结束共享显式操作；超时未知不补造字节数。

| AM-14 | runtime,config,migrations,CLI | 有限适配器、SQL 角色、协议／保留策略、worker、显式维护计划、恢复工具、静态目录及真实样本。 |

## 不另写公共成功事实的路径

- 普通列表／详情／搜索／筛选快照／续期、前端轮询、上传分片、心跳和索引重放：不记录，避免递归与噪声；敏感正文传输单独记录。
- tasks 控制 Adapter：保持来源委托，公共成功只由原来源命令出口写；接受取消不等于已取消。
- notifications 投递尝试、偏好、已读与归档：保持原投递事实，不把私人收件箱状态复制成业务审计。
- display 订阅游标和遥测：保持域内运行记录，不将诊断日志升格为业务审计。包工作状态使用持久 handoff。
- *_changes 与 *_events：保留原领域历史／发布依据。下表列出每个直接 INSERT 位置，只有明确公共 Writer／桥接生产事实；不通过扫描记录名猜测跨空间关联。
- 目录中的旧动作别名和来源状态词汇保留有限兼容验证；无现存副作用路径的词条不作为新增功能或已执行证据。
