## 要回答的问题

项目角色如何与平台、租户角色页保持一致，同时将独立的项目权限目录合并为角色管理中的说明？

本轮只交付可体验的原型。三版使用同一份现有项目角色和权限数据，在现有 `/t/$tenantId/p/$projectId/roles` 路由中通过 `?variant=A/B/C` 切换。

| 方案 | 信息组织 | 适合验证的问题 |
| --- | --- | --- |
| A · 统一表格 | 共用平台／租户 `RoleTable`，角色详情使用带遮罩的系统 Drawer | 统一操作习惯后，列表密度和详情入口是否合适？ |
| B · 角色工作台 | 左侧连续选择角色，右侧显示权限、成员和资料；编辑仍使用 Drawer | 连续查看多个角色时，是否比反复打开抽屉更方便？ |
| C · 权限对照 | 同时对照最多四个角色，按业务分组展开具体权限 | 角色职责差异是否更容易判断？ |

## 实现与边界

- React / TypeScript 实现可丢弃的视图，源码在项目页面旁的 `roles-prototype*.tsx`。
- TanStack Router 管理 `variant` 参数；浮动切换条与左右方向键更新 URL，刷新保留方案。输入框、菜单、标签页和弹层内不截获切换按键。
- 保留项目角色页原来的 TanStack Query 读取、路由参数和身份边界；权限与成员通过已有 API 只读获取。
- Tailwind 与现有 shadcn/ui 组件保持颜色、字号、表格、筛选和表单一致；使用已有 Base UI `ResponsivePanel` 提供遮罩 Drawer、焦点和移动端适配。
- 角色创建、复制、资料编辑、启停、删除和权限调整只修改 React 内存状态，刷新清除。没有接入真实角色变更接口。
- 权限按业务分组展示中文名称、说明、敏感标记和管理员保留能力。编码默认隐藏，可展开或直接搜索；权限数量由接口数据计算。
- 原型模式下侧栏隐藏“项目权限目录”，入口归入页面“权限说明”和角色配置。未带 `variant` 参数的原页面保持现有行为。
- 原型使用开发环境开关和惰性加载。生产构建不包含原型视图和切换器。
- 本轮沿用当前分支和工作目录，不创建分支或 worktree；原型阶段没有进行正式重构或归档提交；用户选定 A 后，源码归档见本文顶部。
