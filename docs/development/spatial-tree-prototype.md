用户已选择方案 A，并授权正式重构和工程仿真资料制作。以下保留原型评审过程；正式实现与自验收见 [设施树工作台](spatial-tree-workspace.md)。租户入口现已使用正式工作台，不再通过 variant 切换原型。

## 要回答的问题

用「设施 → 构件 → 多层子构件 → 测点」作为唯一的对象导航，是否能让空间资料的导入、复用、绑定和定位更加清楚？

现有页面同时呈现功能标签、空间资料目录、工程对象目录、底图选择、版本和编辑动作。用户必须在多套导航之间建立对应关系。原型以对象树为主线，将资料选择、版本信息和绑定动作收敛到当前对象的上下文中。

## 建议与边界

1. **资料归属和空间绑定是两种关系。** 图纸、模型主要按设施导入和管理；同一份资料可绑定多个构件或测点，同一个对象也可关联多份图纸、模型或地理图层。
2. **沿树导航，不强迫逐层全部绑定。** 用户可以直接为深层测点定位。允许设施直属测点以及任意多层构件，不能为了界面整齐补出不存在的中间层。
3. **上级资料提供查看上下文。** 继承上级预览不能被记为下级已经定位。界面分别呈现「已绑定」「待定位」「未绑定」，并说明当前资料来自哪个祖先节点。
4. **绑定语义随资料和对象变化。** 设施关联整份资料；构件关联图中区域或模型实体；测点关联页码与坐标、三维锚点或地理位置。正式实现应使用对应编辑器。
5. **版本更新需要复核。** 正式实现应将关系固定到明确版本，升级后标记需要检查的位置，避免悄悄把旧坐标套到新图纸。
6. **跨设施资料保留共享入口。** 租户整体 GIS 底图、线路总图等可以作为共享参考资料由设施引用，不应为了按设施管理而重复上传。本轮原型集中验证单设施资料流程，未演示共享资料管理。
7. **保持租户资源语义。** 设施及其下级仍是租户工程资源。项目通过授权使用，不能在每个项目下复制一棵资源树。业务通道留在测点详情或监测入口，空间主树暂时到测点为止。

## 三套方案

| 方案 | 结构 | 更适合的工作 |
| --- | --- | --- |
| A：树与画布 | 左侧资源树，右侧对象路径、资料选择、画布和关联摘要；绑定用带遮罩的 Drawer | 日常查看、定位与维护，优先建议 |
| B：树形管理表 | 全宽树表同时显示资料、位置和状态；按需打开预览或绑定 Drawer | 集中检查未绑定对象、核对资料覆盖 |
| C：分步配置 | 设施列表加「导入资料 → 逐层绑定 → 检查关系」三步 | 新设施首次配置与交接检查 |

三个方案通过同一浮动工具栏及 `?variant=A/B/C` 切换。切换方案保留当前选择和内存中的演示修改；刷新或点击重置恢复示例。箭头快捷键不拦截输入框、树和对话框中的按键。

## 技术与文件

- 使用现有 React、TypeScript、TanStack Router 和 Vite。原租户路由与身份、权限边界保留，在现有空间工作台完成 hooks 后切换渲染分支。
- 使用 `@infrapro/ui` 的 Button、ResponsivePanel（系统带遮罩 Drawer）和 Lucide 图标，CSS 仅针对原型类名。
- SVG 只演示图纸、三维外观及 GIS 视图，不调用文件转换或真实渲染服务。
- 示例资源、导入和绑定数据只保存在 React 内存中。原型没有上传、保存、发布等业务 API 写调用。
- 仅开发模式加载原型；生产构建删除原型组件和切换条。
- 原型文件位于 `apps/console/src/features/spatial/tree-prototype*`，共享切换条为 `packages/ts/ui/src/patterns/design-prototype-switcher.tsx`。
- 按仓库约定在当前分支和检出目录工作，没有创建分支或 worktree，也没有提交其他工作区改动。

## 人工评审步骤

1. 打开 A，沿「青澜大桥 → 第1跨主梁 → 左幅箱梁」选择「梁底应变测点」。预期能清楚区分它的父级、资料来源与尚未定位的状态。
2. 点击「绑定 / 标注测点」，选择资料并在图中指定示例位置，确认绑定。预期树上状态和图上点位同时变化。
3. 切换到 B。预期能从同一层级的表格中查出尚未绑定的对象，刚才的演示关系仍存在。
4. 切换到 C，选「沿江公路东段」，按导入、绑定、检查步骤体验空设施配置。
5. 比较哪种结构最适合日常操作，以及是否需要将 B 的状态检查或 C 的首次配置流程合入 A。
