# 历史分析交互原型

2026 年 11 月 18 日。用户已选定 **C 按成果**。正式实现及验收流程见[历史分析成果工作区](historical-analysis-results-workspace.md)。

## 要评审的问题

工程人员第一次打开历史分析，能否自己选好测点和时间，算出一个能解释的数？同一项分析下周再做一次时，能否找到上次的方法和当时的成果？

## 从需求到页面

| 使用者要做的事 | 已有业务要求 | 原型里的入口 |
| --- | --- | --- |
| 回答一个历史问题 | 人工选定过去时段并发起分析。来自空间视图的已授权对象和时段可以预填，仍须由人启动。历史成果归属创建它的工作空间。 | 问题、测点、起止时间和明确的运行按钮。试算与生成成果分别可选。 |
| 确认数字怎样算 | 支持常用模板、算子组合和受限公式。输入可以来自原始观测或正式派生。单位、时间含义、方向、基准与质量必须与运算相容。 | 常用问题先给出自然语言算式。通道带单位、方向和来源。匹配、质量、小数位和第二项输出按需展开。 |
| 重复使用方法 | 保存草稿，校验输入和规则，固定执行版本。一次运行另选时段、质量和输出。单份配置支持多个输出。 | 可继续草稿、复用已有方案。原型将校验和固定版本合在一次确认中。时段或本次质量筛选可以独立更换。 |
| 解释计算结果 | 正式运行的全部指定输出完成后发布固定成果。结果带规则版本、快照、实际匹配、质量和缺值原因。历史专属的双向最近、未来基准、完整源范围应能解释。 | 结果先回答工程问题，再逐行展开输入与匹配依据。演示严格同时刻、双向最近和整段汇总。 |
| 复核或交付成果 | 补录或撤销后标示依据状态。人工重算可追加新版本，旧版本可复核、比较。结果与完整输入依据分别按权限导出。配置及成果可归档。 | 从成果换时段重算、比较版本、下载两类示例 CSV。真实目录的受限、归档与依据状态沿用工作空间返回值。 |

正式依据见[监测数据与派生分析 C-02 至 C-07](../requirements.md#derived-monitoring)、[空间联动及授权边界](../requirements.md#spatial-scope)和[历史分析与成果比较操作流程](../operations/derived-monitoring-and-analysis.md#历史分析和成果比较)。

## 三种待选设计

| 入口 | 用户第一眼看到什么 | 适合检验的任务 |
| --- | --- | --- |
| A 按问题 | 三个能直接回答的工程问题，点击后才显示所需测点和时段。 | 新用户独立完成一次两跨位移比较。 |
| B 按测点 | 测点目录和观测预览并排，选中输入后在同一工作区更换计算方法。 | 已经知道工程部位，尝试不同测点组合。 |
| C 按成果 | 左侧成果目录，右侧查看固定时段的结论、依据与版本。 | 先复核上次结果，再复用方法计算另一个时段。 |

## 原型边界与评审

复用 React、TypeScript、TanStack Router 和管理端工作空间外壳。三个视图挂载在同一个历史分析地址，用底部切换条或左右方向键切换。样例桥的数据、草稿、试算和版本在内存中管理，真实工作空间目录只读。用本机已有会话评审。实现时仍需沿用现有 Go 计算服务、输入授权、完整后台执行和固定快照机制。

常用流程默认按相同时刻匹配，并展示减法顺序。计算设置可改质量、精度、匹配方式、容差及输出项，自定义计算式可试 `a-b`、`b-a`、`abs(a-b)`。固定方案可在“方案与成果”中复用。完整算子库和任意受支持的公式组合、正式派生输入、未来固定基准、空间预填、归档写入和后台 Parquet 导出，在正式开发时对接现有能力。

## 原型评审记录

三种原型的[评审源码快照](../../.artifacts/historical-analysis-prototype/accepted-source.tar.gz)已留存在本机。日常使用从租户或项目工作空间的“监测数据 → 历史分析”进入。以下为原型阶段记录的示例场景。

1. 在 A 点“两处位移相差多少？”，保留第一跨减第二跨及全部样本，点“试算看看”。07:10 的差值为 −0.2100 mm，交换测点后是正值 0.2100 mm。
2. 展开 06:40。示例第二跨在 06:40:08 采样，相同时刻规则给出缺值原因。改用双向最近并设 15 秒容差，结果采用晚 8 秒的样本，依据中可见原时刻。
3. 点“生成这份成果”，再点“换时段再算”并选择后半小时。新旧版本均在“方案与成果”中可查，“版本比较”显示输出时间、数值或依据的差异。
4. B 可以从第三跨开始选一个测点计算整段平均值。C 可以先复核已存结果、输入样本和版本，再决定是否重算。

## 原型自检

管理端 TypeScript、相关文件 ESLint 和独立目录的生产构建通过，构建产物排除了演示页面。浏览器在租户和项目入口完成 14 组交互检查，包括 1440 像素桌面、390 像素手机和 360 像素深色界面。自检核对了差值符号、缺值、8 秒匹配依据、草稿、固定方案、试算、成果版本比较与两类 CSV。交互过程中记录到 0 个页面异常和 0 次分析业务写入。
