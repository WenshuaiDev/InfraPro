# 工程资源操作与人工验收

对应[详细方案](../requirements/engineering-resource-management-plan.md)。本轮真实对象由租户统一维护，入口为“租户工作空间 → 工程资源 → 设施管理”。页面使用同一 console，开发地址 `http://127.0.0.1:5173/`，部署使用既有 `/console/` 基础路径。自动验证和人工验收分别记录在[自验记录](../verification/engineering-resources.md)。

## 1. 升级与启动

已有环境先备份数据库、配置及旧应用，停止旧 API 的写入；先在隔离库恢复备份、核对存量及增量升级，再执行：

```bash
pnpm infrapro database migrate
pnpm infrapro access sync --dry-run
pnpm infrapro access sync
pnpm infrapro access check
make dev
```

本轮新增 `00009_engineering_resources.sql`，资源表初始为空，不将定义样例转换为设施。完整权限目录为 90 项；租户管理员显式获得资源查看和维护权限，普通成员不因此获得资源权限。`/healthz`、`/readyz` 均应返回正常。已有环境不重复执行 account bootstrap。首次安装仍按项目 README 的本地初始化步骤配置。

本机实际迁移、备份恢复和访问检查的结果以自验记录为准；上述命令本身不代表已经运行。迁移不改写既有账号、密码、会话、租户、项目与工程定义。权限目录未同步或数据库版本不匹配时 readiness 失败，不在 API 启动时自动修复。

回退优先前向修复。v9 禁止通过 Down 删除资源与历史。需要恢复时停止写入，将备份恢复到新数据库，比较四类资源、定义版本、编号墓碑、历史和收据，使用匹配构建验证后再切换连接；按账号运维约定撤销恢复前的访问凭据。不能仅因 dump 文件存在就认为恢复通过。

## 2. 权限与验收准备

在测试租户 A、B 中使用已有账号准备以下角色和成员；使用独立浏览器配置文件切换身份，避免共用会话：

| 角色 | 本租户权限 |
| --- | --- |
| 资源维护员 | `tenant.engineering.resource.read`、`tenant.engineering.resource.manage`、`tenant.engineering.catalog.read` |
| 资源只读员 | 仅 `tenant.engineering.resource.read`；可以解释已有资源采用的版本，不能任意浏览目录或创建对象 |
| 普通成员 | 不授予资源权限 |
| 平台账号 / 项目管理员 | 不额外授予租户资源权限，单凭该身份不能读取资源 |

由有权平台人员在“工程配置”准备两个已发布设施类型，编号自行命名，其中一个类型包括：

- 根属性：必填数值“设计长度”，默认值可设置为 0。
- 构件类别：跨、梁；允许“设施整体 → 跨”和“跨 → 梁”；跨的参考最少数量 2、最多正常数量 2。
- 另一个类型使用不同名称、属性或类别，检验数据驱动能力。

另准备一个已发布长度单位、允许该单位的数值指标，以及不使用单位的枚举指标。均为测试资料，不导入现场项目数据。管理员可通过既有定义页面完成，无需改代码、改表或重新构建。

| 用户名 | 用途 |
| --- | --- |
| `er_maintainer` | 租户 A 资源维护员，建议从此账号开始第 5 节验收 |
| `er_reader` | 租户 A 资源只读员，无公共目录读取权 |
| `er_member` | 租户 A 普通成员，无资源权限 |
| `er_project` | 租户 A 中已任命的项目管理员，无租户资源权限 |
| `er_admin` | 租户 A 管理员，用于角色和成员管理 |
| `er_other` | 租户 B 管理员，用于跨租户隔离 |
| `e2e_owner` | 仅此隔离环境的平台管理员，用于发布 V2、停用定义和检查平台审计 |

密码在本机 `.artifacts/resources-v9/accounts.local.json`（权限 0600）；不复制到 Git 或文档。精确租户/设施链接记录在 `.artifacts/resources-v9/acceptance-fixture.json` 的 `urls` 中。使用独立浏览器配置文件验证不同身份；同一主机端口间 Cookie 可能共享，请将验收环境与 `5173` 的常规使用分开。

测试环境存续于本次测试服务进程，停止该进程会清理隔离 schema。验收数据不进入常规本机库；需要重新准备时，先关闭占用 `18080/15173` 的隔离测试服务，重新运行 `node scripts/e2e-server.mjs`，另一终端运行 `API_PROXY_TARGET=http://127.0.0.1:18080 CONSOLE_PORT=15173 VITE_API_BASE_URL=/api/v1 pnpm --filter @infrapro/console dev`，就绪后运行 `node .artifacts/resources-v9/prepare-acceptance.mjs`。重新准备会生成新的隔离数据与密码文件，不是恢复上一次人工操作。

## 3. 正常使用

1. 新增设施，选择明确的类型发布版本，输入编号、名称和当前必填属性。保存后直接打开设施工作页；空构件、空测点均为正常状态。
2. 左侧选择“设施整体”或构件，再新增构件、添加测点。窄屏使用“选择设施整体或构件”展开选择区。树按直接子项分页加载，Tab/Enter 选择，左右方向键展开/折叠，不受样例的 500 节点上限限制。
3. 新增构件时选择固定类别；参考最少数量不阻止保存，最多数量仍校验。构件、测点的编辑表单可选择同设施归属；已有子项和通道身份保留。
4. 查看测点后添加业务通道。数值指标选择其允许的固定单位；枚举指标不选择单位。可添加多个同指标通道，以不同编号区分。选择统计区间结束时刻必须解释区间含义。
5. 名称、说明和计划采样可编辑；通道指标、单位、时间含义、统计含义、观测方向和基准固定，语义变化时另建通道。计划采样只记录配置，不下发设备命令。
6. 位置资料整体可留空。填写地理、投影、高程或局部坐标时同时填写相应基准；真实 0 不会被当作未填写。路线桩号保留原标注；两种断面都需要明确参照。所属设施位置单独标为参照，不写入测点自身位置。
7. 对象菜单包含编辑、退役、恢复和删除。退役/恢复/删除需填写原因；任一祖先退役后，后代只读。恢复祖先不会恢复原本自行退役的子项。
8. 有未删除子项时禁止删除，包括退役子项。无引用误建叶子可以软删除；编号永久保留。本轮没有恢复删除。
9. “设施变更记录”查看设施及后代的前后值、操作者、时间与原因。展开“查看前后值”可读取当时采用的类型、指标、单位及枚举含义，固定版本及依赖停用后仍可解释。已删除设施可从列表“已删除记录”进入历史；普通详情仍不可访问。资源只读员无需公共目录权限即可读取这些历史引用，接口不接受任意版本查询。

编号去除首尾空白，以 ASCII 小写判重；允许字母、数字、点、下划线、连字符，首位字母或数字，最多 64 字符。名称最多 200 字符，一般说明最多 2000，来源说明最多 1000。每组位置数组最多 20 项；单个请求最多 256 KiB，属性最多 128 KiB，位置最多 32 KiB。这些是输入边界，不是租户数量额度。

## 4. 并发、故障和版本

两窗口编辑同对象时，后提交的旧修订返回冲突且输入保留。点击“检查连接并重新读取当前记录”，核对服务端名称及变更记录，再点击“已核对，按当前记录继续编辑”；不会自动覆盖、合并或丢弃本地表单。

网络故障时禁用保存并保留输入。先用“核对本次提交结果”查询收据：查到表示原命令已经提交，随后读取当前对象；未查到不等于保存成功。需要继续操作时检查连接；手动重试相同内容沿用请求编号，修改内容产生新请求。写请求不会自动重试。

发布 V2 不会改变已有资源的 V1 引用。类型停用后，既有设施仍可维护并按其原结构增加构件/测点；新设施不能采用停用版本。指标/单位停用后原通道仍能改名称、说明和计划采样，新通道不能采用不可用版本。

## 5. 人工验收步骤与预期

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1（MA-01、02） | 在租户 A 新增设施，填写必填属性，暂不建构件和测点 | 保存即为正常设施，普通空态，无草稿、建档任务、完成度或发布步骤 |
| 2（MA-03） | 在最少数量参考为 2 的类型下只新增一跨，再为其添加测点 | 均保存成功，没有待完善或最低数量警告；测点归属路径准确 |
| 3（MA-04） | 尝试在设施整体下添加梁，再尝试添加第 3 个正常跨 | 明确拒绝非法关系/超过上限；已有对象不丢失 |
| 4（MA-05、06） | 选中构件添加测点，不添加通道，刷新深链接 | 测点正常，归属与选择保留，显示“暂无业务通道” |
| 5（MA-07） | 为测点添加两个同指标不同编号通道，再添加枚举通道 | 两个数值通道独立保存；只能选允许单位；枚举不使用单位 |
| 6（MA-08、09） | 录入路线、桩号、两类断面及带基准的零坐标；另建坐标留空测点 | 原资料及参照保留，真实 0 保留；新测点自身坐标为空，设施坐标仅作为参照 |
| 7（MA-10） | 修改名称或位置，纠正测点归属，查看历史 | 身份和通道关系不变，前后值及操作者可查 |
| 8（MA-11） | 平台发布类型 V2，再打开旧设施；停用 V1 后维护旧设施 | 旧设施仍解释 V1；可以维护旧实例，新设施不能采用停用 V1 |
| 9（MA-12） | 两窗口打开同一对象并分别修改 | 后提交旧修订返回冲突、输入保留；核对后可继续提交 |
| 10（MA-13） | 先退役一个测点，再退役设施；尝试改后代，然后恢复设施 | 后代只读且自身状态不被改写；恢复设施后原退役测点仍退役 |
| 11（MA-14） | 删除含测点的构件；再删除无引用误建叶子 | 前者显示依赖种类/数量；后者软删除，历史仍可读，同编号不能复用 |
| 12（MA-15） | 切换只读员、普通成员、租户 B、平台账号和项目管理员 | 只读员能读已有引用但不能修改；其余无租户资源权限者不可读；平台审计不泄露资源名称、位置和历史 |
| 13（MA-16） | 检查工作空间、窄屏、键盘选择和长名称 | 仅租户有工程资源入口；无独立方案、模板应用、项目地图、图纸/模型绑定按钮 |

未通过的步骤反馈后在本轮修复。只有用户明确确认功能验收，才将状态改为 Accepted。

## 6. 范围边界

本轮没有项目资源使用授权、设备或数据来源绑定、采集与观测存储、图表告警、地图或坐标转换、图纸/三维模型上传绑定、独立监测方案、模板批量生成、配额和审批，也没有类型版本迁移、历史回滚或恢复已删除对象。已有工程定义与模板的发布机制继续保留，实际资源没有发布流程。
