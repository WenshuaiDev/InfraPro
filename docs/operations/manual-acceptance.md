## 1. 直接开始

验收入口：<http://localhost:25173/login>。

账号密码、每个样例的精确链接以及一次性邀请，已写入仓库下 `.artifacts/manual-acceptance/账号与验收入口.local.md`。文件仅本机可读且被 Git 忽略。先打开该文件复制密码，无需自行开户或录入初始数据。

建议按以下顺序使用三个主账号：

1. `accept_admin`：从左上工作空间切换器选择“验收·华东交通监测中心”，验收成员、角色、工程资源及私有模板。
2. `accept_platform`：通过工作空间切换进入平台，验收账号、角色、租户治理、公共工程定义和审计。
3. `accept_project`：从左上工作空间切换器选择项目，验收项目资料、成员、角色、归档和交接。

这是独立的持久化环境，使用当前工作区代码。原开发入口 `127.0.0.1:5173` 和原工程资源临时环境 `127.0.0.1:15173` 的账号数据不适用于这里。请始终使用 `localhost:25173`，不要替换成 `127.0.0.1:25173`。同时验收两个账号时使用不同浏览器配置文件，或普通窗口与隐私窗口；同一浏览器的普通标签页共享登录状态。

## 2. 账号分工

所有用户名以 `accept_` 开头，密码各不相同，见本机账号文件。

| 用户名 | 已准备的身份与用途 |
| --- | --- |
| `accept_platform` | 平台管理员；能治理平台和发布公共定义；没有租户成员资格，不能直接读租户私有业务 |
| `accept_admin` | 租户 A、C、D 管理员；A 的主要业务验收账号；不自动获得项目业务权限 |
| `accept_project` | A 的普通成员及三个项目的管理员；无租户资源权限 |
| `accept_engineer` | A 的工程资源维护与资料维护多角色成员；同时是 B 的普通成员，可检查多租户切换 |
| `accept_reader` | A 的资源只读员，没有公共工程目录权限；主项目资料只读员 |
| `accept_other` | B 管理员，用于隔离验证 |
| `accept_audit` | 平台账号、角色、租户与审计只读 |
| `accept_editor` | 公共工程编制员，可保存草稿，不能发布或启停 |
| `accept_template` | A 的私有模板编制员，可复制、修改，不能发布 |
| `accept_project_editor` | 主项目资料维护与只读双角色成员，可检查权限合并与操作记录 |
| `accept_member` | A 普通成员，无资源维护权限；主项目普通成员 |
| `accept_invitee` | 有账号但尚未加入 A，保留了一条定向邀请供本人确认 |
| `accept_suspended` | A 的已暂停成员；账号仍正常，可恢复成员关系 |
| `accept_removed` | A 的已移除成员；保留历史，可重新邀请 |
| `accept_disabled` | 账号已停用，不能登录；平台管理员恢复后可验收原关系 |
| `accept_spare` | 租户/项目管理交接候选人，也是项目业务负责人；负责人身份本身不增加管理权限 |
| `accept_personal` | 独立的个人资料、改密、会话和恢复密码练习账号 |
| `accept_noauth` | A 中成员关系有效但已清空全部角色，只能查看本人授权状态 |

先完成查看和权限检查，再进行停用、移除、交接、改密等操作。建议在名称带“练习”的租户/项目上执行交接；可自行新建资源做删除练习。变更原因填写“人工验收 + 操作说明”，便于检索记录。

## 4. 手动验收顺序与预期

| 步骤 | 使用账号、操作及样例 | 应看到的结果 |
| --- | --- | --- |
| 1 登录与个人资料 | `accept_personal` 登录，修改显示名称，刷新页面；退出后重新登录 | 显示名称保存，用户名不可变；退出后原页面需登录 |
| 2 账号安全 | 用普通及隐私窗口登录 `accept_personal`，查看账号安全并撤销另一会话；最后练习改密 | 会话列表能区分当前会话；撤销后另一窗口失效；改密后使用新密码登录，安全记录可查。自行记下新密码 |
| 3 开户邀请 | 退出账号，在本机账号文件打开开户邀请，注册 `accept_newuser`；再次使用旧链接 | 第一次开户成功；一次性链接不能重复开户；新账号没有平台管理资格 |
| 4 平台账号治理 | `accept_platform` 搜索 `accept_disabled`，恢复后尝试登录；检查账号角色、权限来源 | 状态恢复后可登录；角色与个人权限来源清楚；停用/恢复有原因和审计 |
| 5 平台角色 | 查看自定义及预置角色、权限说明、停用角色；创建/复制练习角色并配置权限 | 权限按分组展示，可见作用范围；内置角色受到保护；自定义角色变更记录可查 |
| 6 平台只读 | `accept_audit` 查看账号、角色、租户与审计 | 有权读取，不能创建、配置角色或停用账号；租户私有资源不可访问 |
| 7 租户建档与资料 | `accept_platform` 查看四个租户并新建练习租户；`accept_admin` 修改 A 的说明 | 建档需要名称、编号、管理员；当前资料及前后值在相应审计中可查 |
| 8 编号保留与交接 | 在 D 将编号改为 `acceptance-d-new`，尝试让新租户使用旧编号；将 D 管理员交给 `accept_spare` | 旧编号仍保留；交接生效，原管理员失去 D 的管理员权；A 不受影响 |
| 9 租户启停 | 平台查看 C 的停用说明和影响预览，然后恢复；再次停用/恢复 C | C 管理员停用时只见状态；恢复后原关系保留；个人资料与 A 继续可用 |
| 10 成员邀请 | `accept_invitee` 打开本机文件中的成员邀请，核对后确认加入 A；换账号打开相同链接 | 正确本人确认后才加入；错误账号不可领取；接受历史可查。不要在完成本步前重新生成这条邀请 |
| 11 成员生命周期 | `accept_admin` 恢复 `accept_suspended`，重新邀请 `accept_removed` 并由本人确认；查看历史 | 暂停恢复沿用关系；移除后重新加入产生新关系，旧历史保留；原管理员不能直接暂停或移除 |
| 12 租户角色与无授权 | 查看 `accept_engineer` 的两个自定义角色及权限来源，配置一个练习成员；登录 `accept_noauth` | 多角色权限合并；清空后仍是成员但无业务权限；无授权账号显示本人授权状态 |
| 13 多租户/多窗口 | `accept_engineer` 分别打开 A、B；两个窗口在 A 编辑相同资料，先后提交 | A 可维护资源，B 只有普通成员权限；窗口上下文不互相串用；旧版本提交冲突并保留输入 |
| 14 项目治理 | `accept_admin` 查看 A 的项目治理，打开主项目；再用 `accept_project` 从左上工作空间切换器进入项目 | 租户管理员能治理但不自动读项目业务；项目管理员能进入主项目成员、角色和审计 |
| 15 项目授权 | 项目管理员查看主项目成员；用 `accept_project_editor` 编辑资料、用 `accept_reader` 查看 | 协作员可编辑且有双角色来源；只读员不能修改；业务负责人 `accept_spare` 不自动获得管理员权限 |
| 16 项目归档与交接 | 项目管理员打开已归档北山隧道一期，恢复；在练习项目添加 `accept_spare`、练习暂停/恢复/移除，再添加并交接 | 归档保留合法读取，常规写入受限；恢复后可以管理；成员历史保留，交接后新管理员生效并可查历史 |
| 17 工程定义与动态属性 | 平台打开梁式桥梁、边坡、隧道和路面；预览桥梁属性、增加样例构件 | 不同类型由配置驱动；八类字段、必填零/false、日期时区和构件关系正确；样例不会变成实际设施 |
| 18 编制/发布分工 | `accept_editor` 修改涵洞草稿；平台管理员发布它；查看桥梁 V1/V2 差异 | 编制者能保存但没有发布权；发布产生固定版本；V2 增加养护等级，旧版本仍可解释 |
| 19 模板复制与隔离 | `accept_admin` 打开 A 私有模板、对比公共来源；`accept_template` 编辑私有草稿；`accept_other` 查看 B | 私有副本有来源记录并可独立修改；编制者不能发布；A/B/纯平台账号不能互读私有模板 |
| 20 定义启停影响 | 平台预览停用类型/指标的影响；使用“停用类型（恢复练习）”做恢复操作 | 原因和依赖影响清晰；不可用版本不能新采用；恢复要求依赖可用 |
| 21 工程资源树 | `accept_engineer` 打开青澜大桥，选择跨、梁、测点和通道；刷新精确链接 | 两跨三梁、整体/构件测点及通道可读；选中上下文和固定 V1 引用保持；V2 不改写旧设施 |
| 22 空态及构件校验 | 在“空设施”新增一跨及测点；检查“单跨参考数量”设施；在青澜大桥尝试第三跨或根下直接加梁 | 一跨和无通道测点均正常；最少数量是参考，最多两跨和父子关系仍严格校验 |

## 5. 重启、维护与数据保留

服务已启动时直接访问。若停止或电脑重启，在仓库根目录执行：

```bash
docker compose --env-file .env -f deploy/compose/local.yaml up -d --wait
node scripts/acceptance/start.mjs
```

按 Ctrl+C 只停止本次启动的服务，不删除数据库。端口占用时命令报错，不抢占其他服务。当前运行的 API 构建位于 `build/acceptance/api`；Go 代码变化后先停止验收服务，执行 `node scripts/acceptance/setup.mjs` 更新构建/迁移，再启动。setup 在已有环境不重建账号，不重置密码。

维护命令显式绑定验收库，防止误操作普通开发库：

```bash
node scripts/acceptance/ops.mjs access check
node scripts/acceptance/ops.mjs account find --username accept_personal
node scripts/acceptance/ops.mjs account reset-link --username accept_personal --reason '人工验收：本人密码恢复练习'
```

重置链接只能由现有 CLI 在交互终端显示。需要核验密码恢复时再生成；其默认有效期 30 分钟。开户和成员邀请默认 24 小时有效，过期后用对应管理员在页面重新生成，旧链接不会恢复。

`seed.mjs` 已完成后重复运行会直接退出，保留用户的修改。不要删除配置或准备状态文件，也不要运行 Docker 的删卷操作。数据库是 `infrapro_acceptance_20261110`，与普通开发库分开；没有自动清空或定时销毁行为。

本轮未部署生产，不包含实际数据采集、告警、地图或模型功能；也没有替代生产备份、迁移演练和 Safari/Firefox 验证。请反馈使用的账号、步骤编号、页面提示及预期差异；只有用户明确确认后，功能状态才进入 Accepted。
