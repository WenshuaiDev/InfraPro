已有环境从仓库根目录启动：

## 2 全新环境

仅在没有现有数据、配置和初始账号时，执行：

```bash
make install
pnpm setup:local
pnpm infrapro account bootstrap
make dev
```

`setup:local` 包含迁移、权限同步和目录检查；`bootstrap` 在交互终端创建第一个账号，没有默认密码。已有环境不得重复 bootstrap 或清库。新账号通过账号开户邀请自行设置凭证；已有账号加入租户仍使用租户成员邀请，由被邀请人明确确认。

## 3 其他已有环境的升级与回退

1. 记录应用版本、数据库版本和存量授权检查结果。备份数据库、配置和匹配的旧应用，并在隔离库实际恢复核对。
2. 停止旧 API 写入，部署同一版本的 API、CLI 和 console；不让旧版本与新的 project 范围约束混跑。
3. 从配置正确的仓库根目录执行：

```bash
pnpm infrapro database migrate
pnpm infrapro access sync --dry-run
pnpm infrapro access sync
pnpm infrapro access check
```

4. 确认迁移版本 7，71 项权限、13 个内置角色；新增 3 项租户治理权限、21 项项目权限和 5 个项目预置角色。租户目录现为 13 项普通能力、9 项保留能力。既有自定义角色不会自动扩权。
5. 核对原账号及凭证、会话、租户成员、邀请、角色、绑定和审计，确认没有虚假项目；启动服务并验证就绪、创建、授权和归档闭环。

目录发布若会给归档项目或上层失效成员增加能力，预检会阻止发布。先明确处理真实授权，再重新预检，不能绕开检查写数据库。

迁移 v7 拒绝可能丢失项目数据的向下回退。失败优先前向修复；确需恢复时，应停止写入，使用已验证的备份与匹配旧应用，并明确恢复点之后写入将丢失。恢复及凭证撤销遵循[账号运行手册](account-management.md)。本次本机 v6 备份和配置在 `.artifacts/project-management/`，权限为 0600；不得提交到 Git 或分享其中的凭证。

## 4 人工验收准备

使用隔离测试数据和独立浏览器配置文件，避免不同账号共享同一登录 Cookie。已有本机数据不包含自动生成的验收项目。

准备平台治理人员 P、租户 A/B、租户管理员 TA/TB、甲（项目筹建）、乙（项目管理员）、丙（负责人及后续普通成员）；乙、丙加入 A，乙另加入 B。一个人可兼任准备角色，但验证“无隐式权限”时必须使用不同账号。

P 在平台“账号与邀请”创建开户邀请，被邀请人完成开户；TA/TB 在租户“成员邀请”邀请相应账号并由本人接受。TA 在“租户角色”创建筹建角色，只选 `tenant.project.read`、`tenant.project.create`，然后通过成员详情给甲绑定。可以不授予租户资料编辑能力。

危险变更统一先预览、填写原因、确认；要求近期密码时输入当前密码，重新检查预览后再次手动提交。密码确认不会自动重放写入。预览过期使用“重新读取并比较”；结果未确认时保持内容和请求不变重试，或先核对记录。

| 2 | 创建 A2、B1，给乙不同项目职责；分别从我的项目及租户治理进入 | 列表范围不同；切换后上下文、角色及操作随项目变化，不串用 A1 权限 |
| 3 | 乙从 A1 成员页添加丙，再重复添加 | 首次建立关系并显式授普通成员；重复被阻止。外租户成员不能选择或添加 |

| 13 | P 停用 A，乙切换 B1 或个人资料，再恢复 A | A 项目业务关闭，B1/个人功能按自身资格可用；A1/A2 的运行或归档状态保持 |

## 6 应急停用及管理空缺恢复

仅对专门的验收账号演示，并保留至少一个可用平台治理人员。命令调用与 HTTP 共用账号状态事务：

```bash
pnpm infrapro account disable --username <验收管理员用户名> --reason '项目管理员应急验收' --emergency
```

普通项目管理员不可用：TA 进入“项目治理”，勾选“仅管理员不可用或空缺”，打开治理详情→“恢复项目管理员”→选择有效租户成员→预览、原因、确认。

若不可用账号同时是租户管理员（D-12）：P 在平台租户详情选择“交接管理员”，预览其全部项目影响，明确勾选受控修复确认，提交给新租户管理员；原租户及项目关系结束、绑定撤销，并记录项目管理空缺。若租户已停用，P 先恢复租户；新租户管理员再逐项目恢复管理员；已归档项目仍归档，由恢复后的项目管理员单独决定是否恢复项目。该链路已有真实数据库自动证据，无需用户手工修改 SQL。

如需恢复该验收账号：

```bash
pnpm infrapro account enable --username <验收管理员用户名> --reason '应急验收完成'
```

账号启用不复活旧会话或已经结束的租户/项目关系，需要重新登录并按当前资格使用。
