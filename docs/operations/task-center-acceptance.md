# 任务中心合成人工验收

状态：**Awaiting acceptance（待人工验收）**。2026-11-13 完整自动自验及 12 项浏览器旅程通过，当前合成环境覆盖 14 类、62 个任务；人工接受必须由用户另行确认。

## 启动与材料

在仓库根目录执行 `pnpm tasks:demo`。脚本启动独立 PostgreSQL schema、ClickHouse 数据库、S3 前缀、API、控制台、业务执行、通知和任务索引进程。使用仓库生成的 CSV、PDF、PNG/JPEG、GLB、IFC2X3/IFC4、GeoJSON 和最小大屏包，不需要用户提供业务材料。空间转换器首次使用需先执行 `pnpm spatial:setup`。

控制台固定为 `http://127.0.0.1:15573/tasks`；API 在 18573，大屏 shell/package 在 15870/15871。端口被占用时脚本报错并保留已有进程，不自动结束其他开发或验收环境。只清理自己创建的隔离数据。

本机被忽略目录 `.artifacts/task-center/lab/` 中：

- `accounts.json`：A、B、M 的合成账号和临时密码，权限 0600。不复制到仓库或截图。
- `task-acceptance.json`：成功生成的来源类型、任务编号、租户／项目和来源引用。`complete:true` 且 `sourceTypes` 覆盖 14 类才表示准备完成。
- `session.json`：实际地址、当前进程状态；`server.log`：本次实验室日志。
- `notification-acceptance.json`、`derived-acceptance.json`、`spatial-acceptance.json`：原业务样本的对应关系。

准备完成后终端输出访问地址与凭证文件位置。Ctrl+C 正常停止本环境并清理隔离数据；再次执行会生成新环境，旧任务链接不再适用。`pnpm tasks:browser` 自动创建、验查并清理自己的环境；若上述 demo 已运行，使用 `INFRAPRO_TASK_LAB_REUSE=1 pnpm tasks:browser` 复用它并保留环境。

本实验室的运维诊断可直接使用隔离配置：

```bash
INFRAPRO_CONFIG=.artifacts/task-center/lab/operator.json go run ./tools/infrapro/cmd/infrapro tasks status
INFRAPRO_CONFIG=.artifacts/task-center/lab/operator.json go run ./tools/infrapro/cmd/infrapro tasks verify
```

这里直接调用 CLI，避免 `pnpm infrapro` 自动加载仓库 `.env` 后覆盖实验室数据库地址；生产运维仍按显式环境覆盖配置文件的既有规则执行。预期 status 为 ready、六个来源 complete，verify 为 true。

## 操作步骤

1. **跨空间与筛选**：A 登录后打开任务中心。应看到两个租户的任务；进入一个原监测工作空间，再由顶栏任务入口返回，点击“当前工作空间”只显示该空间，“全部工作空间”恢复汇总。按状态／类型／提交时间／检索筛选，刷新后 URL 保留条件。
2. **原入口兼容**：从导入批次的“查看任务”打开导入校验，或从原监测任务 URL 的 `?job=` 打开同一详情。状态与统一入口一致；“打开原业务详情”回原批次。校验完成仍需原批次确认采用，completed_noop 不代表新增数据。
3. **查询与导出**：A 打开“后台精确查询”，结果入口进入原监测任务详情的“固定查询结果”，保持原快照／水位；普通导出进入原文件清单。下载继续执行原业务检查。快查询不产生新的持久任务。个人查询快照按原规则在 15 分钟后到期，较早样本显示过期属于预期；重新运行验收脚本会通过原业务生成新的固定查询，不延长或修改旧快照。
4. **失败、理由与代次**：A 打开失败的大屏包，填写理由后重试。只增加一代，旧失败和尝试仍在；包校验就绪仍需到原大屏页面明确发布。打开旧代后无重试／取消按钮，刷新仍停留旧代。
5. **通知定位**：打开该包重试前的任务通知，再点击“打开业务页面”，应定位原失败代，而非新的执行结果。原通知已读状态独立保留。旧 v1 通知若没有代次，会明确显示历史限制。
6. **计算与空间**：B 按类型检查派生试算、历史回算、原依据回放、历史分析试算／正式运行／比较、分析成果导出、计算依据导出和空间处理。每项都有真实来源与专业结果入口。空间转换完成不自动发布版本；自动派生不出现在 mine，可在“运行概况”进入原来源工作区。
7. **分页与恢复**：B 选择每页 10 条，下一页不重复任务；刷新保持当前页，浏览器后退回原页。首页刷新才纳入刚创建任务。撤权或恢复后旧游标会要求重新核实。
8. **最小管理权**：退出 B，登录 M 并选“管理视图”。应只有获准的租户监测摘要，“打开原业务详情”禁用且显示结果访问受限。直接访问 A 的大屏任务链接应得到统一隐藏结果，不泄漏名称、进度或文件。
9. **窄屏与键盘**：375px 宽度下查看列表和详情；200% 缩放下操作筛选和按钮；键盘打开任务，Escape 关闭后焦点回到原任务。按钮与文字表达状态，不依赖颜色。
10. **刷新失败**：使用浏览器离线或受控断网后刷新，应显示错误并隐藏未核实的任务／动作；恢复网络后“重新核实”可恢复。操作理由保留；若命令响应丢失，原请求可幂等重放。

专项自动验证还覆盖管理员并发重试、原执行身份失效、取消与旧租约竞争、交接乱序／晚提交、索引／通知停止、结果过期／失效、迁移中断、完整备份恢复和真实 SQL 角色边界，详见[逐项证据](../verification/task-center.md)。它们不需要用户在人工环境执行破坏性故障。
