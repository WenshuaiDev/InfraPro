## 2. 权限准备

工程功能新增 17 项权限，完整目录现为 88 项、13 个内置角色。租户目录为 27 项，其中 18 项可配置给普通自定义角色、9 项保留能力。平台管理员和租户管理员通过内置角色同步取得各自范围的新能力；既有自定义角色不自动扩权。

| 职责 | 权限编码 |
| --- | --- |
| 平台类型查看 / 编辑 / 发布 / 停用恢复 | `engineering.type.read/edit/publish/state` |
| 平台指标、单位及单位类别 | `engineering.metric.read/edit/publish/state` |
| 平台公共模板 | `engineering.template.read/edit/publish/state` |
| 租户公共目录读取与选用 | `tenant.engineering.catalog.read` |
| 租户私有模板 | `tenant.engineering.template.read/edit/publish/state` |
| 查看操作记录 | 平台 `platform.audit.read`；租户 `tenant.audit.read` |

表内斜线表示四个独立权限编码。进入页面需要 read，变更还需对应动作权限；创建、复制、新草稿和删除草稿使用 edit。类别维护使用 metric.read + metric.edit。新增引用还需相应公共目录读取资格；租户必须有当前有效成员关系。平台身份不会直接获得租户私有模板的读取资格。

在既有角色管理中建立编制角色、发布角色或兼有全部能力的角色，再显式绑定账号/租户成员。有权同一人可以直接校验并发布，没有审批单、审批人或待审批阶段。

## 3. 建立单位和指标

1. 平台“单位目录”点击“类别管理”维护单位类别，例如键 `length`、名称“长度”、说明“空间长度”。类别键、名称与含义说明必填。一旦单位或指标草稿引用，类别不再允许改义或删除；发布快照冻结类别说明。
2. 新建单位 `mm` / “毫米”，填写符号 `mm`，选择 `length`，填写变更原因，保存、校验、发布 V1。
3. 新建指标 `vertical_displacement` / “竖向位移”，明确测量含义，选择数值形态、单位类别，选择“标准单位”和“允许单位”的明确发布版本。标准单位必须在允许列表中。
4. 数值范围属于值有效性；这里不配置告警。枚举指标配置稳定选项键和名称，不配置物理单位。无量纲数值需要显式建立“无量纲”类别与相应单位，不等同于枚举状态。

单位选择保留具体版本。只校验允许单位及量纲，不做单位换算。新增指标方向或参考含义时使用清楚的名称/说明；核心形态或量纲改变应创建新身份。

## 4. 贯穿示例：新增路基路面

以下为验收示例，不是预置行业规范。建议在验收租户和测试定义中操作；编号重复时添加后缀。

1. 平台“设施类型定义”→“新建定义”，编号 `road_subgrade_pavement`、名称“路基路面”，填写原因并创建草稿。
2. 在“设施属性”添加必填文本 `segment_name` / “路段名称”；可继续添加起终点桩号等属性。
3. 添加构件类别 `layer` / “路面结构层”，添加必填小数属性 `thickness` / “厚度”，下限 0，选择毫米 V1。
4. 添加 `root → layer` 组成关系，最少 1、最多 3。定义的是类别规则，不是实际路段或真实构件。
5. 保存草稿，再到“样例预览”：填路段名称，增加一个结构层、厚度填 0，点击“验证样例与定义”；再增加第二层、厚度填 20，应再次通过。
6. 把厚度改为 -1，或删除全部必需结构层，应显示问题列表和位置。错误链接定位输入或对应配置分组；没有“保存正式设施”操作。
7. 返回编制区域，填写变更原因、校验定义并“发布当前草稿”，确认后得到 V1。样例错误不改变已保存的定义；发布验证定义及依赖，不把临时样例写入数据库。
8. 新建公共模板，选择路基路面 V1，添加监测项“路面位移”，映射到 `layer`，绑定竖向位移 V1、毫米 V1和至少一个“观测通道”要求。保存、预览并发布。
9. 可给同一类型再建立另一份公共模板。多适用类型模板必须为每个监测项逐一配置每个目标版本的映射；名称相同不能代替有效类别键。
10. 租户 A 进入“本租户监测模板”，点击“从公共模板复制”，在选择面板中检索公共模板、选择明确版本、填写独立编号和复制原因，点击“复制到本租户”。修改监测项、保存并发布，公共原件不变。
11. 从类型 V1 点击“从此版本建立草稿”，在面板填写变更原因并点击“建立草稿”，修改名称或属性并发布 V2。旧模板及租户副本仍引用 V1；通过“版本记录”比较明确版本，旧快照不会自动更新。
12. 保持服务运行，按相同方式再建立一个任意名称/编号的类型；不修改源码、迁移或重新部署。

## 5. 属性与样例规则

支持文本、整数、小数、布尔、日期、带时区的日期时间、单选枚举和多选枚举。属性可配置名称、说明、必填、默认值、范围、单位版本、分组、顺序及适用的展示提示。文本按 Unicode 码点计数；整数及小数绝对值最多 `9007199254740991`，整数不得有小数部分。服务端不将字符串转数字，不接受 NaN/Infinity，也不自动转换单位。

必填数值 0 和布尔 false 都有效。未填写与 `null` 不同，`null` 不合法；必填文本不能只有空白，必填多选至少一项，多选不能重复。日期为真实 `YYYY-MM-DD`；日期时间须显式带 `Z` 或 `±HH:MM` 时区，例如 `2026-11-10T09:30:00+08:00`。页面将本地日期时间与时区偏移分开填写，存储原始明确值。

默认值只在创建新样例/新增构件时显式填入。随后删除值再校验不会自动补回默认值。显示精度只影响显示，不截断实际输入。样例保存在页面内存中，离开预览、刷新、切换账号或上下文后清理，不上传为真实工程实例。

样例树支持增加、编辑、删除子树和合法重新挂接。每个节点只属于一个父级，不能循环或挂到不存在的父节点。每个实际父节点分别检查其直接子构件类别和数量。

服务端边界：定义内容最多 256 KiB；HTTP 请求另留 16 KiB 元信息空间；每个对象最多 100 个属性、每份类型最多 100 个构件类别和 500 条关系、临时样例最多 500 个节点。文本字段长度约束最多 10000 码点、枚举最多 200 项；其他字段限制以错误提示为准。系统只编译自身生成的 JSON Schema 2020-12，不接收脚本、公式、任意 Schema 或远程引用。前端 Zod 使用 CSP 兼容的无动态代码生成模式。

Nginx 对平台和租户的 `/api/v1/.../engineering/` 路径允许最多 272 KiB 请求体，其他路径保留 16 KiB 代理限制。工程资源仍由 Go 接口执行 256 KiB 总请求限制；代理放宽不会取消定义内容、属性值或位置资料的输入边界。更新该配置后需重建并重新启动 web 容器。

## 6. 版本、复制、停用与冲突

一个身份最多一个当前草稿。保存增加草稿修订；没有实际变化的保存不会制造变更审计。发布消费草稿并生成递增版本；修改已发布内容必须从明确版本建立新草稿。删除未发布草稿会保留编号墓碑，不能复用其编号；存在发布历史时只删除草稿。

发布正文、编译规则、类别快照及依赖记录不可改写。单位和指标形态/量纲不能在同一身份中换义；属性键即使在中间版本删除，也不能在后续版本复用成另一种形态或量纲。更名不改变固定版本的含义。

复制创建独立身份并冻结来源名称、编号与版本。来源用于追溯，不形成可用性依赖：停用来源模板不会直接停用副本；副本实际引用的类型、指标或单位停用后，副本仍会不可新使用。公共目录仅提供当前可新采用版本；已获授权的私有模板仍可按其固定历史依赖解释和预览。

停用/恢复前读取引用影响、填写原因并确认。平台只能看到公共引用详情和“存在受限私有引用”的提示，不能读取私有模板内容。发布、复制、新引用、恢复都在事务中重新检查完整依赖链；旧预览不能作为绕过检查的许可。

两个窗口并发保存时，旧修订收到 409，保留本地编辑；“重新读取结果”会先确认再替换本地内容。发布和停用由工程目录锁协调，不会留下半成品。临时网络错误保留输入，写请求不会自动重放。确认成员关系结束时清空页面；重新接受邀请后，切回页面或点击“重新检查租户资格”，仅按服务端当前关系恢复显示。相同操作、载荷、原因的显式重试沿用请求标识；可先用“查询上次请求结果”确认是否已成功。结果查询仍复验当前权限。修改载荷后重新操作使用新请求标识。

HTTP：格式/未知字段 400，当前资格不足 401/403，不可见对象 404，修订/幂等/依赖状态冲突 409，定义及样例校验失败 422（含路径、稳定键和问题列表），临时故障 503。业务失败不留下成功审计或发布版本。

## 7. 操作记录

有审计权限时，定义详情的“操作记录”可查看当前对象的创建、保存、复制、发布、建立/删除草稿和启停记录；支持原因/事件/时间筛选及分页。平台公共事件也可在平台审计查询；租户私有事件只进入本租户审计。

记录包含操作者、时间、范围、对象、原因、版本和来源，以及配置变化；不记录会话、密码、邀请令牌或临时样例。使用独立租户 B 或仅有平台资格的账号验证私有模板无法通过详情、搜索、复制、预览或审计读取。
