# 文件与附件人工验收

软件状态：Awaiting acceptance（2026-11-15 方案 A 页面正式改造自验通过；原功能自验记录为 2026-11-14）。仅用户明确确认后才记 Accepted。

## 启动与样本

在仓库根目录执行 `pnpm files:demo`。脚本启动隔离 PostgreSQL schema、私有 S3 bucket、API、检查器、文件 worker、任务索引与通知 worker。访问 `http://127.0.0.1:15574`；合成账号文件 `.artifacts/files/lab/accounts.json`，样本 `.artifacts/files/lab/samples/`，空间编号 `.artifacts/files/lab/files-acceptance.json`。凭据只写入权限 0600 的本地文件，不放进 URL。已有服务端口占用时拒绝启动，避免影响其他验收环境。

`Ctrl+C` 停止本演示并清理它的隔离后端资源。该环境是可重建的合成演示，不迁移或覆盖已有人工验收业务数据。自动浏览器链路为 `pnpm files:browser`；截图及实际下载摘要在 `.artifacts/files/browser/`。

自动浏览器回归使用独立端口 15575 / 18575 和 `.artifacts/files/browser-lab/`，不会停止正在运行的 15574 演示。自动回归结束后清理本次隔离服务；日常人工演示仍使用上述 15574 入口。

## 页面组织与按需操作（2026-11-15）

1. 文件页默认显示紧凑表格。输入名称或打开“创建日期”筛选，点击文件名：出现系统统一的带遮罩 Drawer，背景列表位置和筛选保持不变。
2. 附件详情将预览和版本记录合为一个阅读界面，不再显示概览/版本记录页签。默认显示版本选择、预览、格式/大小、时间、说明和下载入口；不应出现附件编号、SHA-256、编辑表单或展开全部修订历史。PDF/DOCX/XLSX/CSV/TXT 自动打开文档阅读器，细项见[文档预览验收](document-preview.md)；获准读取的 PNG/JPEG 自动显示安全预览。
3. 点击预览上方的版本按钮展开历史，选择某版后正文和“下载原件”同时切换。历史版本可“返回最新版”或“还原此版本”；还原会生成新版本，不覆盖已有记录。版本列表支持加载更多、错误重试和键盘选择。
4. 抽屉底部“更多”提供编辑信息、替换正文、回收/恢复及技术信息。编辑后填写操作原因再提交；“技术信息与处理记录”保留摘要、原始文件名、审计和固定代任务入口。
5. “添加附件”以及“上传与待处理”详情也使用 Drawer。待传输记录可“继续上传”；取消未提交上传及技术报告位于更多菜单，需要处理的记录提供“重新确认绑定”。
6. 关闭按钮、Escape 或遮罩关闭抽屉后，应恢复列表及焦点。移动端变为底部 Drawer；375px、200% 缩放和深色模式下操作可达。只检查布局时可退出编辑而不提交。

方案与本次验证结果见 [正式改造记录](../development/files-workspace-redesign.md)。名称与日期由服务端筛选；未提供原型中仅针对已加载行的类型筛选或排序。

## 资料附件操作

1. 在第一个租户“租户资料”查看“资料附件”，空状态应明确显示尚未添加普通附件。上传 `资料说明.txt`，填写名称、说明和原因；资料页原位打开上传结果，检查状态最终为已绑定，也可从“文件与附件”的“上传与待处理”找到同一记录。
2. 打开本代附件修订。文件页与资料页应是相同附件 ID，资料页预览和刷新后仍保留资料页路径。下载原件，与样本 SHA-256 相同；TXT 可以直接阅读。上传 PNG/JPEG 合成图片时，安全预览应显示重新编码版本。
3. 从抽屉更多菜单选择“编辑信息”修改名称和说明，原始文件名、大小、摘要与正文修订号不变。用“替换正文”上传 `替换资料.txt`，再在预览上方选择第一版并还原。应产生新的正文修订，原版本与原因继续可查。
4. 移入回收站后，普通列表与原件入口关闭；回收站可恢复全部历史。重复提交原请求只返回原回执，不产生重复修订或恢复。
5. 上传 `续传样本.txt`，在多片传输中离开，再从会话选回同一文件。仅补缺片；同名异文不能续传。上传 `伪装文档.pdf` 应在真实内容检查中失败，不生成附件。
6. 在第二个租户和项目资料页重复上传：项目资料 A 方案中入口为「项目附件」，上传结果与预览在该资料页原位打开，刷新恢复同一对象；附件身份、列表、回收站和详情严格隔离。归档项目可按资格查阅，不提供新增附件。375px 窄屏与 200% 缩放下无整页水平滚动，键盘能选文件、填写原因、提交及恢复错误。

## 多账号授权

演示已提供 `profile`、`reader`、`downloader`、`manager` 四个最小权限账号，具体用户名和密码见本机 accounts.json；分别登录第一租户复核以下组合。两租户各有两个独立项目。自动数据库测试覆盖同样组合以及会话撤销、成员重新加入和归档竞争。

| 权限组合 | 应观察到的结果 |
| --- | --- |
| 只有 profile.read | 资料正常，附件面板说明无附件查看权限 |
| profile.read + attachments.read（R） | 可以看元数据和历史，没有正文入口 |
| R + attachments.manage + profile.update（M），无 D | 可以改名/替换/回收，不能预览或下载 |
| R + attachments.download（D） | 可以下载当前和仍有效历史正文，不能修改 |
| D 但无宿主 profile.read | 不可访问附件 |
| 平台管理员/租户项目治理，未加入项目业务角色 | 不隐含项目附件读取 |
| 项目已归档且仍有 R+D | 可以读取，不能新建/替换/恢复/还原 |

下载过程中撤权或结束会话后，新块不再放行；已传到浏览器的字节不能撤回。离开上传页面会停止浏览器继续发送；complete 已接受的后台委托不随退出登录取消。成员退出后以新关系重新加入，不自动恢复旧委托，需获准人员明确发起新代次。

## 现有专业流程

在项目原有合成验收环境运行监测、空间和大屏手册对应步骤。监测 CSV/XLSX 仍按原生映射/校验/采用，公共文件列表提供原件和导出分卷；派生、分析、比较与输入依据导出维持格式和期限。空间来源经过转换、草稿与发布，图模展示权不变为原件下载权。大屏 ZIP 经检查、配置、发布和回退，隔离运行和终端 ReadSubject 边界不变。过期/撤权/缺失专业正文不得从公共列表绕过原模块读取。

## 任务、通知和审计

从上传详情更多菜单打开“技术信息与处理报告”，再打开固定代任务及结果，应落到同一附件修订。附件详情的“技术信息与处理记录”也保留固定代任务入口。替换后旧通知仍指向旧代/旧修订；回收后说明结果不可用。任务应展示排队、阶段、失败、取消和需要处理；自动重试只有 attempt 增长，手工处理生成新代。管理员取消别人的任务时，事件显示管理员操作，执行请求人保持原人。

暂停通知 worker 后上传应照常成功；恢复后同代终态只投递一次。关闭个人“任务”通知偏好时仍可完成附件操作。撤权后通知不能恢复原名称、作用域和正文。操作记录可通过 request_id、附件 ID、upload/job ID 与任务源引用核对。

## 清理与恢复

仅在一次性隔离环境执行 `pnpm test:files:restore` 和维护命令，参见 [运行手册](files-and-attachments.md)。自动功能测试采用受控时钟验证 24 小时预备期限、30 天回收与 purge，不修改机器时间。历史引用、活跃读取与备份 hold 均阻止删除；未登记对象不在清理计划中。

恢复演练实际创建独立数据库和 bucket，先漏对象使核对失败，再补齐重新核对。预期恢复 epoch 更新，旧上传、游标、worker fence、读取租约无效，原任务保留中断记录，不补发历史通知。自验记录与用户最终接受分开记录。
