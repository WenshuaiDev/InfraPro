# 租户启停与恢复运行及人工验收

日期：2026-11-10。方案已确认，功能实现及自验完成，状态为 **Awaiting acceptance**；结果见[验证记录](../verification/tenant-lifecycle.md)。只有用户明确完成下列人工验收后，功能才记为 Accepted。

## 1 本轮行为

- 创建及旧库迁移的租户默认“已启用”。平台可填写原因，预览影响后停用或恢复；只改变租户整体状态。
- 停用关闭当前全部租户业务读写，包括资料、成员、角色、邀请管理、完整上下文及租户审计。原账号登录、个人功能、其他租户及平台治理继续按原权限工作。
- 账号、成员、角色、绑定和邀请历史不批量改写。pending 邀请保留原链接及有效期；停用不延期。真实失权、过期、已撤销等终态不会被恢复。
- 恢复需当前管理员可用。平台可以在停用期间编辑档案或交接管理员；交接完成后仍须单独恢复。
- 内部操作原因只供平台治理和完整审计使用。成员及合法邀请目标仅看到租户可见说明；恢复后租户审计提供公开投影。

已有环境不重复 bootstrap、不清库。其他 v5 环境升级顺序：备份并验证恢复 → 停旧 API 写入 → 发布匹配代码 → 执行以下命令 → 启动新程序并检查 `/readyz`。旧 API 不识别状态，禁止混跑。


数据库迁移不提供丢弃状态的 Down。优先前向修复；真正的备份恢复必须停止写入，恢复匹配版本，按[账号恢复规程](account-management.md)执行 `account revoke-access --reason ...` 并检查后再启动。这会撤销旧凭据，与“恢复租户”不同。**本机验收库没有执行全局凭据撤销。**

## 3 验收准备

使用页面准备以下数据；可先复用已有测试租户。不要通过修改实际数据库制造管理员不可用或过期情形。

| 身份/对象 | 准备方式 |
| --- | --- |
| 平台 P | 使用平台管理员；自定义角色需 `platform.tenant.read` 加 `platform.tenant.disable` / `platform.tenant.enable`。交接和审计分别需要原有权限 |
| 租户 A、B 和管理员 M | P 创建两个租户，指定 M。记录 A 的编号和 URL 中的 UUID |
| 普通成员 U | M 在 A/B 邀请同一账号加入；A 可授“租户资料维护员”，用于打开未提交表单 |
| 邀请目标 V、W | 已开户但尚未加入 A 的正常账号；M 创建 A 的待领取邀请，保留原链接和到期时间 |
| 暂停 S、已移除 E | 在 A 建立普通成员后分别暂停/移除；另备停用角色或撤销绑定，供恢复后核对 |
| 无权 N | 基础成员或仅具租户查看权的账号，无平台启停权限 |

P、M、U、V 使用独立浏览器配置或隔离上下文。普通标签页共享 Cookie，只适合验证同一账号多标签。自动测试账号只存在于隔离测试环境，不作为人工登录账号。

## 4 人工验收步骤与预期

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 基线 | P 打开平台租户列表及 A 详情；U 进入 A、B | 两租户显示“已启用”；管理员可用性单列。业务按当前授权可用 |
| 2 邀请与旧表单 | V 打开 A 的邀请确认页但不接受；U 在 A 编辑资料并留下草稿，另开 B 标签 | 邀请显示原有效期；没有提前加入。A/B 各自独立 |
| 3 预览取消 | P 点击“停用租户”，核对名称/编号、人数、邀请数；按 Escape 或“取消” | 焦点返回触发按钮；状态不变，没有成功停用事件 |
| 4 停用 | P 重开预览，填写不同的内部原因和公开说明，点击“确认停用租户” | 明确显示“已停用”和时间，出现“恢复租户”；内部/公开文本分列 |
| 5 旧入口 | U 聚焦旧 A 标签，或尝试保存旧表单，再刷新旧 URL | 业务请求拒绝；显示统一停用页与公开说明，旧内容和草稿清理。健康前台页轮询在 35 秒目标内发现；聚焦立即核验 |
| 6 我的租户与隔离 | U 返回我的租户，查看 A 卡片，再进入 B、个人资料及账号安全 | A 保留卡片，入口为“查看状态”；B 和个人功能正常，没有全局登出 |
| 7 邀请 | V 在旧确认页尝试加入，再点“查验当前邀请结果”或重新打开原链接 | 提示“租户已停用，暂时无法加入”，显示原有效期，接受按钮不可用；不建立成员关系，也不泄露内部原因 |
| 8 平台治理 | P 在 A 停用期间编辑档案，查看平台记录；如有需要交接管理员 | 治理仍可用，A 保持停用。平台身份本身不能进入普通租户业务 |
| 9 版本与预览 | 用两个 P 页面打开操作预览；另一页面修改档案后再提交旧预览 | 返回版本或影响变化，保留原因，要求重新预览、核对和明确确认。重复请求不产生重复成功事件 |
| 10 复验 | 登录超过近期密码确认窗口（5 分钟）后提交启停 | 提示当前密码。确认密码后重新读取预览，仍需点击确认，不自动重发写请求 |
| 11 权限分离 | N 查看相应页面；可另用仅 read+disable、仅 read+enable 的平台角色分别尝试两种动作 | 普通成员/租户管理员没有自行恢复入口；停用权和恢复权不能互代。服务端直调矩阵已有自动证据 |
| 12 恢复 | P 核对恢复预览，填写原因，点击“确认恢复租户”；U 在停用页点“重新检查” | 同一个 UUID/编号恢复；重新读取当前授权，原 active 成员关系 ID 保留，旧草稿不回来 |
| 13 邀请继续 | 在未过期前让 V 用原链接重新检查并明确加入 | 原链接可继续使用，只有用户点击才加入。过期/撤销/替换/资格失效邀请仍不可用 |
| 14 保留限制 | M 检查 S、E、停用角色和撤销绑定 | 原暂停、结束、停用和撤销状态保持；不会因为恢复重新授予能力或恢复已撤销会话 |
| 15 审计与隐私 | P 搜索内部原因；M 在恢复后的租户审计查看启停事件并搜索同一内部词 | P 可追溯完整事件；M 仅见公开状态历史和“平台操作”，内部原因搜索不命中，不暴露平台人员和网络信息 |
| 16 交互和故障 | 在 375/768/1440px、明暗主题和键盘下操作；使用浏览器离线模拟故障后恢复网络 | 对话框可滚动、动作可达、状态有文字。服务故障与停用/失权文案不同；纯故障保留输入、禁止提交，重新连接后仍需明确操作 |

管理员不可用阻断恢复、合法交接后单独恢复、真实过期、并发顺序、审计回滚、全路由拒绝和旧库升级以[专项技术证据](../verification/tenant-lifecycle.md)配套，不需要为人工验收应急停用真实管理员。网络写结果未知时先读取当前状态及平台审计，不能直接重复提交。

验收反馈请注明步骤、账号身份、租户编号、预期/实际结果和请求编号；不要提供密码、Cookie 或完整邀请链接。人工确认由用户给出，自验通过不等于 Accepted。

## 5 范围限制

仅覆盖当前真实存在的租户业务。未实现项目、租户删除/归档、批量/定时启停、审批、许可/计费、外部通知、后台采集/任务或实时订阅。将来项目及新业务入口必须复用租户状态校验。

浏览器自验为 Chromium；不包含 Safari/Firefox、真实手机系统、辅助技术全量审计或大规模性能/异机灾备测试。浏览器已收到的历史内容无法撤回；后台冻结或离线时不承诺 35 秒显示更新，服务端每次新业务事务仍即时校验。
