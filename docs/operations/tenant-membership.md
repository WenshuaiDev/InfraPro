## 2 邀请与成员规则

- “账号开户邀请”用于创建账号；“成员邀请”用于邀请已有正常账号加入指定租户，二者凭据不能混用。
- 管理员输入完整用户名，定位账号后填写原因。固定授予租户普通成员，24 小时有效。目标本人登录后仍须点击“确认加入”。
- 完整链接只在首次创建或重新生成成功时展示。关闭后不能再次取回；需要时在邀请记录中明确重新生成。新链接替换旧链接，撤销/失效/过期历史仍保留。
- 受邀者刷新确认页后需重新打开原链接；凭据仅暂存在当前页面内存。退出或切换账号会清理，不应把链接写入截图、工单或日志。
- 普通成员只能读取租户基本资料和本人权限；没有资料编辑、成员/邀请/审计管理能力。平台身份也不能绕过租户成员校验。
- 暂停只阻止该租户访问，保留关系及固定角色；恢复使用同一成员 ID。移除结束关系并撤销绑定；再次邀请并接受会创建新的成员 ID，旧历史不复活。
- 当前管理员必须通过平台交接流程变更，不能在成员页面暂停或移除。接任有效普通成员复用关系和加入时间；暂停成员须先恢复；已结束或无关系账号建立新关系。原管理员关系结束。
- 发起人失去管理员资格、受控重置密码、账号停用、目标被停用或直接任命为管理员、备份恢复统一撤销，按方案永久关闭相关未领取邀请。常规改密和退出登录不撤销邀请；已成立的成员关系不因发起人退出或交接自动移除。
- 版本冲突、密码复验、结果未知均需用户核对后再确认，不自动重发写请求。超时先查记录，丢失链接响应可明确重新生成。

## 3 人工验收准备

准备平台人员 P、租户管理员甲、普通账号乙和错账号丁。P 需有平台租户创建/交接与账号开户邀请权限，原本机账号可按现有授权使用。

1. P 从“账号开户邀请”分别生成链接，甲、乙、丁在独立浏览器上下文开户。不要使用隔离自动测试环境的账号或密码。
2. P 在“租户管理”创建 A、B，均指定甲为管理员，名称和编号自行选择。P 不会因为创建租户自动成为成员。
3. P、甲、乙、丁使用不同浏览器用户配置或独立隐身上下文。同一浏览器普通标签共享 Cookie，不能当成不同账号。
4. 甲进入左上切换器→A。新功能入口为“成员管理”和“成员邀请”；普通成员看不到这些入口。

## 4 人工验收步骤及预期

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 定向邀请 | 甲在 A 的成员邀请中精确输入乙的完整用户名，定位、填写原因、创建并复制链接；再关闭链接弹窗 | 显示乙身份、A 名称/编号、普通成员角色和 24 小时到期时间。乙尚未成为成员；关闭后列表/详情不能取回明文链接 |
| 2 本人确认 | 乙在未登录窗口打开链接，完成登录；先不点确认，查看租户选择器，再回确认页点击“确认加入” | 登录本身不会加入；确认后 A 才出现。丁打开同一链接不能领取，也看不到乙身份和 A 预览 |
| 3 普通权限 | 乙进入 A，展开“当前租户权限”；直接打开 A 的成员、邀请和审计路径 | 能看名称、编号、说明、管理员最小信息；角色为普通成员，仅有查看资料权限。管理入口不可用，直接请求也拒绝 |
| 4 暂停和恢复 | 甲另邀请乙加入 B；记录乙在 A 的成员 ID。甲暂停 A 中乙，再恢复 | 暂停后原会话的新请求立即拒绝 A，B 和个人功能不受影响；可见页面在轮询/重新聚焦时清理。恢复后 A 可访问且成员 ID 不变 |
| 5 移除和再次加入 | 甲移除乙，再发新邀请，由乙确认；成员列表选择全部状态并搜索乙，打开旧关系详情 | 新关系 ID 不同；旧关系已结束、角色已撤销、原因及来源可查。旧已接受邀请只能查看原结果，不能恢复旧关系 |
| 6 撤销与替换 | 甲邀请丁，撤销后让丁尝试接受；再重新生成，分别打开新旧链接。刷新新链接确认页 | 撤销/旧链接不能领取；新链接仅丁可用；替换链和终态历史完整。刷新后提示重开链接，不自动接受 |
| 7 管理员保护与交接 | 尝试从 A 成员页操作当前管理员甲；P 将 A 交给有效普通成员乙 | 当前管理员无暂停/移除入口，直接 API 也拒绝。交接预览说明复用乙的关系；乙保留加入时间改授管理员，甲在 A 的关系结束，甲仍能管理 B |
| 8 暂停接任人 | 在 B 将某普通成员暂停，P 尝试将 B 交给该成员 | 预览明确须先恢复，服务端拒绝交接；不能留下暂停的当前管理员。恢复后再明确交接才成功 |
| 9 版本与复验 | 同账号两窗口操作同一成员/邀请；等待密码复验窗口过期后执行管理写入 | 旧版本冲突不覆盖，原因输入保留；复验后要求再次核对确认，不自动提交。断网/结果未知提示先查记录 |
| 10 审计与历史 | 查看成员详情、邀请详情和租户操作记录，按对象、事件、时间或原因筛选；切换到 B 查看 | 加入、暂停、恢复、移除、撤销、替换及失效原因可追溯；只显示当前租户数据，普通成员不能读管理审计 |
| 11 手机和键盘 | 375px 视口用 Tab/Shift+Tab、Enter、Escape 完成定位、邀请、确认与取消；切换明暗主题 | 列表以卡片显示，主要操作无需横向滚动，标签和文字反馈完整；取消后焦点返回触发按钮 |
| 12 原流程 | 检查开户、登录退出、个人资料、改密、会话、平台角色、租户建档编辑及管理员停用保护 | 原能力保持；账号和租户成员生命周期分别生效，不出现平台角色自动扩权 |

全部 MA-01–MA-52 对照和并发、故障注入、迁移恢复的自验证据见[验证记录](../verification/tenant-membership.md)。功能须由用户明确确认后才标记 Accepted；不满足项继续在本轮修复。

## 5 增量发布与恢复

升级其他既有环境前，备份并在隔离数据库实际验证恢复，停止所有旧 API 写入；核实同版本程序和权限目录后执行：

```bash
pnpm infrapro database migrate
pnpm infrapro access sync
pnpm infrapro access check
make dev
```

本轮迁移为 v4，目录共 37 项权限、4 个内置角色。tenant_admin 有 11 项租户权限，tenant_member 仅有 tenant.profile.read；自定义平台角色不会自动增加租户权限。重复 migrate/sync/check 可安全核验，不制造普通成员和邀请。

本机升级前备份为 `.artifacts/tenant-membership/local-before-v4.dump`（0600，gitignored）。已真实恢复到独立临时库并比对 12 个业务表的原始列内容指纹，然后删除临时库。升级后原行保留，只新增本次权限同步审计；重复同步无新增事件。摘要为 `local-backup-check.json`、`local-upgrade-result.json` 和 `local-idempotency-result.json`，同在该目录。

迁移失败保持停服并排查；不能混跑 v3 API 与 v4 数据库。Down 明确拒绝删除新成员历史。优先前向修复；确需恢复备份时按[账号运行手册](account-management.md)停止写入、恢复匹配程序与数据库，再执行：

```bash
pnpm infrapro account revoke-access --reason '备份恢复后统一撤销旧凭据'
pnpm infrapro access check
```

此命令覆盖会话、开户邀请、重置凭据和未领取租户邀请。只有确认撤销完成、检查通过后才重启 API。恢复后的账号需要重新登录，成员关系历史保留。该流程已在专用 HTTP 测试栈用真实 pg_dump/pg_restore 验证；本机正式库没有执行全局撤销。

正式 HTTP 部署沿用 Nginx `/console/`，需将 `public_console_url` 配置为实际公开 console 地址，生成链接和登录返回使用同一前缀。

## 6 保留与验证边界

审计沿用 `audit_retention`，默认 `2160h`（90 天）；成员、角色授予和邀请历史不随审计清理删除。没有项目、计费、配额、自定义租户角色、并列管理员、自助退出或邮件发送。

本轮完成开发、本机升级和隔离环境自验；未进行用户人工验收、生产部署、生产规模吞吐/长期稳定性或异机灾备验证。全局授权变化仍串行化，不能据此宣称高并发吞吐指标。
