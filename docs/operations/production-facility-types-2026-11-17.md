# 生产设施类型目录（2026-11-17）

状态：**Awaiting acceptance**。六类首版已在生产发布并启用，配置及自验证完成；人工接受须由用户另行确认。

## 范围与已确认口径

在平台管理 → 工程配置 → 设施类型定义中建立并发布六类：桥梁、隧道、边坡、路基路面、涵洞、气象站。用户明确路基与路面合为一种设施类型；气象站以观测为主，直接管理测点和设备，不设杆塔、基础、机柜等构件类别。

设施类型描述静态业务属性和允许的工程结构。监测指标沿用现有公共指标目录，监测通道在实际测点上选择指标；类型定义不自动创建真实设施、设备、测点或通道。

## 定义方案

| 类型 | 设施边界 | 可选构件范围 | 监测断面 | 孔位 |
| --- | --- | --- | --- | --- |
| 桥梁 | 一座按实际管养边界识别的桥梁；可按桥联、桥跨细分 | 梁、板、拱、墩台、基础、支座、塔索、桥面及附属构造 | 支持 | 支持，限真实基础／岩土等孔内监测 |
| 隧道 | 一个明确管理边界的隧道；多洞可用洞体分别表达 | 洞体、结构段、支护、衬砌、仰拱、洞门、横通道、井室和排水等 | 支持 | 支持，表达围岩或地下水等监测孔 |
| 边坡 | 一处明确范围的自然或人工边坡 | 坡体、分级坡段、支挡、锚固、防护和排水构造 | 支持 | 支持，表达深部位移、水位等孔内监测 |
| 路基路面 | 同一道路区段内的路基与路面统一建档 | 路基、路堤／路堑、路床、地基处理、路面及面层／基层／底基层／垫层等 | 支持 | 支持，表达深层岩土、温度等监测孔 |
| 涵洞 | 一处涵洞或按同一边界管理的涵洞结构 | 涵身、涵节、板壁、拱圈／管节、基础、洞口、接缝和排水构造 | 支持 | 支持，限实际地基或岩土监测孔 |
| 气象站 | 一个具有明确站址和观测服务范围的站点 | 无 | 不支持 | 不支持 |

前五类允许孔位是本目录为可选岩土监测场景作出的配置决定，不表示所有设施都需要孔位。排水管、埋入式路温探头或普通设备端口不自动产生孔位。钻孔身份、孔口高程、孔深与孔内测点定位使用系统专用字段。

所有构件关系的最小数量为零，不设置无依据的数量上限。各构件类别可以直接归属设施，方便资料不完整时按已知对象建档；具备完整资料时，可按配置的父子关系进一步细分。监测断面和孔位为独立工程对象，允许穿插在工程树中；不强制统一层序。桥联、洞体、路段结构单元、分级坡段须有真实工程范围，不能用来伪装监测分组。

## 属性边界

- 名称、内部编码、状态、说明、来源依据、线路与桩号、侧别、方向、经纬度、投影坐标和带基准的高程沿用系统字段，不创建第二套同义属性。
- 类型属性只补充结构形式、材料、设计尺寸、设计荷载等静态业务事实；均可留空，不给未知事实赋零或默认分类。
- 数值引用生产中已发布且可用的单位固定版本。非负尺寸、整数数量及枚举选项由系统校验；不把基础字段校验当成工程设计审核。
- 几何位置、起终点、方向及跨字段关系仍按真实资料填写，不凭类型自动推算。类型属性不承担告警阈值、风险分级或监测计算规则。
- 材料、结构形式等不在列举范围时使用“其他”并补充已有说明／来源字段；不同工程方案不强制采用同一构造。

## 气象站的具体建档方法

站点保留外部站号、站点场景、观测方式、启用观测日期、下垫面、周边环境、服务范围和观测依据等可选属性。站点自身坐标与高程使用系统位置资料。

站点下可直接建立空气温湿度、风场、降水、能见度、路表状况等实际观测位置。不同高度、不同车道或不同参照位置分别建测点；同一位置的多个要素可以建在一个测点的多个业务监测通道上。测点定位保留实际高度／位置及参照，不在类型内写死统一观测高度。

一体式气象仪、分体传感器、采集器和网关按设备台账管理，安装归属与输出绑定分别记录。一台仪器可以提供多个输出；更换设备不改变站点或测点身份。服务范围是说明资料，不产生其他设施的自动绑定或授权。气象站的路面状况观测也不要求人为新增“路面构件”。

## 实施方式与技术

使用现有 Go 工程定义服务、PostgreSQL 版本数据模型和 React／TypeScript 配置界面，遵循元模型 2 的属性、组成关系、监测断面和孔位声明。通过正常 HTTPS API 使用用户授权账号创建草稿、执行预览校验并发布，保留请求回执和平台审计；不直接修改数据库，不修改或部署应用程序。

本地 Python 仅用于生成可复核配置清单与样例，Node.js HTTPS 客户端使用生产 CA 验证证书、调用既有 API。录入前快照、完整配置、样例结果和逐项读回证据保存在本机 `.artifacts/production-facility-types-20261117/`；认证材料不写入该目录。

构件名称参考工程常用构造与[《公路桥涵养护规范》](https://xxgk.mot.gov.cn/jigou/glj/202108/P020240129349058736824.pdf)、[《公路隧道养护技术规范》](https://xxgk.mot.gov.cn/jigou/glj/202607/P020260714390832074827.pdf)所覆盖的结构范围；这些资料不规定本系统的实体层级。气象站的站点／测点／设备划分按本次用户确认及项目现有领域模型确定。

## 自验与人工验收

发布前验证：空属性及无构件设施可建；真实构件关系和混合断面／孔位树通过；不允许的父子关系、测点下挂结构、循环、非法枚举及越界数值被拒绝；气象站直接建测点通过，构件／断面／孔位样例被拒绝。

发布后逐项读回，核对六个名称与稳定编码、完整属性、构件类别、关系、结构能力及单位引用，确认版本已启用且可用。其他目录采用操作前后列表摘要比对，并核对本次写入请求范围。

人工验收入口：生产控制台 → 平台管理 → 工程配置 → 设施类型定义。

1. 目录显示且仅新增以上六类，每类均有已发布可用的版本；路基路面只占一类。
2. 查看气象站：无构件类别，断面和孔位均不适用；样例中根设施可以直接拥有多个测点。
3. 查看桥梁、隧道、边坡、路基路面、涵洞：构件及子构件按实际选建，无强制补齐的节点；直接建测点仍合法。
4. 查看属性与单位；已有桩号、坐标、高程等位置资料没有被复制成扩展属性，未知业务属性可留空。
