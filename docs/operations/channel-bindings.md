# 测点与设备绑定

状态：**Awaiting acceptance（待人工验收）**。本轮按用户选择的方案 A 重构，软件自检和用户人工接受分别记录。

## 页面与操作

租户入口为 `/t/{tenantId}/bindings`。目录按「设施 → 构件（支持多级）→ 测点 → 业务通道」展示；设施直属测点明确标注「设施直属（无构件）」。搜索支持上述各级名称、编号，可叠加设施范围和绑定状态。

目录每次加载 50 个业务通道，同一设施、构件和测点按身份合并。树节点旁的数字表示已加载通道数，底部显示已加载数与当前筛选总数。链接指定的通道若尚未加载，单独展示其完整路径；「定位已选」会展开并聚焦该通道。后续加载失败保留已加载目录和当前选择，可重试。

右侧固定展示当前关系：正常绑定用绿色区域突出设备名称、编号、输出和代次；停用、退役、权限受限和未绑定各有独立提示。候选列表在其下方滚动，不重复当前绑定的输出，并优先列出可用设备通道。已被占用、停用或观测含义不一致的输出不可选择。

桌面左右区域等高，底部核对栏紧接两栏，不因列表长短产生断层。窄屏改为上下排列。选择候选只暂存配对；点击核对后仍需填写变更原因，由既有服务校验两端版本、占用、观测含义及权限，再完成绑定或原子更换。解除绑定、关系历史、设计要求和设施跳转保留。

「已绑定」只说明关系建立，不表示已接收到观测数据。设备安装位置仍独立维护。

## 实现与接口

- React、TypeScript、TanStack Query：树形目录、分页缓存、当前关系和候选选择；查询随租户、权限与绑定版本变化刷新。
- Go、PostgreSQL：目录从工程资源祖先链返回 `component_path`（设施下首级到测点父构件，直属测点返回空数组），同时支持搜索祖先构件。没有新增数据库结构或迁移。
- 候选查询在服务端排除本通道当前输出，再按可用状态、创建时间、身份排序并分页；游标包含排序位置，当前关系变化后前端从第一页读取。
- OpenAPI 与生成的 TypeScript 类型同步增加必填 `component_path`。管理端构建与 API 需一起更新。
- 写入继续使用现有来源命令、预览、并发版本、收据与审计；没有新增绕过校验的保存入口。

主要实现位于 `apps/console/src/features/bindings/` 和 `packages/go/platform/sources/`。

## 自检与人工接受

2026-11-16 已通过：

- 绑定客户端单元检查 5 项；包括多级构件、同名但不同身份、直属测点及跨页去重。
- Go 来源模块及相关设备权限回归（带 race 检查）；包括祖先路径与搜索、目录可见性、占用、原子更换、回滚和并发失效。
- 管理端及工具 TypeScript 检查、绑定相关 ESLint、OpenAPI 类型一致性、管理端正式构建、API 编译。
- 桌面和手机浏览器回归 4 项（绑定工作台和原有设备登记／来源入口各两种视口）：跨页深链定位、加载失败重试、构件编号搜索、原因必填、真实绑定／更换／解除、历史、直属测点、候选分页和对齐。
- 本机正式构建只读检查：现有 15 个业务通道、完整构件路径、突出当前设备、候选排除当前输出、滚动固定、桌面／平板／手机和暗色布局。没有修改现有工程的绑定关系。

浏览器证据保存于 `.artifacts/binding-workspace/`。本轮未执行全站 E2E、规模压力或生产部署。
